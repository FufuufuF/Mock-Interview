# JavaScript 对象 — 面试要点笔记

> 学习日期：2026-06-25 | 分类：js-basics

## 一句话总结

JavaScript 万物皆对象，掌握对象的创建、属性控制、原型链、继承、拷贝是面试必备基础。

## 知识要点

### 1. 对象创建方式

**面试问法**: JavaScript 中创建对象有哪些方式？各自有什么区别和适用场景？

**核心回答**:

四种方式：

| 方式 | 适用场景 | 原型指向 |
|------|---------|---------|
| 对象字面量 `{}` | 一次性、不需要复用模板的对象 | Object.prototype |
| 构造函数 + new | ES6 之前批量创建同结构对象 | 构造函数.prototype |
| Object.create(proto) | 精确控制原型链、创建纯净字典 | 传入的 proto 参数 |
| ES6 class | 现代项目定义类的标准方式 | 类.prototype |

**加分细节**:
- `Object.create(null)` 创建无原型的纯净对象，可用作哈希表（Vue2 源码中用此技巧存储纯数据映射）
- class 与构造函数的差异：class 内方法挂在 prototype 上且 `enumerable: false`，构造函数手动挂的方法默认 `enumerable: true`
- class 不存在变量提升，和 let/const 一样有暂时性死区（TDZ）。原因：class 可以有 extends，如果允许提升则继承关系可能不确定

**易错点**:
- ❌ "class 是一种全新的机制" → ✅ 本质还是原型链语法糖
- ❌ "Object.create 和 new 差不多" → ✅ Object.create 不执行构造函数，只建立原型链接

### 2. 属性描述符

**面试问法**: 请解释 Object.defineProperty 的用法，数据描述符和访问器描述符有什么区别？

**核心回答**:

每个对象属性背后都有一组元信息（属性描述符）来控制其行为，分为两类：

| | 数据描述符 | 访问器描述符 |
|---|---|---|
| 核心字段 | `value`, `writable` | `get`, `set` |
| 公共字段 | `configurable`, `enumerable` | `configurable`, `enumerable` |
| 用途 | 存储一个具体的值 | 拦截读写操作 |

**两者互斥**：一个属性要么是数据描述符（有 value），要么是访问器描述符（有 get/set），不能混搭。逻辑上：数据描述符是"格子里直接放值"，访问器描述符是"格子里放机关函数，不直接持有值"。

四个特性含义：
- `writable` — 能否修改值
- `enumerable` — 能否被 for...in / Object.keys 遍历
- `configurable` — 能否删除属性 / 修改描述符

**关键陷阱**：`defineProperty` 定义的属性，布尔值默认全是 **false**；字面量赋值的属性默认全是 **true**。

**加分细节**:
- `configurable: false` 不可逆：设为 false 后再也改不回 true
- Object.freeze → 所有属性 writable: false + configurable: false（完全冻结）
- Object.seal → 所有属性 configurable: false，但 writable 不变（不能增删，能改值）
- Vue2 用 getter 收集依赖、setter 触发更新；局限是无法监听属性新增/删除，所以需要 $set/$delete

**易错点**:
- ❌ "defineProperty 和直接赋值一样" → ✅ 默认值完全不同
- ❌ "getter/setter 可以和 value 共存" → ✅ 互斥，同时写会报 TypeError

### 2.5 延伸：Vue2 响应式原理 & Vue3 Proxy

**面试问法**: Vue2 的响应式原理是什么？Vue3 为什么改用 Proxy？

**核心回答**:

**Vue2 响应式三步走：**
1. **数据劫持（Observer）**：初始化时遍历 data 的每个属性，用 `defineProperty` 改写成 getter/setter
2. **依赖收集（getter + Dep）**：组件渲染时读取数据 → 触发 getter → 把当前 Watcher 记录到该属性的 Dep（订阅者列表）中
3. **派发更新（setter + Dep.notify）**：数据修改 → 触发 setter → Dep 通知所有 Watcher → 组件重新渲染

关键机制：通过**全局变量** `Dep.target` 实现 getter 与 Watcher 的关联。Vue 在渲染前把当前 Watcher 挂到 `Dep.target`，渲染过程触发 getter 时去读取它。

**Vue2 的两个核心痛点：**

1. **无法监听属性新增/删除**：
   - 原因：`defineProperty` 只能劫持初始化时已存在的属性，后来新增的属性没有被劫持
   - 场景：`this.newProp = 'xxx'` → 页面不更新；`delete this.name` → 不触发 setter
   - 补丁：必须用 `this.$set()` / `this.$delete()`

2. **无法直接监听数组索引赋值**：
   - 原因：性能考虑，Vue2 放弃对数组每个索引做 defineProperty
   - 场景：`this.list[0] = 'x'` → 页面不更新
   - 补丁：重写了 7 个数组原型方法（push/pop/shift/unshift/splice/sort/reverse），在方法内手动触发通知

**Vue3 用 Proxy 解决一切：**

Proxy 代理整个对象，任何操作（新增、删除、索引赋值）都能被 trap 拦截：

```js
function reactive(obj) {
  return new Proxy(obj, {
    get(target, key) { track(target, key); return target[key] },
    set(target, key, value) { target[key] = value; trigger(target, key); return true },
    deleteProperty(target, key) { delete target[key]; trigger(target, key); return true }
  })
}
```

**Vue3 Proxy vs Vue2 defineProperty：**

| | Object.defineProperty | Proxy |
|---|---|---|
| 劫持粒度 | 一次一个属性 | 一次整个对象 |
| 新增属性 | ❌ 需要 $set | ✅ 自动拦截 |
| 删除属性 | ❌ 需要 $delete | ✅ deleteProperty trap |
| 数组索引 | ❌ 需要 hack | ✅ 天然支持 |
| 性能 | 初始化时递归遍历全部属性 | 惰性代理（访问时才代理） |
| 兼容性 | 支持 IE9+ | 不支持 IE |

### 3. 原型与原型链

**面试问法**: 请解释 prototype、\_\_proto\_\_ 和 constructor 三者的关系。原型链是怎么工作的？

**核心回答**:

**三角关系：**
1. **函数有 `prototype`** — 指向原型对象，给实例共享方法用
2. **实例有 `__proto__`** — 指向构造函数的 prototype
3. **原型对象有 `constructor`** — 回指构造函数本身

```
p.__proto__ === Person.prototype            // true
Person.prototype.constructor === Person     // true
```

**原型链查找链路：**
```
p 自身 → Person.prototype → Object.prototype → null（终点）
```

- 属性读取：沿原型链向上查找
- 属性赋值：只在对象自身创建/修改，不影响原型链
- 所有对象能用 toString()/valueOf() → 因为定义在 Object.prototype 上

**加分细节**:
- `__proto__` 是非标准的，规范推荐 `Object.getPrototypeOf(obj)`
- `Object.create(null)` 创建的对象没有原型链，连 toString 都没有

**易错点**:
- ❌ "所有对象都有 prototype" → ✅ 只有函数才有 prototype，普通对象只有 `__proto__`
- ❌ "原型链无限" → ✅ 终点是 `Object.prototype.__proto__ === null`

### 4. 继承方式演进

**面试问法**: JavaScript 有哪些继承方式？各自有什么优缺点？请手写寄生组合式继承。

**核心回答**:

演进脉络（每一步解决上一步的问题）：

| 方式 | 做法 | 解决了什么 | 还有什么问题 |
|------|------|-----------|------------|
| 原型链继承 | `Child.prototype = new Parent()` | 能继承方法 | 引用类型属性被所有实例共享 |
| 构造函数继承 | `Parent.call(this)` | 属性独立 | 继承不到原型上的方法 |
| 组合继承 | call + new Parent() | 属性独立 + 能继承方法 | 父类构造函数被调用两次 |
| 寄生组合式（最优解） | call + Object.create(Parent.prototype) | 全部解决 | 无 |
| ES6 class extends | super() | 语法糖，底层同上 | 无 |

核心理解：**属性用 call 复制到自身（独享），方法放 prototype 共享（省内存）**

寄生组合式的关键：用 `Object.create(Parent.prototype)` 代替 `new Parent()`，只建立原型链接，不执行父类构造函数，避免多余调用和原型上的冗余属性。

**加分细节**:
- 能说清每一步的演进逻辑，而不是直接背最终答案
- `super()` 的本质：调用父类构造函数 + 绑定 this
- class extends 中子类 constructor 必须先调用 super() 才能用 this

**易错点**:
- ❌ "组合继承就够了" → ✅ 有多余调用的性能浪费，面试需要知道最优解
- ❌ "class extends 是新机制" → ✅ 底层就是寄生组合式继承

### 5. 对象遍历方式

**面试问法**: for...in、Object.keys、Object.getOwnPropertyNames、Reflect.ownKeys 有什么区别？

**核心回答**:

| 方法 | 遍历范围 |
|------|---------|
| `for...in` | 自身 + 原型链上的**可枚举**属性 |
| `Object.keys()` | 仅自身**可枚举**属性 |
| `Object.getOwnPropertyNames()` | 自身所有属性（含不可枚举，不含 Symbol） |
| `Reflect.ownKeys()` | 自身**全部**属性（含不可枚举 + Symbol） |

能力范围从小到大：Object.keys ⊂ for...in（多原型链）；Object.keys ⊂ getOwnPropertyNames（多不可枚举）；getOwnPropertyNames ⊂ Reflect.ownKeys（多 Symbol）

**加分细节**:
- `for...in` 经常搭配 `hasOwnProperty` 过滤原型链属性
- `Object.keys` 的顺序：先数字升序 → 字符串按创建顺序 → Symbol
- 实际开发最常用 `Object.keys()` / `Object.entries()`

**易错点**:
- ❌ "for...in 只遍历自身属性" → ✅ 会沿原型链找可枚举属性
- ❌ "Object.keys 能拿到 Symbol" → ✅ 拿不到，需要 Reflect.ownKeys

### 6. 浅拷贝与深拷贝

**面试问法**: 浅拷贝和深拷贝有什么区别？各有哪些实现方式？手写一个深拷贝。

**核心回答**:

- 浅拷贝：只复制第一层，嵌套对象仍是同一引用
- 深拷贝：所有层级都独立复制，完全互不影响

**浅拷贝方式**：`{ ...obj }` / `Object.assign({}, obj)` / `arr.slice()`

**深拷贝方式**：

| 方式 | 优点 | 缺点 |
|------|------|------|
| `JSON.parse(JSON.stringify())` | 简单 | 丢失 undefined/function/Symbol，Date 变字符串，RegExp 变 `{}`，循环引用报错 |
| `structuredClone()` | 原生 API，处理循环引用/Date/RegExp/Map/Set | 不能处理函数、DOM、Symbol |
| 手写递归 | 完全可控 | 需处理循环引用和特殊类型 |

**手写深拷贝核心思路**：
```js
function deepClone(obj, map = new WeakMap()) {
  if (obj === null || typeof obj !== 'object') return obj
  if (map.has(obj)) return map.get(obj)  // 处理循环引用
  if (obj instanceof Date) return new Date(obj)
  if (obj instanceof RegExp) return new RegExp(obj)
  const clone = Array.isArray(obj) ? [] : {}
  map.set(obj, clone)
  for (const key of Reflect.ownKeys(obj)) {
    clone[key] = deepClone(obj[key], map)
  }
  return clone
}
```

关键细节：WeakMap 处理循环引用（弱引用不阻止 GC）；Reflect.ownKeys 遍历最全面；Date/RegExp 需单独处理。

**加分细节**:
- 能说出 JSON 方式的至少 4 个缺陷
- 知道 structuredClone 新 API（2022 年起主流浏览器支持）
- 手写版可增强：支持 Map/Set、保持原型链、拷贝属性描述符

**易错点**:
- ❌ "展开运算符是深拷贝" → ✅ 只是浅拷贝
- ❌ "JSON 方式能完美深拷贝" → ✅ 会丢失函数/undefined/Symbol，不能处理循环引用
