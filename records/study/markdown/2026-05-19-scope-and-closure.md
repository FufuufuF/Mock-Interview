# 作用域与闭包 — 面试要点笔记

> 学习日期：2026-05-19 | 分类：js-basics

## 一句话总结

作用域链决定变量查找路径（定义时确定），闭包是函数 + 其捕获的词法环境引用，使外部变量生命周期被延长。

## 知识要点

### 1. 词法作用域与作用域链

**面试问法**: 请解释 JavaScript 中的作用域链是如何工作的。

**核心回答**:
- JS 采用词法作用域（静态作用域），作用域链在函数**定义时**确定，不是调用时
- 三种作用域：全局、函数、块级（let/const）
- 变量查找沿作用域链逐层向外，直到全局作用域；找不到则 ReferenceError
- 每个作用域对应一个环境记录，通过 [[OuterEnv]] 指向外部环境形成链

**加分细节**:
- 对比词法作用域与动态作用域（Bash 等）
- with/eval 会破坏词法作用域的静态分析
- V8 中环境记录的实体是 Context 对象，通过 parent 指针串联

### 2. 执行上下文与变量环境

**面试问法**: var 的变量提升机制是什么？为什么 let/const 也存在提升但表现不同？

**核心回答**:
- var 和 let/const 都会提升
- var 提升时同时初始化为 undefined
- let/const 只提升声明不初始化，访问未初始化的绑定触发 TDZ（暂时性死区）报错
- 执行上下文中：VariableEnvironment 存 var/function，LexicalEnvironment 存 let/const/class
- 每进入一个 {} 块创建新的 LexicalEnvironment，但 VariableEnvironment 整个函数共享

**加分细节**:
- TDZ 内访问变量不会穿透到外层作用域（引擎已知当前块存在该绑定）
- V8 用 TheHole 哨兵值标记未初始化的 let/const 变量

### 3. 闭包的本质

**面试问法**: 请解释什么是闭包？它是怎么形成的？

**核心回答**:
- 闭包 = 函数 + 它定义时的词法环境的引用
- 形成条件三要素：函数嵌套 + 内部函数引用外部变量 + 内部函数生命周期长于外部函数
- 闭包不只在 return 时形成，事件回调、定时器、赋值给外部变量都可以
- 本质是作用域链 + 垃圾回收的自然结果：内部函数持有 Context 引用，GC 发现可达就不回收

**加分细节**:
- 广义上所有函数都是闭包（都捕获外部环境），狭义上只在变量生命周期被延长时讨论
- V8 优化：只把被内部函数引用的变量放入 Context，其余留在栈上
- 闭包捕获的是变量引用（binding），不是值的快照

### 4. 闭包的应用与陷阱

**面试问法**: 闭包有哪些实际应用场景？for 循环 + setTimeout 输出什么？

**核心回答**:
- 应用场景：数据私有化（模块模式）、函数工厂、缓存/记忆化、防抖节流
- for + var + setTimeout 经典题：所有回调共享同一个 i，输出循环结束后的值
- 修复方式：let（块级作用域）、IIFE（创建新函数作用域）、setTimeout 第三个参数

**加分细节**:
- 能手写 once(fn)、memoize(fn) 等闭包应用
- 三种修复方式都能说出来并解释原理

### 5. 闭包与内存

**面试问法**: 闭包会导致内存泄漏吗？什么时候需要注意？

**核心回答**:
- 闭包本身不是内存泄漏，泄漏发生在无意中延长了变量生命周期
- 高危场景：被遗忘的事件监听器、未清除的定时器、闭包互相引用
- 排查方法：Chrome DevTools → Memory → Heap Snapshot → 对比 → 看 Retainers

**加分细节**:
- V8 只捕获被引用的变量，未引用的大对象会被正常 GC
- eval 会破坏这个优化（引擎被迫保留所有变量）
- 修复手段：removeEventListener、clearInterval、AbortController、手动置 null

## 常见追问及回答

| 追问 | 回答要点 |
|------|---------|
| 词法作用域和动态作用域的区别？ | 词法看定义位置，动态看调用位置；JS 是词法作用域 |
| TDZ 内能否访问外层同名变量？ | 不能，引擎已知当前块有该绑定，不会穿透查找 |
| 所有函数都是闭包吗？ | 广义是（都捕获外部环境），狭义只在延长生命周期时讨论 |
| 闭包捕获的是值还是引用？ | 引用（binding），后续修改对闭包可见 |
| 手写 once(fn)？ | flag + 缓存 result，首次执行后返回缓存值 |

## 易错点

- 误区"let/const 不存在变量提升"：它们有提升，只是不初始化（TDZ）
- 误区"闭包是一个函数"：闭包是函数 + 捕获的环境，两者的组合体
- 误区"闭包 = 内存泄漏"：合理使用不是泄漏，只有无意延长生命周期才是
- 误区"闭包只在 return 时形成"：回调、定时器、赋值外部变量都可以形成闭包
- for + var + setTimeout 输出值：是循环终止值（i=3），不是最后一次迭代值（i=2）
