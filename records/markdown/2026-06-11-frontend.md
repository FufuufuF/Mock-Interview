## 题目与回答

### Q1: 请详细解释 this 的指向规则，并按优先级排列
- **所属模块**: js-basics
- **评分**: B
- **回答摘要**: 列出四种绑定（直接调用 / 方法调用 / 显式绑定 / new 绑定），优先级 new > 显式 > 隐式 > 默认。被指出后自行修正了"直接调用继承外部 this"的错误，并准确回答了构造函数 return 值与对象时的差异。
- **追问**: ① 默认绑定时严格/非严格模式下 this 是什么？② 构造函数有 return 时返回什么？
- **面试官反馈**:
  - 准确部分：四种绑定的分类、优先级排序、`new` 调用时 this 与最终返回对象的分离这个细节回答得很好。
  - 需要修正：默认绑定不是"继承外层 this"，而是非严格模式指向全局对象（浏览器是 window）、严格模式下是 `undefined`（不是 null）。
  - 可以补充：箭头函数没有自己的 this，词法捕获外层作用域的 this，且无法被 call/apply/bind 改变；对应特殊性（不能 new、没有 arguments、没有 prototype）也应一并掌握。

### Q3: 浏览器如何构建 DOM 树和 CSSOM 树？script/link 的影响？
- **所属模块**: browser
- **评分**: D
- **回答摘要**: 完全不记得，跳过。
- **追问**: 无（已跳过）
- **面试官反馈**: 上次面试也是 D。需系统梳理：HTML 字节流 → token → node → DOM 树；CSS 字节流 → CSSOM 树；DOM + CSSOM → Render Tree → Layout → Paint → Composite。`<script>` 默认阻塞 HTML 解析（async/defer 改变行为），且会等待前面的 CSS 加载完成再执行；`<link>` CSS 不阻塞 DOM 解析，但阻塞渲染，阻塞后续 JS 执行。

### Q4: 重排和重绘的区别？什么会触发重排？
- **所属模块**: browser
- **评分**: C
- **回答摘要**: 几何属性变化触发重排，颜色/透明度等触发重绘，重排开销大于重绘。追问"只读属性是否触发"和"transform/opacity 原理"无法回答。
- **追问**: ① 只读取属性会不会触发重排？② transform/opacity 是只触发重绘还是连重绘都不触发？
- **面试官反馈**: 基础概念正确但深度不够。补充：
  - 强制同步布局（Forced Synchronous Layout）：读取 offsetWidth/clientHeight/getBoundingClientRect() 等会强制浏览器立即计算布局。所以"读+写"循环要先读后写或缓存读取。
  - transform 和 opacity 既不触发重排也不触发重绘：它们是合成层属性，由 GPU 单独处理，跳过 Layout 和 Paint 阶段，直接走 Composite。

### Q5: async/await 的原理及代码输出
- **所属模块**: js-basics
