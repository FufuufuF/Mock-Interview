# JavaScript 对象专题：从运行机制到面试题

> 这不是一份对象 API 手册。全文围绕一条主线展开：对象是什么、属性如何工作、对象之间如何关联，以及对象如何参与 JavaScript 的其他机制。

## 核心心智模型

理解 JavaScript 对象，先记住下面这句话：

```text
对象 = 自身属性的集合 + [[Prototype]] + 内部状态
属性 = 属性键 + 属性描述符
```

由此可以推导出整个对象专题：

```text
对象如何创建
  ↓
自身有哪些属性
  ↓
读取和修改属性时发生什么
  ↓
自身找不到属性时，如何沿原型链查找
  ↓
多个对象如何继承、共享和复制数据
  ↓
对象如何比较、转换、迭代和被代理
  ↓
对象如何序列化，以及何时被垃圾回收
```

## 学习优先级

- `🔥 必会`：高频基础题，应当能脱离笔记完整讲述。
- `⭐ 追问`：面试官常在基础答案后继续追问。
- `💡 加分`：理解思想即可，不要求背诵全部细节。

# 一、对象到底是什么

## 1.1 对象不是简单的键值对

我们平时看到的对象是：

```js
const user = {
  name: 'Alice',
  age: 20,
};
```

表面上它是键值对，实际上每个属性还携带一组控制信息：

```text
name
├── value: "Alice"
├── writable: true
├── enumerable: true
└── configurable: true
```

对象还通过内部的 `[[Prototype]]` 指向另一个对象。自身没有某个属性时，引擎可以继续去原型中寻找。

因此，理解对象主要要回答两个问题：

1. 对象自身保存了什么？
2. 对象找不到属性时会去哪里找？

前者是属性描述符，后者是原型链。

## 1.2 属性键为什么只有两种类型

对象的属性键只能是：

- 字符串
- Symbol

数字、布尔值等作为属性键时，会先被转成字符串：

```js
const obj = {};

obj[1] = 'one';
obj[true] = 'yes';

obj['1'];    // "one"
obj['true']; // "yes"
```

这解释了为什么普通对象不适合用任意对象作为键：

```js
const key1 = {};
const key2 = {};
const obj = {};

obj[key1] = 'first';
obj[key2] = 'second';

// key1 和 key2 通常都会变成字符串 "[object Object]"
obj[key1]; // "second"
```

如果需要任意类型的键，应当使用 `Map`；如果需要避免字符串属性名冲突，可以使用 `Symbol`。

## 1.3 创建方式到底改变了什么

对象的创建方式很多，但不应逐个死记。创建对象真正决定的是：

1. 新对象有哪些自身属性。
2. 新对象的 `[[Prototype]]` 指向谁。
3. 初始化逻辑是否能够复用。

### 对象字面量：创建普通对象

```js
const user = {
  name: 'Alice',
  sayHi() {
    return `Hi, ${this.name}`;
  },
};
```

它适合创建单个普通对象，原型通常是 `Object.prototype`：

```js
Object.getPrototypeOf(user) === Object.prototype; // true
```

日常开发优先使用字面量。`new Object()` 通常只会让代码更长，并没有带来不同的普通对象模型。

### 工厂函数：封装对象创建过程

```js
function createUser(name) {
  return {
    name,
    sayHi() {
      return `Hi, ${name}`;
    },
  };
}

const alice = createUser('Alice');
```

它的重点不在特殊语法，而是把创建过程放进函数。缺点是上例每次调用都会创建一个新的 `sayHi` 函数。

### 构造函数：让实例共享原型方法

```js
function User(name) {
  this.name = name;
}

User.prototype.sayHi = function () {
  return `Hi, ${this.name}`;
};

const alice = new User('Alice');
const bob = new User('Bob');
```

两个实例拥有各自的 `name`，但共享同一个原型方法：

```js
alice.sayHi === bob.sayHi; // true
```

### `class`：用更清晰的语法表达同一套模型

```js
class User {
  constructor(name) {
    this.name = name;
  }

  sayHi() {
    return `Hi, ${this.name}`;
  }
}
```

`class` 没有创造新的对象继承机制。`sayHi` 仍然位于 `User.prototype` 上：

```js
User.prototype.sayHi === new User('Alice').sayHi; // true
```

### `Object.create`：直接指定新对象的原型

```js
const animal = {
  speak() {
    return 'sound';
  },
};

const dog = Object.create(animal);
dog.name = 'Lucky';

dog.speak(); // "sound"
Object.getPrototypeOf(dog) === animal; // true
```

它没有调用构造函数，只做了一件核心事情：创建新对象，并把新对象的 `[[Prototype]]` 指向指定对象。

## 1.4 `Object.create(null)` 为什么特殊

```js
const dictionary = Object.create(null);

dictionary.name = 'Alice';
'toString' in dictionary; // false
```

普通对象会继承 `Object.prototype` 上的 `toString`、`constructor` 等属性，而这个对象的原型直接是 `null`：

```js
Object.getPrototypeOf(dictionary) === null; // true
```

所以它适合充当纯字符串字典，但它也没有 `hasOwnProperty` 等继承方法：

```js
Object.hasOwn(dictionary, 'name'); // true
```

## 1.5 对象字面量中的 ES6 语法

这些语法只是让创建自身属性更方便，不改变对象模型。

```js
const name = 'Alice';
const key = 'age';

const user = {
  name,          // 属性简写
  [key]: 20,     // 计算属性名
  sayHi() {      // 方法简写
    return `Hi, ${this.name}`;
  },
};
```

计算属性名最终仍必须得到字符串或 Symbol：

```js
const id = Symbol('id');

const user = {
  ['user' + 'Name']: 'Alice',
  [id]: 1001,
};
```

## 1.6 第一章面试回答

### `🔥 必会`：JavaScript 对象是什么？

> JavaScript 对象可以理解为自身属性的集合，每个属性由属性键和属性描述符组成。属性键只能是字符串或 Symbol。对象内部还有 `[[Prototype]]`，自身找不到属性时会沿着它继续查找。字面量、构造函数、class 和 Object.create 的主要区别，是它们如何初始化自身属性，以及把新对象的原型指向哪里。

### `⭐ 追问`：`class` 和构造函数是不是两套机制？

> 不是。class 是对构造函数和原型机制的语法封装。实例属性通常由 constructor 初始化，实例方法仍然定义在类的 prototype 上，实例通过原型链访问这些方法。

# 二、执行 `obj.x` 时发生了什么

## 2.1 属性读取的完整过程

执行下面的代码时：

```js
const value = obj.x;
```

可以把引擎的行为理解为：

```text
1. 在 obj 的自身属性中查找 x
2. 找到数据属性 → 返回 value
3. 找到访问器属性 → 调用 getter
4. 自身没有 → 去 obj 的 [[Prototype]] 中继续查找
5. 一直找到属性，或者原型变成 null
6. 最终仍未找到 → 返回 undefined
```

先看一个例子：

```js
const parent = {
  role: 'guest',
};

const user = Object.create(parent);
user.name = 'Alice';

user.name;    // "Alice"，自身属性
user.role;    // "guest"，原型属性
user.missing; // undefined，整条链都没找到
```

因此，读取结果为 `undefined` 不一定说明属性不存在：

```js
const obj = { x: undefined };

obj.x;                    // undefined
Object.hasOwn(obj, 'x');  // true
```

## 2.2 属性描述符为什么存在

属性描述符决定找到属性之后能做什么。

数据属性有四个主要特性：

| 特性 | 回答的问题 |
|------|------------|
| `value` | 属性保存的值是什么？ |
| `writable` | 能否通过赋值修改值？ |
| `enumerable` | 常规遍历能否看到它？ |
| `configurable` | 能否删除或重新配置它？ |

普通赋值创建的属性默认都比较开放：

```js
const user = { name: 'Alice' };

Object.getOwnPropertyDescriptor(user, 'name');
// {
//   value: 'Alice',
//   writable: true,
//   enumerable: true,
//   configurable: true
// }
```

`Object.defineProperty` 的作用，是让我们显式控制这些规则：

```js
const user = {};

Object.defineProperty(user, 'id', {
  value: 1001,
  writable: false,
  enumerable: false,
  configurable: false,
});
```

现在：

```js
user.id;              // 1001，仍然可以读取
Object.keys(user);     // []，不可枚举
user.id = 1002;        // 修改失败
delete user.id;        // 删除失败
```

### 高频陷阱：默认值不同

对象字面量或普通赋值创建的属性，三个布尔特性默认是 `true`；通过 `defineProperty` 新建属性时，省略的布尔特性默认是 `false`。

```js
const obj = {};

Object.defineProperty(obj, 'x', {
  value: 1,
});

Object.getOwnPropertyDescriptor(obj, 'x');
// writable: false
// enumerable: false
// configurable: false
```

这比背诵 API 参数更重要，因为它直接决定后面的赋值、遍历和删除行为。

## 2.3 getter 和 setter 改变了什么

访问器属性不直接保存 `value`，而是在读取或赋值时执行函数：

```js
const user = {
  firstName: 'Ada',
  lastName: 'Lovelace',

  get fullName() {
    return `${this.firstName} ${this.lastName}`;
  },

  set fullName(value) {
    [this.firstName, this.lastName] = value.split(' ');
  },
};

user.fullName; // 自动调用 getter
user.fullName = 'Grace Hopper'; // 自动调用 setter
```

它仍然符合属性读取流程，只是“找到属性以后”执行的不是返回 `value`，而是调用 getter。

### getter 中的 `this` 指向谁

```js
const parent = {
  get label() {
    return this.name;
  },
};

const child = Object.create(parent);
child.name = 'child';

child.label; // "child"
```

getter 虽然定义在 `parent` 上，但本次访问从 `child` 发起，所以 getter 中的 `this` 是 `child`。这也是后面 `Reflect.get` 为什么需要 `receiver` 的基础。

## 2.4 属性赋值的完整过程

读取属性主要是“沿链向上找”，赋值则更复杂。执行：

```js
obj.x = 2;
```

要考虑：

```text
1. obj 自身是否已有 x
2. 如果有，它是可写数据属性还是 setter
3. 如果没有，原型链上是否存在同名 setter
4. 原型链上是否存在不可写的同名数据属性
5. 是否可以在 obj 上创建新的自身属性
```

最常见情况是创建或修改自身属性：

```js
const parent = { x: 1 };
const child = Object.create(parent);

child.x = 2;

child.x;  // 2
parent.x; // 1
```

赋值没有修改 `parent.x`，而是在 `child` 上创建了新的同名属性。

## 2.5 属性遮蔽

自身属性和原型属性同名时，自身属性会遮蔽原型属性：

```text
child.x = 2       ← 先找到
   ↓ [[Prototype]]
parent.x = 1      ← 被遮蔽
```

删除自身属性后，原型属性会重新暴露：

```js
delete child.x;
child.x; // 1
```

因此下面两句话不是一回事：

- 修改原型属性
- 在实例上创建同名属性

### 原型 setter 会接管赋值

```js
const parent = {
  set score(value) {
    this._score = value;
  },
};

const child = Object.create(parent);
child.score = 100;

child._score; // 100
Object.hasOwn(child, 'score'); // false
```

赋值找到了原型上的 setter，因此调用 setter，而不是创建自身的 `score` 数据属性。

### 原型上的不可写属性会阻止普通赋值

```js
const parent = {};

Object.defineProperty(parent, 'id', {
  value: 1,
  writable: false,
});

const child = Object.create(parent);
child.id = 2;

child.id; // 1
Object.hasOwn(child, 'id'); // false
```

严格模式下，这类失败通常会抛出 `TypeError`；非严格模式下可能静默失败。

## 2.6 `configurable` 为什么是最强的开关

`configurable: false` 表示属性结构基本被锁定：

- 不能删除。
- 不能改成访问器属性。
- 不能修改 `enumerable`。
- 不能重新变成可配置。

但它不等于“值一定不能修改”：

```js
const obj = {};

Object.defineProperty(obj, 'x', {
  value: 1,
  writable: true,
  configurable: false,
});

obj.x = 2; // 可以，因为 writable 仍为 true
```

所以需要区分：

- `writable` 管值能否赋值修改。
- `configurable` 管属性结构能否被重定义或删除。

## 2.7 删除属性时发生什么

```js
delete obj.x;
```

`delete` 只尝试删除对象的自身属性，不会沿原型链删除：

```js
const parent = { x: 1 };
const child = Object.create(parent);

delete child.x; // child 本来就没有自身 x
parent.x;       // 1
```

不可配置属性无法删除。删除数组元素还会留下空位：

```js
const arr = ['a', 'b', 'c'];
delete arr[1];

arr.length; // 3
1 in arr;   // false
```

因此删除数组元素通常使用 `splice`，而不是 `delete`。

## 2.8 对象不可变性的层级

理解描述符后，三个 API 不需要单独死记：

```text
preventExtensions
└── 不允许增加新属性

seal
├── 不允许增加新属性
└── 所有自身属性 configurable = false

freeze
├── seal 的全部限制
└── 所有自身数据属性 writable = false
```

| 操作 | 禁止新增 | 禁止删除 | 禁止修改已有值 |
|------|----------|----------|----------------|
| `preventExtensions` | 是 | 否 | 否 |
| `seal` | 是 | 是 | 否，原本可写的值仍能改 |
| `freeze` | 是 | 是 | 是 |

三者都只作用于当前对象：

```js
const config = Object.freeze({
  api: { timeout: 1000 },
});

config.api.timeout = 2000; // 仍然可以
```

这是因为被冻结的是 `config.api` 这个属性，不能把它改指向另一个对象；它指向的对象本身没有被冻结。

一个简洁的深冻结实现：

```js
function deepFreeze(value, visited = new WeakSet()) {
  if (
    value === null ||
    (typeof value !== 'object' && typeof value !== 'function') ||
    visited.has(value)
  ) {
    return value;
  }

  visited.add(value);

  for (const key of Reflect.ownKeys(value)) {
    deepFreeze(value[key], visited);
  }

  return Object.freeze(value);
}
```

`WeakSet` 用来防止循环引用导致无限递归。

### `const` 和 `freeze` 不在同一层

```js
const user = { name: 'Alice' };

user.name = 'Bob'; // 可以
// user = {};      // 不可以
```

`const` 限制变量重新指向别的值；`freeze` 限制对象自身属性。一个约束变量绑定，一个约束对象内容。

## 2.9 第二章面试回答

### `🔥 必会`：读取对象属性时发生了什么？

> 引擎先查对象自身属性，找到数据属性就返回 value，找到访问器属性就调用 getter；自身没有则沿 `[[Prototype]]` 继续查找，直到找到属性或原型为 null。整条链都没有时返回 undefined。

### `🔥 必会`：数据属性的四个描述符是什么？

> value 保存属性值，writable 控制能否赋值修改，enumerable 控制常规枚举能否看到，configurable 控制能否删除或重新配置。普通赋值创建的属性默认都为 true，而 defineProperty 省略的布尔配置默认是 false。

### `⭐ 追问`：给继承属性赋值会修改原型吗？

> 通常不会，而是在当前对象上创建同名自身属性，形成属性遮蔽。但如果原型上有 setter，就会调用 setter；如果原型上是不可写的数据属性，普通赋值会失败。

# 三、为什么不同遍历方式结果不同

## 3.1 遍历问题只有三个维度

面对任何对象遍历 API，先不要背名字，先问三个问题：

```text
1. 要自身属性，还是也要原型属性？
2. 只要可枚举属性，还是全部属性？
3. 只要字符串键，还是也要 Symbol 键？
```

例如：

```js
const symbol = Symbol('id');
const parent = { inherited: 1 };
const obj = Object.create(parent);

obj.visible = 2;
obj[symbol] = 3;

Object.defineProperty(obj, 'hidden', {
  value: 4,
  enumerable: false,
});
```

这个对象有四类可观察属性：

```text
visible    自身 + 可枚举 + 字符串
hidden     自身 + 不可枚举 + 字符串
Symbol(id) 自身 + 可枚举 + Symbol
inherited  原型 + 可枚举 + 字符串
```

不同方法只是选择了不同范围。

## 3.2 高频遍历方法如何放进这套模型

| 方法 | 自身 | 原型 | 不可枚举 | Symbol |
|------|------|------|----------|--------|
| `for...in` | 是 | 是 | 否 | 否 |
| `Object.keys` | 是 | 否 | 否 | 否 |
| `Object.getOwnPropertyNames` | 是 | 否 | 是 | 否 |
| `Object.getOwnPropertySymbols` | 是 | 否 | 是 | 是，仅 Symbol |
| `Reflect.ownKeys` | 是 | 否 | 是 | 是 |

应用到刚才的对象：

```js
Object.keys(obj);
// ["visible"]

Object.getOwnPropertyNames(obj);
// ["visible", "hidden"]

Object.getOwnPropertySymbols(obj);
// [Symbol(id)]

Reflect.ownKeys(obj);
// ["visible", "hidden", Symbol(id)]
```

`for...in` 还会继续访问原型：

```js
for (const key in obj) {
  console.log(key);
}
// visible
// inherited
```

如果只想在 `for...in` 中处理自身属性：

```js
for (const key in obj) {
  if (Object.hasOwn(obj, key)) {
    console.log(key);
  }
}
```

## 3.3 `in` 和 `Object.hasOwn` 为什么不同

它们回答的是两个不同问题：

```text
'x' in obj
→ 按照正常属性查找过程，能否在自身或原型链找到 x？

Object.hasOwn(obj, 'x')
→ x 是否直接存储在 obj 自身？
```

```js
const obj = {};

'toString' in obj;                // true
Object.hasOwn(obj, 'toString');   // false
```

`toString` 可以通过原型链访问，但不属于对象自身。

### 为什么推荐 `Object.hasOwn`

传统写法是：

```js
obj.hasOwnProperty('x');
```

但对象可能没有继承这个方法：

```js
const obj = Object.create(null);
obj.x = 1;

Object.hasOwn(obj, 'x'); // true
```

对象也可能自己定义了同名属性。`Object.hasOwn` 不依赖对象自身的方法，因此更可靠。

## 3.4 `keys`、`values`、`entries` 是同一个范围

这三个方法选择的属性范围完全相同：自身、可枚举、字符串键。

```js
const user = { name: 'Alice', age: 20 };

Object.keys(user);
// ["name", "age"]

Object.values(user);
// ["Alice", 20]

Object.entries(user);
// [["name", "Alice"], ["age", 20]]
```

它们的区别只是输出形式，不需要当成三个独立知识点。

`Object.entries` 经常与 `Object.fromEntries` 形成转换流程：

```js
const prices = { apple: 10, banana: 5 };

const doubled = Object.fromEntries(
  Object.entries(prices).map(([name, price]) => [name, price * 2]),
);

// { apple: 20, banana: 10 }
```

## 3.5 展开语法复制了哪些属性

对象展开的范围是：自身、可枚举、字符串和 Symbol 属性。

```js
const id = Symbol('id');
const source = {
  name: 'Alice',
  [id]: 1001,
};

Object.defineProperty(source, 'hidden', {
  value: true,
  enumerable: false,
});

const copy = { ...source };

copy.name;   // "Alice"
copy[id];    // 1001
copy.hidden; // undefined
```

这说明对象展开并不等于 `Object.keys`：二者都忽略不可枚举属性，但展开语法会复制可枚举 Symbol 属性。

## 3.6 属性顺序为什么看起来“不完全按插入顺序”

普通对象自身键的核心顺序是：

```text
1. 数组索引键：按数值升序
2. 其他字符串键：按创建顺序
3. Symbol 键：按创建顺序
```

```js
const first = Symbol('first');
const obj = {};

obj.b = 1;
obj[10] = 2;
obj[2] = 3;
obj.a = 4;
obj[first] = 5;

Reflect.ownKeys(obj);
// ["2", "10", "b", "a", Symbol(first)]
```

面试中掌握这条主规则即可，不需要背所有数字字符串的规范边界。

如果业务强依赖严格插入顺序和任意类型键，通常应考虑 `Map`，而不是利用普通对象的属性顺序实现复杂逻辑。

## 3.7 为什么不建议用 `for...in` 遍历数组

数组本质上也是对象，因此 `for...in` 遍历的是可枚举字符串属性，而不是“数组元素协议”：

```js
const arr = ['a', 'b'];
arr.extra = 'value';

for (const key in arr) {
  console.log(key); // "0"、"1"、"extra"
}
```

遍历数组值应优先使用 `for...of`：

```js
for (const value of arr) {
  console.log(value); // "a"、"b"
}
```

两者背后的问题不同：

- `for...in` 枚举属性键。
- `for...of` 消费对象的迭代器。

## 3.8 第三章面试回答

### `🔥 必会`：对象遍历方法有什么区别？

> 我会从自身还是原型、可枚举还是全部、字符串还是 Symbol 三个维度区分。for...in 会遍历自身和原型链上的可枚举字符串属性；Object.keys 只取自身可枚举字符串属性；Reflect.ownKeys 则取得全部自身字符串和 Symbol 键，不区分是否可枚举。

### `🔥 必会`：`in` 和 `Object.hasOwn` 有什么区别？

> `in` 遵循属性查找过程，会检查自身和整条原型链；`Object.hasOwn` 只判断自身属性。现代代码更推荐用 `Object.hasOwn` 代替直接调用 hasOwnProperty，因为它也适用于 null 原型对象，并且不怕同名属性覆盖。

### `⭐ 追问`：对象属性的顺序是什么？

> 普通对象的自身键通常先按数组索引升序排列，再按创建顺序排列其他字符串键，最后按创建顺序排列 Symbol 键。如果业务真正需要任意键和明确插入序，Map 通常更合适。

- [ ] 不靠死记也能推出 `Object.keys` 和 `Reflect.ownKeys` 的区别。
- [ ] 能解释 `in` 与 `Object.hasOwn` 回答的不同问题。
- [ ] 能说明 `for...in` 和 `for...of` 为什么不同。

# 四、对象之间如何建立关系

## 4.1 原型的本质是属性查找委托

假设很多用户对象都需要 `sayHi` 方法。如果把方法放进每个对象，会创建许多功能相同的函数：

```js
const user1 = { sayHi() {} };
const user2 = { sayHi() {} };

user1.sayHi === user2.sayHi; // false
```

JavaScript 的解决方案不是把方法复制给每个实例，而是让多个对象把属性查找委托给同一个原型：

```text
user1 ─┐
       ├──→ User.prototype ──→ Object.prototype ──→ null
user2 ─┘
```

```js
function User(name) {
  this.name = name;
}

User.prototype.sayHi = function () {
  return `Hi, ${this.name}`;
};

const user1 = new User('Alice');
const user2 = new User('Bob');

user1.sayHi === user2.sayHi; // true
```

方法实际只存了一份，实例通过原型链找到它。

## 4.2 `prototype` 和 `[[Prototype]]` 为什么容易混淆

它们属于不同对象，作用也不同：

```text
User.prototype
→ User 函数上的普通属性
→ 将来用作实例的原型

user 的 [[Prototype]]
→ user 对象内部真正的原型链接
→ 指向 User.prototype
```

```js
function User() {}
const user = new User();

Object.getPrototypeOf(user) === User.prototype; // true
```

历史属性 `__proto__` 通常可以访问 `[[Prototype]]`：

```js
user.__proto__ === User.prototype; // true
```

但正式代码应使用：

```js
Object.getPrototypeOf(user);
Object.setPrototypeOf(user, anotherPrototype);
```

不要把下面两条关系混成一条：

```js
Object.getPrototypeOf(user) === User.prototype;     // 实例继承原型
Object.getPrototypeOf(User) === Function.prototype; // 函数自身也是对象
```

`User.prototype` 用来服务实例；`User` 自己的原型则让函数继承 `call`、`apply` 等函数能力。

## 4.3 原型链在哪里结束

普通实例的典型原型链：

```text
user
  ↓
User.prototype
  ↓
Object.prototype
  ↓
null
```

```js
Object.getPrototypeOf(user) === User.prototype; // true
Object.getPrototypeOf(User.prototype) === Object.prototype; // true
Object.getPrototypeOf(Object.prototype) === null; // true
```

`null` 表示已经没有下一个原型，属性查找在这里结束。

## 4.4 `new` 到底做了什么

执行：

```js
const user = new User('Alice');
```

可以拆成四步：

```text
1. 创建一个新对象
2. 新对象的 [[Prototype]] 指向 User.prototype
3. 用新对象作为 this 调用 User('Alice')
4. 返回新对象，除非构造函数显式返回了另一个对象
```

手写实现：

```js
function myNew(Constructor, ...args) {
  const instance = Object.create(Constructor.prototype);
  const result = Constructor.apply(instance, args);

  const returnedObject =
    result !== null &&
    (typeof result === 'object' || typeof result === 'function');

  return returnedObject ? result : instance;
}
```

验证：

```js
function User(name) {
  this.name = name;
}

const user = myNew(User, 'Alice');

user.name; // "Alice"
Object.getPrototypeOf(user) === User.prototype; // true
```

### 构造函数返回值的规则

```js
function A() {
  this.x = 1;
  return 100;
}

new A(); // 仍返回拥有 x 的实例
```

基本类型返回值会被忽略。若显式返回对象，则该对象替代新实例：

```js
function B() {
  this.x = 1;
  return { y: 2 };
}

new B(); // { y: 2 }
```

## 4.5 `instanceof` 为什么沿原型链判断

```js
user instanceof User;
```

默认含义是：`User.prototype` 是否出现在 `user` 的原型链上。

```text
user
  ↓
User.prototype  ← 找到，返回 true
  ↓
Object.prototype
  ↓
null
```

简化实现：

```js
function myInstanceof(value, Constructor) {
  if (
    value === null ||
    (typeof value !== 'object' && typeof value !== 'function')
  ) {
    return false;
  }

  let proto = Object.getPrototypeOf(value);

  while (proto !== null) {
    if (proto === Constructor.prototype) return true;
    proto = Object.getPrototypeOf(proto);
  }

  return false;
}
```

这解释了为什么一个对象可以同时是多个类型的实例：

```js
user instanceof User;   // true
user instanceof Object; // true
```

因为两个构造函数的 `prototype` 都在它的原型链上。

`Symbol.hasInstance` 可以自定义 `instanceof`，因此“检查原型链”描述的是默认机制，不是所有情况。

## 4.6 继承实际要解决两个问题

构造函数继承不是单纯“连一条原型链”，而是要同时解决：

```text
实例属性：每个子实例应当拥有独立状态
原型方法：子实例应当复用父类型方法
```

传统继承方案的演进，就是不断解决这两个问题。

## 4.7 原型链继承：共享了不该共享的状态

```js
function Parent() {
  this.colors = ['red'];
}

Parent.prototype.sayHi = function () {
  return 'hi';
};

function Child() {}

Child.prototype = new Parent();
```

现在父构造函数创建的 `colors` 位于 `Child.prototype` 上：

```js
const child1 = new Child();
const child2 = new Child();

child1.colors.push('blue');
child2.colors; // ["red", "blue"]
```

两个实例通过原型共享同一个数组。这说明引用类型的实例状态不应放在共享原型上。

## 4.8 借用构造函数：状态独立，但方法没有继承

```js
function Parent(name) {
  this.name = name;
  this.colors = ['red'];
}

function Child(name, age) {
  Parent.call(this, name);
  this.age = age;
}
```

`Parent.call(this)` 让每个子实例分别执行父构造函数，因此状态独立：

```js
const child1 = new Child('Alice', 10);
const child2 = new Child('Bob', 12);

child1.colors !== child2.colors; // true
```

但 `Child.prototype` 没有连接到 `Parent.prototype`，所以父原型方法没有继承。

## 4.9 组合继承：同时解决两个问题，但执行两次父构造函数

```js
function Child(name, age) {
  Parent.call(this, name); // 初始化独立状态
  this.age = age;
}

Child.prototype = new Parent(); // 继承原型方法
Child.prototype.constructor = Child;
```

它同时获得独立实例属性和共享原型方法，但 `Parent` 被调用了两次：

1. 创建 `Child.prototype` 时一次。
2. 创建每个 `Child` 实例时一次。

问题已经很接近解决，只需要避免为了连接原型而执行父构造函数。

## 4.10 寄生组合式继承：只连接原型，不执行父构造函数

```js
function Parent(name) {
  this.name = name;
  this.colors = ['red'];
}

Parent.prototype.sayHi = function () {
  return `Hi, ${this.name}`;
};

function Child(name, age) {
  Parent.call(this, name);
  this.age = age;
}

Child.prototype = Object.create(Parent.prototype);

Object.defineProperty(Child.prototype, 'constructor', {
  value: Child,
  writable: true,
  configurable: true,
});
```

逻辑分工非常清楚：

```text
Parent.call(this)
→ 继承并初始化父类型的实例属性

Object.create(Parent.prototype)
→ 让子类型原型委托给父类型原型
```

`constructor` 被修复是因为替换了整个 `Child.prototype`。它主要用于维持原型结构的合理反射结果，不是 `new Child()` 能工作的前提。

## 4.11 `class extends` 如何表达同一逻辑

```js
class Parent {
  constructor(name) {
    this.name = name;
  }

  sayHi() {
    return `Hi, ${this.name}`;
  }

  static category() {
    return 'person';
  }
}

class Child extends Parent {
  constructor(name, age) {
    super(name);
    this.age = age;
  }

  sayHi() {
    return `${super.sayHi()}, age ${this.age}`;
  }
}
```

它建立两条关系：

```js
Object.getPrototypeOf(Child.prototype) === Parent.prototype;
// 实例方法继承

Object.getPrototypeOf(Child) === Parent;
// 静态方法继承
```

第一条让子实例找到父类实例方法；第二条让 `Child.category()` 能找到父类静态方法。

## 4.12 `super` 到底表示什么

### 构造函数中的 `super()`

派生类构造函数必须先调用 `super()`，再使用 `this`：

```js
class Child extends Parent {
  constructor(name) {
    // this.name = name; // ReferenceError
    super(name);
    this.age = 10;
  }
}
```

`super()` 执行父类构造过程，并完成派生实例的 `this` 初始化。

### 方法中的 `super.method()`

```js
class Child extends Parent {
  sayHi() {
    return super.sayHi();
  }
}
```

它从当前方法所属对象的原型上查找 `sayHi`，但调用时 `this` 仍然是当前实例。因此父类方法读取到的仍是子实例的数据。

## 4.13 为什么动态修改原型通常不推荐

```js
Object.setPrototypeOf(obj, newPrototype);
```

语义上可行，但对象创建后再改变原型，可能破坏引擎对对象结构的优化，也让关系更难理解。通常应在创建时确定：

```js
const obj = Object.create(prototype);
```

或者通过 `class extends` 建立稳定继承关系。

## 4.14 第四章面试回答

### `🔥 必会`：`prototype` 和 `__proto__` 有什么区别？

> `prototype` 通常是构造函数上的普通属性，用作实例的原型；实例内部真正保存的是 `[[Prototype]]`，它会指向构造函数的 prototype。`__proto__` 是访问 `[[Prototype]]` 的历史方式，正式代码应使用 Object.getPrototypeOf。

### `🔥 必会`：`new` 做了什么？

> new 创建一个新对象，把它的 `[[Prototype]]` 指向构造函数的 prototype，再以新对象作为 this 调用构造函数。构造函数如果显式返回对象就使用该对象，否则返回新创建的实例。

### `🔥 必会`：寄生组合式继承为什么更合理？

> 它把实例属性和原型方法分开处理：用 `Parent.call(this)` 初始化每个实例自己的父类属性，用 `Object.create(Parent.prototype)` 建立原型方法继承。这样既不会共享实例引用属性，也不会为了创建子原型而额外执行一次父构造函数。

### `⭐ 追问`：`class extends` 建立了哪两条链？

> `Child.prototype` 的原型指向 `Parent.prototype`，用于继承实例方法；Child 构造函数自身的原型指向 Parent，用于继承静态方法。

# 五、对象为什么会共享、复制和变化

## 5.1 变量保存的是对象身份的引用

先看基本值：

```js
let a = 1;
let b = a;

b = 2;
a; // 1
```

赋值后，两个变量各自拥有数值 `1`，修改 `b` 不影响 `a`。

再看对象：

```js
const a = { count: 1 };
const b = a;

b.count = 2;
a.count; // 2
```

这里没有创建第二个对象。`a` 和 `b` 保存的引用都指向同一个对象：

```text
a ─┐
   ├──→ { count: 2 }
b ─┘
```

但两个变量本身仍然独立：

```js
let a = { count: 1 };
let b = a;

b = { count: 2 };

a.count; // 1
```

重新给 `b` 赋值只改变 `b` 指向哪里，不会替换 `a` 指向的对象。

## 5.2 JavaScript 到底是值传递还是引用传递

JavaScript 参数始终按值传递。传入对象时，被复制的值恰好是指向同一对象的引用。

```js
function update(user) {
  user.name = 'Bob';
  user = { name: 'Carol' };
}

const user = { name: 'Alice' };
update(user);

user.name; // "Bob"
```

过程是：

```text
调用时：形参 user 得到一份引用值副本
修改 user.name：通过副本访问同一对象，外部可见
重新给 user 赋值：只改变局部形参，外部变量不变
```

有些资料称其为“按共享传递”，强调双方共享同一对象。不要说成传统意义上的按引用传递，因为函数不能直接改变调用方变量的绑定。

## 5.3 浅拷贝切断了哪一层引用

```js
const source = {
  name: 'Alice',
  profile: {
    city: 'Shanghai',
  },
};

const copy = { ...source };
```

现在顶层对象已经不同：

```js
copy !== source; // true
```

但浅拷贝只是逐个复制第一层属性值。`profile` 的属性值是引用，所以它也被原样复制：

```js
copy.profile === source.profile; // true

copy.profile.city = 'Beijing';
source.profile.city; // "Beijing"
```

内存关系是：

```text
source ──→ { profile: ─┐ }
                       ├──→ { city: "Beijing" }
copy   ──→ { profile: ─┘ }
```

常见浅拷贝方式：

```js
const objectCopy1 = { ...source };
const objectCopy2 = Object.assign({}, source);

const arrayCopy1 = [...array];
const arrayCopy2 = array.slice();
const arrayCopy3 = Array.from(array);
```

它们不需要分别背诵。共同点都是“创建新容器，再复制一层元素或属性值”。

## 5.4 展开语法和 `Object.assign` 的核心区别

二者都复制可枚举自身的字符串和 Symbol 属性，也都会读取源对象的属性值，因此源 getter 可能执行。

最常见的语义区别是目标：

```js
const copy = { ...source };
// 创建一个新对象

Object.assign(target, source);
// 把属性写入现有 target，并返回 target
```

`Object.assign` 使用普通属性赋值写入目标，所以目标上的 setter 可能被触发；对象展开在新对象上创建属性。

面试通常回答到“二者都是浅拷贝，assign 修改目标，展开创建新对象”已经足够。

## 5.5 深拷贝要解决什么

深拷贝的目标不是只创建新顶层对象，而是让嵌套的可变对象也不再共享：

```js
const copy = deepClone(source);

copy !== source;
copy.profile !== source.profile;
```

一个真正有用的深拷贝实现要考虑：

1. 普通对象和数组如何递归。
2. Date、RegExp、Map、Set 等特殊对象如何创建。
3. 循环引用如何终止递归。
4. 同一个源对象被多处引用时，克隆后是否仍保持共享关系。

## 5.6 为什么 JSON 方案不是真正的通用深拷贝

```js
const copy = JSON.parse(JSON.stringify(source));
```

它确实能复制纯 JSON 数据，但序列化过程会主动改变或丢弃很多 JavaScript 值：

| 原值 | JSON 结果 |
|------|-----------|
| 对象属性中的 `undefined`、函数、Symbol | 属性消失 |
| 数组中的这些值 | `null` |
| `NaN`、`Infinity` | `null` |
| Date | 字符串 |
| RegExp、Map、Set | 通常变成普通空对象 |
| BigInt | 抛错 |
| 循环引用 | 抛错 |

```js
const source = {
  date: new Date(),
  value: undefined,
  regexp: /js/,
};

JSON.parse(JSON.stringify(source));
// date 变成字符串，value 消失，regexp 变成 {}
```

所以更准确的说法是：它是“通过 JSON 往返创建纯数据副本”，不是 JavaScript 对象的通用深拷贝。

## 5.7 `structuredClone` 解决了哪些问题

现代环境提供标准结构化克隆：

```js
const source = {
  date: new Date(),
  map: new Map([['x', 1]]),
  set: new Set([1, 2]),
};

source.self = source;

const copy = structuredClone(source);

copy.self === copy;        // true
copy.date instanceof Date; // true
copy.map instanceof Map;   // true
```

它比 JSON 方案更适合复杂数据：

- 支持循环引用。
- 支持 Date、RegExp、Map、Set 等常见内置类型。
- 能保留共享引用关系。

但它仍不是“克隆任何 JavaScript 值”：

- 函数不能克隆。
- WeakMap、WeakSet 等不能克隆。
- 自定义原型和属性描述符通常不会原样保留。
- DOM 等宿主对象有自己的复制方式。

面试时说明这些主要边界即可，不需要背完整支持类型列表。

## 5.8 为什么循环引用需要缓存

```js
const source = {};
source.self = source;
```

如果递归看到对象就继续复制：

```text
复制 source
→ 复制 source.self
→ 又是 source
→ 再复制 source.self
→ 无限递归
```

解决思路是记录：某个源对象是否已经创建过克隆。

```text
WeakMap
源对象 ──→ 对应的克隆对象
```

关键顺序是先缓存，再递归子属性：

```js
const clone = {};
cache.set(source, clone);
// 然后再复制 source 的子属性
```

当再次遇到 `source` 时，直接返回缓存中的 `clone`。

## 5.9 面试版深拷贝

下面实现保留高频要求，不追求克隆所有宿主对象和冷门内部类型：

```js
function deepClone(value, cache = new WeakMap()) {
  if (value === null || typeof value !== 'object') {
    return value;
  }

  if (cache.has(value)) {
    return cache.get(value);
  }

  if (value instanceof Date) {
    return new Date(value.getTime());
  }

  if (value instanceof RegExp) {
    return new RegExp(value.source, value.flags);
  }

  if (value instanceof Map) {
    const clone = new Map();
    cache.set(value, clone);

    for (const [key, item] of value) {
      clone.set(deepClone(key, cache), deepClone(item, cache));
    }

    return clone;
  }

  if (value instanceof Set) {
    const clone = new Set();
    cache.set(value, clone);

    for (const item of value) {
      clone.add(deepClone(item, cache));
    }

    return clone;
  }

  const clone = Array.isArray(value)
    ? []
    : Object.create(Object.getPrototypeOf(value));

  cache.set(value, clone);

  for (const key of Reflect.ownKeys(value)) {
    clone[key] = deepClone(value[key], cache);
  }

  return clone;
}
```

它体现了面试官真正想看的几件事：

- 递归思想。
- 基本值终止条件。
- 数组和普通对象的创建。
- 特殊类型分支。
- 用 WeakMap 处理循环引用。
- 用 `Reflect.ownKeys` 处理 Symbol 键。

如果面试官继续追问属性描述符、不可枚举属性或更多内置类型，再说明可以继续扩展，不必一开始写成对象克隆框架。

## 5.10 不可变更新为什么有用

假设直接修改旧状态：

```js
const previous = {
  user: { name: 'Alice' },
};

previous.user.name = 'Bob';
```

对象身份没有变化，仅通过浅比较无法知道内容是否变了。

不可变更新会为发生变化的路径创建新对象：

```js
const next = {
  ...previous,
  user: {
    ...previous.user,
    name: 'Bob',
  },
};

next !== previous;               // true
next.user !== previous.user;     // true
```

未变化的分支仍可共享引用。这让引用身份成为廉价的变化信号，是 React 和许多状态管理方案依赖浅比较的重要原因。

这和 `Object.freeze` 不完全相同：

- `freeze` 是限制当前对象被修改。
- 不可变更新是创建新状态、不原地修改旧状态的编程方式。

## 5.11 第五章面试回答

### `🔥 必会`：JavaScript 对象参数是按值还是按引用传递？

> JavaScript 始终按值传递。对象作为参数时，复制的是指向同一对象的引用值，因此函数可以通过这个引用修改共享对象，但重新给形参赋值不会改变调用方变量。也可以称为按共享传递，但不是传统的按引用传递。

### `🔥 必会`：浅拷贝和深拷贝有什么区别？

> 浅拷贝只创建新的第一层容器，嵌套对象的引用仍然共享；深拷贝会继续复制嵌套对象，使两边尽量独立。展开语法、Object.assign、数组展开和 slice 都是浅拷贝。

### `🔥 必会`：手写深拷贝为什么使用 WeakMap？

> WeakMap 记录源对象到克隆对象的映射。再次遇到同一个源对象时直接返回已有克隆，这既能终止循环引用，也能保留多个属性原本指向同一对象的共享关系。

### `⭐ 追问`：`structuredClone` 能完全替代手写深拷贝吗？

> 它是标准且更可靠的首选，支持循环引用和多种内置类型，但不能克隆函数、WeakMap 等，也不会完整保留自定义原型和属性描述符。是否适用仍取决于业务需要保留什么语义。

- [ ] 能解释对象参数为什么可修改属性却不能替换外部变量。
- [ ] 能说明 JSON 方案丢失的主要类型。
- [ ] 能写出循环安全的面试版深拷贝。
- [ ] 能从引用身份解释不可变更新的价值。

# 六、对象如何参与判断、比较和运算

## 6.1 类型判断首先要明确“想判断什么”

“怎么判断对象类型”没有唯一答案，因为可能在问不同问题：

```text
它是基本类型还是对象？        → typeof
它是不是数组？                → Array.isArray
某个原型是否在它的链上？      → instanceof
它暴露的内建类型标签是什么？  → Object.prototype.toString.call
它是否具备某项能力？          → 协议或鸭子类型检查
```

### `typeof` 适合做第一层分类

```js
typeof 1;             // "number"
typeof 'x';           // "string"
typeof true;          // "boolean"
typeof undefined;     // "undefined"
typeof Symbol();      // "symbol"
typeof 1n;            // "bigint"
typeof function () {}; // "function"

typeof {};            // "object"
typeof [];            // "object"
typeof new Date();    // "object"
typeof null;          // "object"
```

`typeof` 无法继续区分数组、日期和普通对象。

`typeof null === 'object'` 是早期实现遗留的历史问题。判断非空对象时必须排除 `null`：

```js
function isObjectLike(value) {
  return value !== null && typeof value === 'object';
}
```

若函数也应算对象能力的一部分：

```js
function isObject(value) {
  return value !== null &&
    (typeof value === 'object' || typeof value === 'function');
}
```

### 数组使用 `Array.isArray`

```js
Array.isArray([]);            // true
Array.isArray({ length: 0 }); // false
```

这比 `value instanceof Array` 更准确，也更适合跨 iframe 等不同运行上下文。

### `instanceof` 回答的是原型关系

```js
value instanceof Constructor;
```

它默认判断 `Constructor.prototype` 是否位于 `value` 的原型链上。它适合判断某个类或构造函数的实例，但不要把它误解为值内容检测。

### `Object.prototype.toString.call` 提供类型标签

```js
Object.prototype.toString.call([]);         // "[object Array]"
Object.prototype.toString.call(new Date()); // "[object Date]"
Object.prototype.toString.call(new Map());  // "[object Map]"
```

常见封装：

```js
function getType(value) {
  return Object.prototype.toString.call(value).slice(8, -1);
}
```

但该标签可以被 `Symbol.toStringTag` 修改，所以它适合常规判断和调试，不是不可伪造的安全证明。

### 鸭子类型关注能力

如果代码只需要对象可迭代，不必关心它由哪个构造函数创建：

```js
function isIterable(value) {
  return value != null &&
    typeof value[Symbol.iterator] === 'function';
}
```

这种“能像鸭子一样行动，就把它当鸭子使用”的思想可以降低对具体类的耦合。

## 6.2 对象相等为什么不比较内容

```js
({}) === ({}); // false
[] === []; // false
```

每个字面量都创建了新的对象身份。`===` 比较的是两侧是否引用同一个对象，而不是属性内容是否相同。

```js
const a = { x: 1 };
const b = a;

a === b; // true
```

当两侧都是对象时，`==` 也不会进行深比较：

```js
({ x: 1 }) == ({ x: 1 }); // false
```

只有对象与基本类型进行宽松比较时，才可能先触发对象到基本类型的转换。

## 6.3 `===`、`Object.is` 和 SameValueZero

大多数值使用 `===` 即可。`Object.is` 与它的主要差别只有两个：

```js
NaN === NaN;         // false
Object.is(NaN, NaN); // true

0 === -0;            // true
Object.is(0, -0);    // false
```

Map、Set 和 `includes` 使用 SameValueZero，可以理解为：

```text
类似严格相等
+ NaN 等于自身
+ 不区分 +0 和 -0
```

```js
[NaN].includes(NaN);       // true
new Set([NaN, NaN]).size;  // 1
new Set([0, -0]).size;     // 1
```

这三个概念不需要背规范算法全文，记住使用场景和两个特殊值即可。

## 6.4 深度相等为什么没有唯一实现

两个对象内容是否相等，需要先回答：

- 是否比较原型？
- 是否包含 Symbol 和不可枚举属性？
- Date、RegExp、Map、Set 怎么比较？
- 函数按引用还是源码？
- 是否支持循环引用？
- `+0` 和 `-0` 是否视为相等？

所以 deep equal 不是语言内置的一条自然规则，而是一组业务约定。

一个适合面试展示递归思想的基础版：

```js
function deepEqual(a, b) {
  if (Object.is(a, b)) return true;

  if (
    a === null ||
    b === null ||
    typeof a !== 'object' ||
    typeof b !== 'object'
  ) {
    return false;
  }

  if (Array.isArray(a) !== Array.isArray(b)) {
    return false;
  }

  const keysA = Reflect.ownKeys(a);
  const keysB = Reflect.ownKeys(b);

  if (keysA.length !== keysB.length) return false;

  return keysA.every((key) =>
    Object.hasOwn(b, key) && deepEqual(a[key], b[key]),
  );
}
```

然后主动说明边界：它没有处理循环引用和 Date、Map、Set 等特殊对象。面试官要求时，可以像深拷贝一样加入对象对缓存和特殊类型分支。

不能把下面的写法当通用深比较：

```js
JSON.stringify(a) === JSON.stringify(b);
```

因为属性顺序可能不同，JSON 还会丢失特殊值、无法处理循环引用。

## 6.5 对象为什么需要转换为基本类型

对象不能直接完成普通的数字加法或字符串拼接。当对象参与相关运算时，引擎先执行抽象操作 `ToPrimitive`：

```text
对象
  ↓ ToPrimitive
字符串、数字等基本类型
  ↓
继续完成运算或宽松比较
```

```js
const obj = {
  valueOf() {
    return 10;
  },
};

obj + 1; // 11
```

## 6.6 ToPrimitive 的调用顺序

第一优先级是 `Symbol.toPrimitive`：

```js
const obj = {
  [Symbol.toPrimitive](hint) {
    if (hint === 'number') return 10;
    if (hint === 'string') return 'ten';
    return 'default';
  },
};

Number(obj); // 10
String(obj); // "ten"
obj + '';    // "default"
```

没有该方法时，根据 hint 决定尝试顺序：

```text
number hint：valueOf → toString
string hint：toString → valueOf
default hint：普通对象通常类似 number hint
```

每个方法只有返回基本类型才算成功；返回对象就继续尝试下一个方法。

```js
const obj = {
  valueOf() {
    return {}; // 不是基本类型，继续
  },
  toString() {
    return '42';
  },
};

Number(obj); // 42
```

Date 对 default hint 是重要例外，它倾向字符串转换。因此日期的加法和减法可能呈现不同结果。

## 6.7 二元 `+` 为什么最容易出题

二元加法先把两侧转成基本类型：

```text
只要有一侧是字符串 → 字符串拼接
否则               → 数值加法
```

```js
1 + 2;    // 3
'1' + 2;  // "12"
[1] + 2;  // "12"
[] + [];  // ""
```

数组默认转换通常经过：

```text
数组 valueOf 返回数组自身
→ 仍然是对象
→ 调用数组 toString
→ 类似 join(',')
```

所以：

```js
String([]);      // ""
String([1]);     // "1"
String([1, 2]);  // "1,2"

Number([]);      // 0
Number([1]);     // 1
Number([1, 2]);  // NaN
```

## 6.8 经典题：`[] + {}`

```js
[] + {}; // "[object Object]"
```

推导：

```text
[]  → ""
{}  → "[object Object]"
一侧出现字符串
→ "" + "[object Object]"
→ "[object Object]"
```

重点不是背结果，而是能走完 ToPrimitive 和加法规则。

## 6.9 经典题：`{} + []`

结果取决于语法上下文。

作为明确表达式：

```js
({} + []); // "[object Object]"
```

对象转成 `"[object Object]"`，数组转成空字符串，然后拼接。

但如果代码出现在某些脚本或控制台的语句开头：

```js
{} + []
```

`{}` 可能被解析为空代码块，剩下 `+[]` 是一元正号，结果为 `0`。面试时应先说明解析上下文，而不是只报一个答案。

## 6.10 经典题：`[] == ![]`

```js
[] == ![]; // true
```

推导：

```text
[] 是对象，对象转布尔值永远是 true
![] → false

[] == false
false → 0
[] → "" → 0

0 == 0 → true
```

必须记住：空数组和空对象也是真值。

## 6.11 如何让 `a == 1 && a == 2 && a == 3`

每次宽松相等都可能触发对象转换，因此可以让转换结果不断变化：

```js
const a = {
  value: 0,

  [Symbol.toPrimitive]() {
    return ++this.value;
  },
};

a == 1 && a == 2 && a == 3; // true
```

它展示的是宽松比较与 ToPrimitive 的关系，不是值得在业务代码中使用的技巧。

若换成严格相等：

```js
a === 1 && a === 2 && a === 3;
```

单靠对象类型转换无法做到，因为 `===` 不执行 ToPrimitive。

## 6.12 实际代码如何选择比较方式

- 默认使用 `===`，避免隐式转换。
- 判断 `NaN` 可以用 `Number.isNaN`。
- 需要区分正负零或比较 `NaN` 时使用 `Object.is`。
- `value == null` 可以一次判断 `null` 和 `undefined`，但要确保团队认可这种有意的宽松比较。
- 比较对象内容时使用规则明确的 deep equal，而不是期待语言自动比较属性。

## 6.13 第六章面试回答

### `🔥 必会`：对象如何判断类型？

> 要先明确判断目标。typeof 适合区分基本类型和函数，但 null 也是 object，且不能细分对象；数组优先使用 Array.isArray；instanceof 默认判断构造函数的 prototype 是否在对象原型链上；需要常规内建标签时可以使用 Object.prototype.toString.call。

### `🔥 必会`：`===` 和 `Object.is` 有什么区别？

> 对对象两者都比较引用身份，不会深比较。对基本值大多数结果相同，区别是 Object.is 认为 NaN 等于自身，并区分 +0 和 -0。Map、Set 使用 SameValueZero，它认为 NaN 相等但不区分正负零。

### `🔥 必会`：对象转基本类型的顺序是什么？

> 先调用 Symbol.toPrimitive；没有时根据 hint 选择顺序，number 通常先 valueOf 再 toString，string 则相反，default 对普通对象通常类似 number。Date 对 default 是字符串倾向的特殊情况。

# 七、对象如何扩展语言行为

## 7.1 现代语法解决的是哪些对象操作

ES6+ 增加了许多对象语法，但它们主要围绕三类需求：

```text
从对象中取值：解构、可选链、空值合并
创建新对象：属性简写、计算属性、对象展开
在对象与键值序列之间转换：entries、fromEntries、groupBy
```

### 解构是按属性名取值

```js
const user = {
  name: 'Alice',
  profile: { city: 'Shanghai' },
};

const {
  name: userName,
  age = 18,
  profile: { city },
} = user;
```

这里包含：

- `name: userName`：重命名变量。
- `age = 18`：值为 `undefined` 时使用默认值。
- `profile: { city }`：嵌套解构。

默认值不会替换 `null`：

```js
const { value = 1 } = { value: null };
value; // null
```

对象剩余语法收集没有被取出的可枚举自身属性，并创建浅拷贝：

```js
const { password, ...safeUser } = user;
```

### 可选链解决“中间值可能不存在”

```js
user.profile?.address?.city;
user.getName?.();
user.settings?.[dynamicKey];
```

它只在左侧为 `null` 或 `undefined` 时短路，不会把 `0`、空字符串和 `false` 当作缺失。

### 空值合并解决“默认值不能误伤假值”

```js
const count1 = input || 10;
const count2 = input ?? 10;
```

当 `input` 是 `0` 时：

```js
0 || 10; // 10
0 ?? 10; // 0
```

`||` 在任何假值时回退，`??` 只在 `null` 或 `undefined` 时回退。处理配置默认值时，`??` 通常更准确。

### `fromEntries` 是键值序列到对象的桥梁

```js
const entries = [
  ['name', 'Alice'],
  ['age', 20],
];

Object.fromEntries(entries);
// { name: "Alice", age: 20 }
```

常与 `Object.entries` 组成对象转换管道：

```js
const cleaned = Object.fromEntries(
  Object.entries(user).filter(([, value]) => value !== undefined),
);
```

`Object.groupBy` 也是同类思想：遍历输入，根据回调返回的属性键把元素放入不同数组。知道用途即可，面试重点通常不在背它的边界行为。

## 7.2 普通对象为什么不能替代所有键值集合

普通对象很适合表示一条结构固定的记录：

```js
const user = {
  id: 1,
  name: 'Alice',
};
```

但把它当动态字典会遇到限制：

- 键只能是字符串或 Symbol。
- 普通对象存在原型继承属性。
- 取得数量和完整迭代需要额外操作。
- 高频动态增删不是它最清晰的语义。

`Map` 就是为动态键值映射设计的：

```js
const userKey = { id: 1 };
const map = new Map();

map.set(userKey, 'metadata');
map.set(1, 'number key');
map.set('1', 'string key');

map.get(userKey); // "metadata"
map.size;         // 3
```

数字 `1` 和字符串 `'1'` 是不同键，对象键也保留身份。

## 7.3 Map 和普通对象如何选择

| 场景 | 更合适的结构 |
|------|--------------|
| 表示用户、配置等固定字段记录 | 普通对象 |
| 需要直接 JSON 序列化 | 普通对象 |
| 键可能是对象或任意类型 | Map |
| 频繁动态增删和遍历 | Map |
| 需要原生 `size` | Map |
| 简单字符串字典 | Map 或 `Object.create(null)` |

不要绝对地说 Map 一定比对象快。性能取决于访问模式和引擎，选择时首先考虑数据语义。

Map 按插入顺序迭代：

```js
for (const [key, value] of map) {
  console.log(key, value);
}
```

对象键按身份判断，因此下面取不到值：

```js
const map = new Map();
map.set({ id: 1 }, 'Alice');

map.get({ id: 1 }); // undefined
```

两个对象内容相同，但不是同一个对象身份。

## 7.4 Set 是只有键、没有额外值的集合

Set 保存不重复的值：

```js
const set = new Set([1, 1, 2, NaN, NaN]);

[...set]; // [1, 2, NaN]
```

因此经常用于基本值数组去重：

```js
const unique = [...new Set(array)];
```

但对象仍按身份去重：

```js
new Set([{ id: 1 }, { id: 1 }]).size; // 2
```

如果要按 `id` 去重，先定义业务规则：

```js
const uniqueUsers = [
  ...new Map(users.map((user) => [user.id, user])).values(),
];
```

Set 和 Map 都使用 SameValueZero，所以 `NaN` 可以匹配自身，`+0` 与 `-0` 被视为同一个值。

## 7.5 WeakMap 为什么必须弱引用键

普通 Map 会强引用键：

```js
const cache = new Map();
let user = { id: 1 };

cache.set(user, 'data');
user = null;
```

虽然变量 `user` 不再指向原对象，但 Map 仍持有它作为键，因此对象还不能被回收。

WeakMap 不会仅仅因为对象被用作键，就阻止该对象被垃圾回收：

```js
const cache = new WeakMap();
let user = { id: 1 };

cache.set(user, 'data');
user = null;

// 如果没有其他强引用，原 user 对象未来可以被回收
```

这决定了 WeakMap 的典型用途：

- 为对象关联私有或附加数据。
- 缓存以对象为输入的计算结果。
- 关联 DOM 节点和状态。
- 深拷贝中记录源对象到克隆对象的映射。

WeakMap 不可遍历，也没有 `size`。原因不是 API 忘了设计，而是垃圾回收时机不确定；如果允许遍历，程序观察到的键集合会受到 GC 时机影响。

```js
const privateData = new WeakMap();

class Counter {
  constructor() {
    privateData.set(this, { count: 0 });
  }

  increment() {
    privateData.get(this).count += 1;
  }

  get value() {
    return privateData.get(this).count;
  }
}
```

WeakSet 同理，只记录某个对象是否出现过，常用于循环检测。

## 7.6 Symbol 不只是“唯一属性名”

每次调用 `Symbol` 都创建不同的基本值：

```js
const a = Symbol('id');
const b = Symbol('id');

a === b; // false
```

作为属性键时，它可以避免与普通字符串键意外冲突：

```js
const id = Symbol('id');

const user = {
  name: 'Alice',
  [id]: 1001,
};
```

Symbol 属性不会出现在 `Object.keys` 和 `for...in` 中，但能被反射 API 找到：

```js
Object.getOwnPropertySymbols(user); // [Symbol(id)]
Reflect.ownKeys(user);              // ["name", Symbol(id)]
```

所以 Symbol 不是私有属性，只是降低命名冲突和普通枚举干扰。

`Symbol.for` 则从全局注册表复用同一个 Symbol：

```js
Symbol.for('app.id') === Symbol.for('app.id'); // true
```

## 7.7 内置 Symbol 是对象接入语言机制的接口

普通 Symbol 解决属性键冲突，内置 Symbol 则定义语言协议：

| 协议 | 控制的语言行为 |
|------|----------------|
| `Symbol.iterator` | `for...of`、展开和解构如何取值 |
| `Symbol.toPrimitive` | 对象如何转换为基本类型 |
| `Symbol.hasInstance` | `instanceof` 如何判断 |
| `Symbol.toStringTag` | `Object.prototype.toString` 显示什么标签 |

它们不是四个孤立 API，而是同一种设计：对象通过约定的 Symbol 属性参与语言内部操作。

### 用 `Symbol.iterator` 让对象可迭代

```js
const range = {
  from: 1,
  to: 3,

  *[Symbol.iterator]() {
    for (let value = this.from; value <= this.to; value += 1) {
      yield value;
    }
  },
};

[...range]; // [1, 2, 3]

for (const value of range) {
  console.log(value);
}
```

这也解释了为什么普通对象不能直接 `for...of`：它默认没有 `Symbol.iterator`。

### 自定义 `instanceof`

```js
class EvenNumber {
  static [Symbol.hasInstance](value) {
    return typeof value === 'number' && value % 2 === 0;
  }
}

2 instanceof EvenNumber; // true
```

因此，原型链查找是 `instanceof` 的默认行为，但可以被协议改写。

### 自定义类型标签

```js
const collection = {
  [Symbol.toStringTag]: 'UserCollection',
};

Object.prototype.toString.call(collection);
// "[object UserCollection]"
```

这说明 `toString.call` 的标签也不是完全不可伪造。

## 7.8 Proxy 拦截的是对象内部操作

访问对象属性时，引擎会执行类似 `[[Get]]` 的内部操作；赋值会执行类似 `[[Set]]` 的内部操作。Proxy 允许我们拦截这些操作：

```js
const target = { count: 0 };

const proxy = new Proxy(target, {
  get(target, key, receiver) {
    console.log('读取', key);
    return Reflect.get(target, key, receiver);
  },

  set(target, key, value, receiver) {
    console.log('修改', key, value);
    return Reflect.set(target, key, value, receiver);
  },
});

proxy.count;
proxy.count = 1;
```

核心结构是：

```text
外部操作 proxy.x
  ↓
Proxy trap 拦截
  ↓
执行附加逻辑
  ↓
Reflect 执行原本的标准操作
```

## 7.9 为什么 Proxy 经常配合 Reflect

Reflect 把对象内部操作以函数形式暴露：

```js
Reflect.get(target, key, receiver);
Reflect.set(target, key, value, receiver);
Reflect.has(target, key);
Reflect.deleteProperty(target, key);
Reflect.ownKeys(target);
```

它与 Proxy trap 的命名和语义相互对应，适合在完成拦截逻辑后恢复默认行为。

`receiver` 尤其重要：它代表最初发起访问的对象，可以让 getter 中的 `this` 保持正确。

```js
const target = {
  get name() {
    return this._name;
  },
};

const proxy = new Proxy(target, {
  get(target, key, receiver) {
    return Reflect.get(target, key, receiver);
  },
});

const child = Object.create(proxy);
child._name = 'Alice';

child.name; // "Alice"
```

## 7.10 Proxy 比 `defineProperty` 多解决了什么

`defineProperty` 可以控制某个已有属性的读取和写入；Proxy 位于整个对象操作入口，可以拦截更多行为：

- 读取和写入属性。
- 添加新属性。
- 删除属性。
- `in` 判断。
- 获取自身键。
- 函数调用和构造等。

面试不必逐个背完 13 个 trap。应当能说出常用的：

| 操作 | trap |
|------|------|
| `proxy.x` | `get` |
| `proxy.x = 1` | `set` |
| `'x' in proxy` | `has` |
| `delete proxy.x` | `deleteProperty` |
| 取得自身键 | `ownKeys` |
| 调用代理函数 | `apply` |
| `new` 代理函数 | `construct` |

Proxy 返回新对象，因此 `proxy !== target`。如果外部仍然持有原始 target，也可以绕过代理直接操作。

## 7.11 Vue 3 响应式为什么使用 Proxy

响应式系统需要建立下面的因果关系：

```text
执行视图副作用
  ↓
读取 state.count
  ↓ get trap
记录“这个副作用依赖 count”

修改 state.count
  ↓ set trap
找到依赖 count 的副作用
  ↓
重新执行
```

概念版实现：

```js
let activeEffect;
const dependencies = new WeakMap();

function track(target, key) {
  if (!activeEffect) return;

  let depsMap = dependencies.get(target);
  if (!depsMap) {
    depsMap = new Map();
    dependencies.set(target, depsMap);
  }

  let effects = depsMap.get(key);
  if (!effects) {
    effects = new Set();
    depsMap.set(key, effects);
  }

  effects.add(activeEffect);
}

function trigger(target, key) {
  dependencies.get(target)?.get(key)?.forEach((effect) => effect());
}

function reactive(target) {
  return new Proxy(target, {
    get(target, key, receiver) {
      track(target, key);
      return Reflect.get(target, key, receiver);
    },

    set(target, key, value, receiver) {
      const oldValue = target[key];
      const success = Reflect.set(target, key, value, receiver);

      if (success && !Object.is(oldValue, value)) {
        trigger(target, key);
      }

      return success;
    },
  });
}

function effect(fn) {
  activeEffect = fn;
  fn();
  activeEffect = undefined;
}
```

真实 Vue 还需要处理嵌套代理、依赖清理、调度、数组和集合等问题。面试回答重点是：

```text
get 时 track
set/delete 时 trigger
WeakMap 以目标对象组织依赖
Proxy 能自然观察新增、删除和集合操作
```

## 7.12 第七章面试回答

### `🔥 必会`：Map 和普通对象有什么区别？

> 普通对象适合表示固定字段记录，属性键只能是字符串或 Symbol；Map 更适合动态键值映射，键可以是任意值，原生提供 size 并按插入顺序迭代。选择时应先看数据语义，而不是绝对比较性能。

### `🔥 必会`：WeakMap 为什么不可遍历？

> WeakMap 不会因为对象被用作键就阻止它被回收，而垃圾回收时机是不确定的。如果允许遍历，程序观察到的键集合会随 GC 时机变化，所以 WeakMap 只提供按已知键进行 get、set、has、delete 的能力。

### `⭐ 追问`：Symbol 属性是私有的吗？

> 不是。它不会被 Object.keys 和 for...in 枚举，但仍可以通过 getOwnPropertySymbols 或 Reflect.ownKeys 获取。它主要用于避免命名冲突和定义语言协议。

### `🔥 必会`：Proxy 和 Reflect 为什么配合使用？

> Proxy trap 拦截对象内部操作，Reflect 提供对应的标准操作函数，便于执行附加逻辑后恢复默认行为。Reflect.get 和 set 还能传 receiver，从而保持 getter、setter 和继承场景中的 this 语义。

- [ ] 能从垃圾回收的不确定性解释 WeakMap 不可遍历。
- [ ] 能把内置 Symbol 解释为语言协议，而不是冷门 API。
- [ ] 能画出 Proxy 拦截与 Reflect 转发的流程。

# 八、对象如何离开和退出程序

## 8.1 对象生命周期的最后两个问题

对象在程序内通过引用相互连接。到了生命周期末尾，会遇到两个不同问题：

```text
要把对象发送或保存到程序外
→ 序列化

对象已经不再需要
→ 失去可达性，等待垃圾回收
```

序列化关注“如何把对象表示成可传输数据”；垃圾回收关注“程序还能不能访问这个对象”。

## 8.2 JSON 为什么不能完整表示 JavaScript 对象

JSON 能表达的数据只有：

- 对象和数组。
- 字符串、有限数字、布尔值和 `null`。

JavaScript 对象拥有更多能力：函数、Symbol、原型、属性描述符、循环引用和各种内置类型。把对象转成 JSON 时，这些内容无法直接表达。

```js
const json = JSON.stringify({
  name: 'Alice',
  age: 20,
});

const value = JSON.parse(json);
```

JSON 往返得到的是数据结构副本，不是原对象身份，也不会保留原型和属性描述符。

## 8.3 `JSON.stringify` 的核心规则

最值得掌握的是下面几组变化：

### 对象属性中的特殊值会消失

```js
JSON.stringify({
  value: undefined,
  fn() {},
  symbol: Symbol('x'),
  valid: 1,
});
// '{"valid":1}'
```

### 数组为了保留位置，会把它们变成 `null`

```js
JSON.stringify([undefined, function () {}, Symbol('x')]);
// '[null,null,null]'
```

### 非有限数字变成 `null`

```js
JSON.stringify({
  nan: NaN,
  infinity: Infinity,
});
// '{"nan":null,"infinity":null}'
```

### Date 先执行 `toJSON`

```js
JSON.stringify({
  createdAt: new Date('2020-01-01T00:00:00Z'),
});
// '{"createdAt":"2020-01-01T00:00:00.000Z"}'
```

解析回来只是字符串，不会自动恢复成 Date。

### Map、Set 默认没有可序列化的普通属性

```js
JSON.stringify(new Map([['x', 1]])); // '{}'
JSON.stringify(new Set([1, 2]));     // '{}'
```

### BigInt 和循环引用默认抛错

```js
// JSON.stringify({ id: 1n }); // TypeError

const obj = {};
obj.self = obj;
// JSON.stringify(obj); // TypeError
```

把这些规则串起来就能理解：JSON 只处理它能表达的可枚举自身字符串属性，而不是复制完整 JavaScript 对象。

## 8.4 `toJSON`、replacer 和 reviver 分别位于哪里

序列化和解析可以看成两条管道：

```text
对象
→ 对象自己的 toJSON
→ stringify 的 replacer
→ JSON 字符串

JSON 字符串
→ parse
→ reviver 自底向上转换
→ JavaScript 值
```

### `toJSON`：对象决定自己如何输出

```js
const user = {
  name: 'Alice',
  password: 'secret',

  toJSON() {
    return { name: this.name };
  },
};

JSON.stringify(user);
// '{"name":"Alice"}'
```

### replacer：序列化过程统一转换

```js
const json = JSON.stringify(
  { id: 1n, password: 'secret' },
  (key, value) => {
    if (key === 'password') return undefined;
    if (typeof value === 'bigint') return value.toString();
    return value;
  },
);
```

### reviver：解析后恢复特定类型

```js
const value = JSON.parse(
  '{"createdAt":"2020-01-01T00:00:00.000Z"}',
  (key, value) =>
    key === 'createdAt' ? new Date(value) : value,
);
```

复杂系统不要只凭字符串长相猜类型。更可靠的做法是设计明确的类型标记协议，例如：

```json
{
  "$type": "BigInt",
  "value": "123"
}
```

## 8.5 循环对象为什么需要图序列化

普通 JSON 表示的是树结构，而循环对象是图：

```text
obj ──self──→ obj
```

简单 replacer 可以把重复对象替换成 `"[Circular]"`，适合日志，但无法还原原始关系。

如果要求可逆，需要为对象分配 id，并用引用标记表示边：

```json
{
  "$id": 1,
  "name": "root",
  "self": { "$ref": 1 }
}
```

所以“避免 stringify 报错”和“可逆地保存对象图”是两个不同目标。

## 8.6 垃圾回收看的是可达性

现代 JavaScript 垃圾回收的核心不是“有没有互相引用”，而是“还能不能从根访问到”。

常见根包括：

- 全局对象及其属性。
- 当前调用栈中的局部变量。
- 活跃闭包捕获的变量。
- 宿主环境保存的回调和任务。

```js
let user = { name: 'Alice' };
user = null;
```

如果没有其他引用能访问原对象，它就变成不可达对象，可以在未来某次垃圾回收中被清理。

设为 `null` 只断开一个引用，不会立即触发回收，也不能清除其他地方保存的引用。

## 8.7 循环引用为什么不一定泄漏

```js
function createCycle() {
  const a = {};
  const b = {};

  a.b = b;
  b.a = a;
}

createCycle();
```

函数结束后，如果外部没有任何引用能到达 `a` 或 `b`，整个环仍然不可达，可以被现代垃圾回收器清理。

```text
错误理解：互相引用 → 一定不能回收
正确理解：从根不可达 → 即使形成环也可以回收
```

真正的泄漏是：对象已经没有业务用途，但仍然被某个长生命周期的引用保留。

## 8.8 常见内存泄漏如何产生

### 未清理的定时器

```js
const largeData = loadLargeData();

const timer = setInterval(() => {
  console.log(largeData.length);
}, 1000);
```

定时器保存回调，回调闭包保存 `largeData`。只要定时器继续存在，这些对象就仍然可达。

```js
clearInterval(timer);
```

### 未移除的事件监听器

```js
function mount(button) {
  const state = createState();
  const handleClick = () => use(state);

  button.addEventListener('click', handleClick);

  return () => {
    button.removeEventListener('click', handleClick);
  };
}
```

组件卸载时应同步清理监听器、订阅和观察器。

### 无界缓存

```js
const cache = new Map();

function remember(key, value) {
  cache.set(key, value);
}
```

如果 Map 生命周期和应用一样长，又没有容量或过期策略，它会持续强引用所有键和值。解决方案包括：

- 设置容量上限。
- 使用 LRU 或 TTL。
- 在适当时机显式删除。
- 对象键缓存可评估 WeakMap。

### 脱离 DOM 的节点

节点从 DOM 树中移除后，如果 JavaScript 变量、监听器或缓存仍引用它，它依然可达。

### 生命周期过长的闭包

闭包本身不是泄漏。只有闭包长期存活，并捕获了已经不需要的大对象时，才会造成问题。

## 8.9 WeakMap 也不能自动解决所有泄漏

WeakMap 只有在键不再被其他地方强引用时才有价值：

```js
const weakCache = new WeakMap();
const keys = [];

const key = {};
keys.push(key);
weakCache.set(key, 'value');
```

只要 `keys` 数组仍然保存 `key`，它就依然可达，WeakMap 条目不会因此自动消失。

因此排查泄漏的核心仍是寻找“谁在保持引用”，而不是机械地把 Map 换成 WeakMap。

## 8.10 如何排查内存泄漏

基本流程：

```text
1. 稳定复现操作，例如反复进入和退出页面
2. 观察垃圾回收后内存是否仍持续增长
3. 获取多次堆快照进行对比
4. 找到异常存活的对象
5. 查看 retaining path，确认是谁在引用它
6. 清理引用后重复同样流程验证
```

重点检查：定时器、事件监听器、订阅、缓存、DOM 引用和闭包。

## 8.11 “栈和堆”应该怎么回答

面试中常用简化模型：

```text
基本值直接保存
对象值通过引用访问堆中的对象
```

它有助于解释赋值和共享，但 ECMAScript 规范没有规定基本值一定在栈、对象一定在堆。现代引擎会使用寄存器、调用栈、托管堆和多种优化策略。

比较严谨的回答是：

> 栈和堆是理解对象引用的教学模型，语言层真正保证的是值与对象身份的行为，具体内存布局由引擎实现。

## 8.12 第八章面试回答

### `🔥 必会`：`JSON.stringify` 会丢失哪些值？

> JSON 只能表达对象、数组和有限的基本数据。对象属性中的 undefined、函数和 Symbol 会被忽略，数组中的这些值变成 null；NaN 和 Infinity 变成 null；Date 变成字符串；Map、Set 默认变成空对象；BigInt 和循环引用默认抛错。

### `⭐ 追问`：replacer 和 reviver 有什么作用？

> replacer 在 stringify 过程中负责过滤或转换值，reviver 在 parse 后自底向上转换值，常用于恢复 Date、BigInt、Map 等自定义协议。复杂类型最好使用显式类型标记，避免误判普通字符串。

### `🔥 必会`：循环引用一定造成内存泄漏吗？

> 不一定。现代垃圾回收看可达性，只要整个循环从根对象不可达，就可以被回收。真正的泄漏是已经无用的对象仍被定时器、监听器、缓存、闭包等长生命周期引用保留。

- [ ] 能从可达性解释循环引用为什么不一定泄漏。

```text
2. 再说明属性描述符如何控制读写、枚举和删除
3. 读取时沿原型链查找，赋值时关注 setter、writable 和遮蔽
4. new 负责创建实例、连接 prototype 并绑定 this
5. 对象变量共享的是对象引用，浅拷贝只切断第一层
6. 对象比较身份；参与运算时先执行 ToPrimitive
7. Map 扩展键类型，WeakMap 提供弱对象关联
8. Symbol 定义语言协议，Proxy 拦截对象内部操作
9. JSON 只能表示部分数据，GC 则根据可达性回收对象
```
