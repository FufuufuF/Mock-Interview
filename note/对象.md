# JavaScript 对象专题 — 完整面试笔记

## 一句话总结

JavaScript 对象本质上是“属性键到属性描述符的集合”，并通过内部的 `[[Prototype]]` 链接其他对象。掌握对象专题，关键是理解属性描述符、原型链、拷贝与相等、类型转换、集合类型、代理以及序列化，而不只是会写 `{}`。

# 一、对象基础与创建

## 1.1 什么是对象

对象是引用类型，是一组属性的集合。每个属性都由属性键和属性描述符组成：

- 属性键只能是字符串或 `Symbol`。
- 数据属性通过 `value` 保存值。
- 访问器属性通过 `get`、`set` 控制读写。
- 对象还拥有 `[[Prototype]]` 等内部槽，它们不能像普通属性一样直接访问。

```js
const user = {
  name: 'Alice',
  age: 20,
  sayHi() {
    return `Hi, ${this.name}`;
  },
};
```

数组、函数、日期、正则、Map 等都属于对象；函数是额外具备 `[[Call]]` 内部方法的可调用对象。

## 1.2 对象的创建方式

### 1.2.1 对象字面量

最常用、最直观，适合直接创建单个对象。

```js
const person = {
  name: 'Alice',
  age: 20,
};
```

字面量创建的普通对象，其原型通常是 `Object.prototype`。

```js
Object.getPrototypeOf(person) === Object.prototype; // true
```

### 1.2.2 `new Object()`

```js
const obj1 = new Object();
const obj2 = new Object({ x: 1 });

obj1; // {}
obj2; // { x: 1 }，传入对象时直接返回该对象
```

`Object` 作为函数调用与使用 `new` 调用，通常效果相同：

```js
Object() instanceof Object;     // true
new Object() instanceof Object; // true
```

但 `Object(value)` 会根据参数转换或直接返回对象，不一定创建新的普通对象：

```js
const source = { x: 1 };

Object(source) === source; // true
Object(1);                 // Number 包装对象
Object(null);              // 新的空对象
```

### 1.2.3 `Object.create()`

创建一个新对象，并显式指定它的原型。

```js
const animal = {
  speak() {
    return 'sound';
  },
};

const dog = Object.create(animal);
dog.name = 'Lucky';

dog.speak(); // "sound"
Object.getPrototypeOf(dog) === animal; // true
```

第二个参数可以直接定义属性描述符：

```js
const account = Object.create(null, {
  id: {
    value: 1,
    writable: false,
    enumerable: true,
    configurable: false,
  },
});
```

### 1.2.4 工厂函数

工厂函数是返回对象的普通函数，不需要配合 `new`。

```js
function createUser(name, age) {
  return {
    name,
    age,
    introduce() {
      return `${name}, ${age}`;
    },
  };
}

const user1 = createUser('Alice', 20);
const user2 = createUser('Bob', 22);
```

优点：简单、灵活，可以通过闭包保存私有状态。
缺点：若每次都创建相同方法，会产生多个函数实例；也不天然体现原型关系。

### 1.2.5 构造函数

构造函数本质上是普通函数，约定首字母大写，通过 `new` 调用。

```js
function User(name, age) {
  this.name = name;
  this.age = age;
}

User.prototype.introduce = function () {
  return `${this.name}, ${this.age}`;
};

const user = new User('Alice', 20);
```

执行 `new User(...)` 时，引擎大致会：

1. 创建一个新对象。
2. 将新对象的 `[[Prototype]]` 指向 `User.prototype`。
3. 以新对象作为 `this` 调用 `User`。
4. 若构造函数显式返回对象，则返回该对象；否则返回新对象。

近似手写：

```js
function myNew(Constructor, ...args) {
  const instance = Object.create(Constructor.prototype);
  const result = Constructor.apply(instance, args);

  return result !== null &&
    (typeof result === 'object' || typeof result === 'function')
    ? result
    : instance;
}
```

### 1.2.6 `class`

`class` 是基于原型机制的语法封装，并不是另一套继承模型。

```js
class User {
  constructor(name, age) {
    this.name = name;
    this.age = age;
  }

  introduce() {
    return `${this.name}, ${this.age}`;
  }
}

const user = new User('Alice', 20);
```

类方法定义在 `User.prototype` 上，而且默认不可枚举；类必须使用 `new` 调用，类体默认运行在严格模式下。

## 1.3 属性名的类型：字符串与 Symbol

对象的属性键只有两类：字符串和 `Symbol`。数字、布尔值等作为属性名时，会被转换为字符串。

```js
const obj = {};

obj[1] = 'number key';
obj[true] = 'boolean key';

obj['1'];    // "number key"
obj['true']; // "boolean key"
```

不同对象作为普通对象的键时，也会先被转成字符串，容易冲突：

```js
const key1 = {};
const key2 = {};
const obj = {};

obj[key1] = 1; // 实际键通常是 "[object Object]"
obj[key2] = 2; // 覆盖前一个值
```

需要以任意值作为键时，应使用 `Map`。需要避免属性名冲突时，可以使用 `Symbol`：

```js
const id = Symbol('id');
const user = {
  [id]: 1001,
  name: 'Alice',
};
```

## 1.4 计算属性名

对象字面量中的方括号允许使用表达式动态计算属性名。

```js
const field = 'name';
const prefix = 'user';

const obj = {
  [field]: 'Alice',
  [`${prefix}Id`]: 1001,
  [1 + 1]: 'two',
};

obj.name;   // "Alice"
obj.userId; // 1001
obj[2];     // "two"
```

计算结果如果不是 `Symbol`，最终会被转换成字符串属性键。

## 1.5 属性简写与方法简写

当变量名与属性名相同，可以使用属性简写：

```js
const name = 'Alice';
const age = 20;

const user = { name, age };
// 等价于 { name: name, age: age }
```

方法简写：

```js
const user = {
  name: 'Alice',
  sayHi() {
    return `Hi, ${this.name}`;
  },
};
```

方法简写与函数属性大多数时候使用方式相同，但并非完全等价。简写方法拥有 `[[HomeObject]]`，因此可以在方法中使用 `super`；简写方法也不能作为构造函数被 `new` 调用。

```js
const parent = { value: 1 };
const child = {
  __proto__: parent,
  value: 2,
  getParentValue() {
    return super.value;
  },
};

child.getParentValue(); // 1
```

## 1.6 对象字面量与 `new Object()` 的区别

| 维度 | 对象字面量 `{}` | `new Object()` |
|------|-----------------|----------------|
| 可读性 | 简洁，意图明确 | 冗长 |
| 动态参数 | 无 | 会根据传入值产生不同结果 |
| 原型 | 通常是 `Object.prototype` | 无参时相同 |
| 性能 | 通常更利于引擎直接优化 | 通常没有优势 |
| 推荐程度 | 推荐 | 除特殊转换场景外不推荐 |

不要把两者的微小性能差异当作核心依据；现代引擎会做大量优化。实际开发优先选择对象字面量，主要原因是语义清晰、代码短且不容易受到 `Object` 标识符被遮蔽的影响。

```js
function demo(Object) {
  const a = {};           // 始终创建普通对象字面量
  const b = new Object(); // 此处 Object 可能已不是内置构造函数
}
```

## 1.7 本章易错点

1. 属性键不是“任意类型”，普通对象的键只能是字符串或 `Symbol`。
2. `class` 没有抛弃原型链，它是原型机制的高级语法。
3. `new Object(existingObject)` 不会克隆对象，而是返回原对象。
4. 工厂函数不必使用 `new`，构造函数通常必须使用 `new`。
5. 方法简写与 `key: function () {}` 存在 `super`、可构造性等细节差异。

## 1.8 面试回答模板

> JavaScript 创建对象常见方式包括对象字面量、`new Object()`、`Object.create()`、工厂函数、构造函数和 `class`。日常创建普通对象优先使用字面量；需要显式指定原型时用 `Object.create()`；需要批量创建同类实例并共享方法时，可以使用构造函数或 `class`。对象属性键只能是字符串或 Symbol，其他类型会先转成字符串。`class` 本质仍然建立在构造函数和原型链之上。

# 二、属性描述符与属性操作

## 2.1 属性描述符是什么

对象属性不只是一个“键值对”。每个自身属性都对应一个属性描述符，描述符分为两类：

- 数据属性：保存一个具体值。
- 访问器属性：通过 getter/setter 计算或控制读写。

同一个属性描述符不能同时既是数据描述符又是访问器描述符。

## 2.2 数据属性的四个特性

| 特性 | 作用 | 字面量创建时默认值 | `defineProperty` 省略时 |
|------|------|--------------------|------------------------|
| `value` | 属性当前值 | `undefined` 或指定值 | `undefined` |
| `writable` | 能否通过赋值修改值 | `true` | `false` |
| `enumerable` | 能否被常规枚举方法发现 | `true` | `false` |
| `configurable` | 能否删除、重定义描述符 | `true` | `false` |

```js
const user = {};

Object.defineProperty(user, 'id', {
  value: 1001,
  writable: false,
  enumerable: true,
  configurable: false,
});

user.id = 1002; // 非严格模式静默失败；严格模式抛 TypeError
delete user.id; // 同样失败
```

`configurable: false` 的限制很强：

- 不能删除属性。
- 不能把 `configurable` 改回 `true`。
- 不能切换数据属性与访问器属性。
- 不能修改 `enumerable`。
- 数据属性若同时 `writable: false`，连 `value` 也不能再修改。
- 唯一较特殊的放宽是：当 `writable: true` 时，仍可修改 `value`，也可将 `writable` 从 `true` 改为 `false`。

## 2.3 访问器属性：getter 与 setter

访问器描述符包含：

| 特性 | 作用 |
|------|------|
| `get` | 读取属性时调用，无参数 |
| `set` | 给属性赋值时调用，接收新值 |
| `enumerable` | 是否可枚举 |
| `configurable` | 是否可重新配置或删除 |

```js
const user = {
  firstName: 'Ada',
  lastName: 'Lovelace',

  get fullName() {
    return `${this.firstName} ${this.lastName}`;
  },

  set fullName(value) {
    [this.firstName, this.lastName] = value.split(' ');
  },
};

user.fullName; // "Ada Lovelace"
user.fullName = 'Grace Hopper';
```

getter 与 setter 不是“调用方法”，而是在普通读取、赋值语法中自动触发。只有 getter 没有 setter 的属性是只读访问器；严格模式下给它赋值会抛错。

为避免 setter 递归，不要在 setter 内给同名属性赋值：

```js
const obj = {
  _value: 0,

  get value() {
    return this._value;
  },

  set value(next) {
    this._value = next; // 不能写 this.value = next
  },
};
```

## 2.4 `Object.defineProperty()`

该方法在对象上新增或修改一个自身属性，并返回原对象。

```js
const obj = {};

Object.defineProperty(obj, 'name', {
  value: 'Alice',
  writable: true,
  enumerable: true,
  configurable: true,
});
```

最常见陷阱：用 `defineProperty` 新建属性时，未显式填写的布尔特性默认都是 `false`，不同于对象字面量或普通赋值。

```js
const a = { x: 1 };
const b = {};
Object.defineProperty(b, 'x', { value: 1 });

Object.getOwnPropertyDescriptor(a, 'x');
// { value: 1, writable: true, enumerable: true, configurable: true }

Object.getOwnPropertyDescriptor(b, 'x');
// { value: 1, writable: false, enumerable: false, configurable: false }
```

## 2.5 `Object.defineProperties()`

一次定义多个属性：

```js
const product = {};

Object.defineProperties(product, {
  price: {
    value: 100,
    writable: true,
    enumerable: true,
  },
  taxPrice: {
    enumerable: true,
    get() {
      return this.price * 1.1;
    },
  },
});
```

每个属性仍然遵循 `defineProperty` 的默认规则。

## 2.6 获取属性描述符

### `Object.getOwnPropertyDescriptor()`

获取单个自身属性的描述符；原型链属性不会被查找。

```js
const obj = { x: 1 };

Object.getOwnPropertyDescriptor(obj, 'x');
// { value: 1, writable: true, enumerable: true, configurable: true }

Object.getOwnPropertyDescriptor(obj, 'toString');
// undefined，因为 toString 是继承属性
```

### `Object.getOwnPropertyDescriptors()`

获取对象全部自身属性（包括不可枚举属性和 Symbol 属性）的描述符集合。

```js
const descriptors = Object.getOwnPropertyDescriptors(obj);
```

它适合配合 `Object.create` 完整复制属性特性：

```js
function cloneWithDescriptors(source) {
  return Object.create(
    Object.getPrototypeOf(source),
    Object.getOwnPropertyDescriptors(source),
  );
}
```

这比展开语法或 `Object.assign` 更完整，因为后两者只读取可枚举自身属性的值，会丢失描述符，并可能触发 getter。

## 2.7 属性的增删改查

### 点语法与方括号语法

```js
const user = { name: 'Alice' };

user.name;       // 点语法
user['name'];    // 方括号语法

const key = 'name';
user[key];       // 动态属性只能用方括号
user['first-name']; // 非法标识符形式的键也要用方括号
```

点语法后必须是合法标识符，且不会计算变量。`user.key` 读取的就是字符串键 `"key"`。

### 新增与修改

```js
user.age = 20;
user['name'] = 'Bob';
```

赋值可能受到以下因素影响：

- 对象是否可扩展。
- 自身属性是否可写。
- 原型链上是否存在 setter。
- 原型链上是否存在不可写数据属性。
- 是否处于严格模式。

### 删除

```js
delete user.age;
```

`delete` 删除的是对象自身属性，不会删除变量，也不会直接删除原型上的属性。不可配置属性无法删除。

```js
const proto = { x: 1 };
const obj = Object.create(proto);
obj.x = 2;

delete obj.x;
obj.x; // 1，自身属性删除后，暴露出原型属性
```

删除数组元素会留下空位，不会自动缩短数组：

```js
const arr = [1, 2, 3];
delete arr[1];

arr.length; // 3
1 in arr;   // false
```

## 2.8 判断属性是否存在

### `in`

检查自身属性和原型链属性，无论属性是否可枚举。

```js
'toString' in {}; // true
```

### `hasOwnProperty()`

只检查自身属性：

```js
const obj = { x: 1 };
obj.hasOwnProperty('x');        // true
obj.hasOwnProperty('toString'); // false
```

它有两个风险：

1. 对象可能创建自 `Object.create(null)`，没有该方法。
2. 对象可能定义同名属性，覆盖该方法。

```js
const dict = Object.create(null);
dict.x = 1;
// dict.hasOwnProperty('x'); // TypeError

const tricky = {
  hasOwnProperty: () => false,
  x: 1,
};
```

传统安全写法：

```js
Object.prototype.hasOwnProperty.call(dict, 'x'); // true
```

### `Object.hasOwn()`

ES2022 提供的静态方法，只检查自身属性，并且能安全处理纯净对象和同名覆盖。

```js
Object.hasOwn(dict, 'x');   // true
Object.hasOwn({}, 'toString'); // false
```

现代代码优先使用 `Object.hasOwn()`。

### 值为 `undefined` 不代表属性不存在

```js
const obj = { x: undefined };

obj.x === undefined;     // true
Object.hasOwn(obj, 'x'); // true
'x' in obj;              // true
```

所以不能仅凭读取结果是否为 `undefined` 判断属性是否存在。

## 2.9 属性读取与赋值的原型链行为

读取 `obj.key` 时：

1. 查找对象自身属性。
2. 若没有，则沿 `[[Prototype]]` 向上查找。
3. 找到数据属性就返回其值。
4. 找到 getter 就以最初的接收者 `obj` 作为 `this` 调用 getter。
5. 到达 `null` 仍未找到则返回 `undefined`。

普通赋值通常会创建或修改自身属性，但原型链上的描述符可能介入：

```js
const proto = {};
Object.defineProperty(proto, 'x', {
  value: 1,
  writable: false,
});

const obj = Object.create(proto);
obj.x = 2; // 失败，不会创建自身 x
```

原型 setter 也会拦截赋值：

```js
const proto = {
  set value(next) {
    this._value = next;
  },
};

const obj = Object.create(proto);
obj.value = 10;
obj._value; // 10
```

## 2.10 本章易错点

1. `defineProperty` 未填写的布尔配置默认是 `false`。
2. `enumerable: false` 只表示不参与常规枚举，不表示属性无法读取。
3. `configurable: false` 并不必然意味着值绝对不能改，还要看 `writable`。
4. `in` 会检查原型链，`Object.hasOwn()` 只检查自身。
5. `delete` 删除自身属性后，可能露出同名原型属性。
6. 属性值为 `undefined` 与属性不存在是两件事。

## 2.11 面试回答模板

> JavaScript 属性由描述符控制。数据属性有 value、writable、enumerable、configurable，访问器属性有 get、set、enumerable、configurable。普通字面量属性的三个布尔特性默认是 true，而通过 `Object.defineProperty` 新建属性时默认是 false。判断属性时，`in` 会查原型链，`Object.hasOwn` 只查自身；现代代码更推荐 `Object.hasOwn`，因为它不依赖对象继承 `hasOwnProperty`，也不怕同名覆盖。

# 三、对象的遍历与枚举

## 3.1 先分清三个维度

选择遍历 API 时，需要先判断：

1. 查自身属性，还是连原型链属性一起查？
2. 只查可枚举属性，还是也包含不可枚举属性？
3. 只查字符串键，还是也包含 Symbol 键？

## 3.2 各方法覆盖范围总表

| 方法 | 自身 | 原型链 | 可枚举 | 不可枚举 | 字符串键 | Symbol 键 |
|------|------|--------|--------|----------|----------|-----------|
| `for...in` | 是 | 是 | 是 | 否 | 是 | 否 |
| `Object.keys()` | 是 | 否 | 是 | 否 | 是 | 否 |
| `Object.values()` | 是 | 否 | 是 | 否 | 对应值 | 不含 |
| `Object.entries()` | 是 | 否 | 是 | 否 | 键值对 | 不含 |
| `Object.getOwnPropertyNames()` | 是 | 否 | 是 | 是 | 是 | 否 |
| `Object.getOwnPropertySymbols()` | 是 | 否 | 是 | 是 | 否 | 是 |
| `Reflect.ownKeys()` | 是 | 否 | 是 | 是 | 是 | 是 |
| `Object.getOwnPropertyDescriptors()` | 是 | 否 | 是 | 是 | 是 | 是 |

## 3.3 `for...in`

遍历对象自身及原型链上的可枚举字符串属性，不包含 Symbol。

```js
const proto = { inherited: 1 };
const obj = Object.create(proto);
obj.own = 2;

for (const key in obj) {
  console.log(key); // own、inherited
}
```

只处理自身属性时，应配合 `Object.hasOwn()`：

```js
for (const key in obj) {
  if (Object.hasOwn(obj, key)) {
    console.log(key, obj[key]);
  }
}
```

不要用 `for...in` 遍历数组：它返回字符串索引，可能包含额外属性和继承属性，而且不保证适合数组语义。数组优先使用 `for...of`、数组迭代方法或普通索引循环。

## 3.4 `Object.keys()`、`values()`、`entries()`

它们只处理对象自身、可枚举、字符串键属性。

```js
const symbol = Symbol('id');
const user = { name: 'Alice', age: 20, [symbol]: 1001 };

Object.defineProperty(user, 'secret', {
  value: 'hidden',
  enumerable: false,
});

Object.keys(user);    // ["name", "age"]
Object.values(user);  // ["Alice", 20]
Object.entries(user); // [["name", "Alice"], ["age", 20]]
```

`Object.entries()` 常用于把对象转换为键值对后处理：

```js
const prices = { apple: 10, banana: 5 };

const doubled = Object.fromEntries(
  Object.entries(prices).map(([key, value]) => [key, value * 2]),
);
// { apple: 20, banana: 10 }
```

## 3.5 `Object.getOwnPropertyNames()`

返回所有自身字符串键，包括不可枚举属性。

```js
const arr = ['a', 'b'];

Object.keys(arr);                // ["0", "1"]
Object.getOwnPropertyNames(arr); // ["0", "1", "length"]
```

数组的 `length` 是不可枚举自身属性，因此只会出现在更完整的查询中。

## 3.6 `Object.getOwnPropertySymbols()`

返回所有自身 Symbol 键，不区分是否可枚举。

```js
const publicId = Symbol('publicId');
const hiddenId = Symbol('hiddenId');
const obj = { [publicId]: 1 };

Object.defineProperty(obj, hiddenId, {
  value: 2,
  enumerable: false,
});

Object.getOwnPropertySymbols(obj); // [publicId, hiddenId]
```

## 3.7 `Reflect.ownKeys()`

返回对象全部自身属性键，相当于：

```js
[
  ...Object.getOwnPropertyNames(obj),
  ...Object.getOwnPropertySymbols(obj),
];
```

它是最完整的自身键查询：

```js
Reflect.ownKeys(user);
// ["name", "age", "secret", Symbol(id)]
```

需要复制所有属性、编写元编程工具或 Proxy 的 `ownKeys` trap 时，经常使用它。

## 3.8 属性遍历顺序

对普通对象的自身键，现代规范中的核心顺序是：

1. 数组索引键按数值升序。
2. 其他字符串键按创建顺序。
3. Symbol 键按创建顺序。

```js
const s1 = Symbol('s1');
const s2 = Symbol('s2');
const obj = {};

obj.b = 1;
obj[10] = 2;
obj[2] = 3;
obj.a = 4;
obj[s1] = 5;
obj[s2] = 6;

Reflect.ownKeys(obj);
// ["2", "10", "b", "a", Symbol(s1), Symbol(s2)]
```

需要注意，“看起来像数字”不一定是数组索引：

```js
const obj = {
  '01': 'leading zero',
  '-1': 'negative',
  '1.5': 'decimal',
  '4294967295': 'too large for array index',
  '2': 'index',
};
```

严格说，数组索引是特定范围内、能按规范往返转换的字符串键。面试中回答“非负整数索引键升序，其他字符串按创建顺序，Symbol 按创建顺序”通常足够，但最好知道边界值并非普通数组索引。

### 删除后重新添加会怎样

非索引字符串属性删除后重新添加，会排到该组末尾：

```js
const obj = { a: 1, b: 2 };
delete obj.a;
obj.a = 3;

Object.keys(obj); // ["b", "a"]
```

只修改已有属性的值，不会改变其顺序。

### `for...in` 的顺序

现代 ECMAScript 已对 `for...in` 的枚举顺序作了更多规范化，但它还涉及原型链、重复键遮蔽和遍历期间修改对象等复杂规则。业务代码不要把关键逻辑建立在 `for...in` 的复杂原型枚举顺序上。

## 3.9 枚举性与常见操作

| 操作 | 是否处理 Symbol | 是否只处理可枚举自身属性 |
|------|-----------------|--------------------------|
| 对象展开 `{ ...obj }` | 是 | 是 |
| `Object.assign()` | 是 | 是 |
| `JSON.stringify()` | 否 | 是（且还有 JSON 规则） |
| `Object.keys()` | 否 | 是 |

对象展开和 `Object.assign` 会复制可枚举自身的字符串键与 Symbol 键，这一点与 `Object.keys()` 不完全相同。

```js
const id = Symbol('id');
const source = { visible: 1, [id]: 2 };
const copy = { ...source };

copy[id]; // 2
```

## 3.10 本章易错点

1. `for...in` 不只遍历自身属性，还会遍历原型链可枚举属性。
2. `Object.keys()` 不包含不可枚举属性和 Symbol 属性。
3. `Object.getOwnPropertyNames()` 包含不可枚举字符串属性，但不包含 Symbol。
4. `Reflect.ownKeys()` 是获取全部自身键最完整的方式。
5. 属性顺序中的第一组是数组索引键，不是所有“数字样式字符串”。
6. 对象展开会复制可枚举 Symbol 属性，而 JSON 序列化不会。

## 3.11 面试回答模板

> 对象遍历要从自身还是原型、可枚举还是全部、字符串还是 Symbol 三个维度区分。`for...in` 遍历自身和原型链的可枚举字符串属性；`Object.keys/values/entries` 只看自身可枚举字符串属性；`getOwnPropertyNames` 包含自身不可枚举字符串属性；`getOwnPropertySymbols` 获取自身 Symbol；`Reflect.ownKeys` 获取全部自身字符串和 Symbol 键。普通对象的自身键顺序通常是数组索引升序、其他字符串按创建顺序、Symbol 按创建顺序。

# 四、原型与原型链

## 4.1 `prototype`、`[[Prototype]]` 与 `__proto__`

这三个概念最容易混淆：

| 名称 | 属于谁 | 含义 |
|------|--------|------|
| `prototype` | 通常是可构造函数的普通属性 | 被 `new` 创建的实例将以它作为原型 |
| `[[Prototype]]` | 几乎所有对象的内部槽 | 当前对象继承的另一个对象或 `null` |
| `__proto__` | `Object.prototype` 上的历史访问器 | 读取或设置对象的 `[[Prototype]]` |

```js
function Person() {}
const person = new Person();

Object.getPrototypeOf(person) === Person.prototype; // true
person.__proto__ === Person.prototype;              // true，不推荐这样写
Object.getPrototypeOf(Person.prototype) === Object.prototype; // true
```

普通函数同时也是对象，因此它本身也有 `[[Prototype]]`；函数自身的 `[[Prototype]]` 与它用于实例继承的 `.prototype` 不是一回事。

```js
Object.getPrototypeOf(Person) === Function.prototype; // true
Person.prototype !== Function.prototype;              // true
```

箭头函数不可构造，通常没有用于构造实例的 `prototype` 属性：

```js
const fn = () => {};
fn.prototype; // undefined
```

## 4.2 原型链查找机制

读取属性时，引擎先查对象自身；找不到就沿 `[[Prototype]]` 向上查找，直到找到属性或遇到 `null`。

```text
person
  │ [[Prototype]]
  ▼
Person.prototype
  │ [[Prototype]]
  ▼
Object.prototype
  │ [[Prototype]]
  ▼
null
```

```js
function Person(name) {
  this.name = name;
}

Person.prototype.sayHi = function () {
  return `Hi, ${this.name}`;
};

const person = new Person('Alice');

Object.hasOwn(person, 'name');  // true
Object.hasOwn(person, 'sayHi'); // false
'sayHi' in person;              // true
person.sayHi();                 // "Hi, Alice"
```

方法虽然定义在原型上，但以 `person.sayHi()` 调用时，`this` 仍由调用点决定，通常指向 `person`。

## 4.3 原型链终点

普通对象原型链最终到达 `Object.prototype`，其原型为 `null`：

```js
Object.getPrototypeOf(Object.prototype) === null; // true
```

也可以写成历史形式：

```js
Object.prototype.__proto__ === null; // true
```

推荐使用标准 API，而不是 `__proto__`。

## 4.4 `Object.getPrototypeOf()`

标准的读取原型方式：

```js
const proto = { x: 1 };
const obj = Object.create(proto);

Object.getPrototypeOf(obj) === proto; // true
```

它比 `obj.__proto__` 更可靠，因为纯净对象可能没有 `__proto__` 访问器，对象也可能定义同名自身属性。

## 4.5 `Object.setPrototypeOf()`

动态设置现有对象的原型：

```js
const proto = { greet: () => 'hello' };
const obj = {};

Object.setPrototypeOf(obj, proto);
obj.greet(); // "hello"
```

但动态修改原型通常代价较高，会破坏引擎已有优化。若创建时就知道原型，优先使用 `Object.create(proto)`；业务建模则通常使用 `class`/`extends`。

不可扩展对象通常不能再更换成不同原型：

```js
const obj = Object.preventExtensions({});
// Object.setPrototypeOf(obj, {}); // TypeError
```

原型链也不能形成环。

## 4.6 `Object.create()` 的原理与应用

`Object.create(proto)` 创建新对象，并直接把新对象的 `[[Prototype]]` 设为 `proto`。概念上的简化实现：

```js
function create(proto) {
  function Temp() {}
  Temp.prototype = proto;
  return new Temp();
}
```

真实 `Object.create` 还允许 `proto` 为 `null`，并支持第二个属性描述符参数，因此上面只是帮助理解，不能完全替代原生实现。

常见用途：

- 创建指定原型的对象。
- 建立继承关系。
- 创建无原型字典。
- 在保留原型与描述符时克隆对象。

## 4.7 `Object.create(null)`：纯净对象

```js
const dictionary = Object.create(null);
dictionary.apple = 1;

Object.getPrototypeOf(dictionary) === null; // true
'toString' in dictionary;                   // false
```

优点：

- 没有继承属性，不担心 `toString`、`constructor` 等键冲突。
- 适合实现简单字符串键字典。
- 可降低某些原型污染相关风险。

限制：

- 没有 `hasOwnProperty`、`toString` 等方法。
- 某些默认假设普通对象原型的库可能不兼容。
- 输出与调试体验可能不同。

```js
Object.hasOwn(dictionary, 'apple'); // true
Object.prototype.toString.call(dictionary); // "[object Object]"
```

如果需要非字符串键、稳定迭代和 `size`，通常直接用 `Map` 更合适。

## 4.8 属性遮蔽（Property Shadowing）

对象自身属性与原型属性同名时，自身属性会遮蔽原型属性。

```js
const proto = { role: 'guest' };
const user = Object.create(proto);

user.role; // "guest"

user.role = 'admin';
user.role; // "admin"
proto.role; // "guest"
```

删除自身属性后，原型属性会重新可见：

```js
delete user.role;
user.role; // "guest"
```

但并非任何原型属性都能被普通赋值遮蔽：原型上存在不可写数据属性时，赋值无法创建同名自身属性；存在 setter 时则会调用 setter。

若确实需要绕开普通赋值语义，可显式定义自身属性：

```js
const proto = {};
Object.defineProperty(proto, 'x', {
  value: 1,
  writable: false,
});

const obj = Object.create(proto);
Object.defineProperty(obj, 'x', {
  value: 2,
  writable: true,
  configurable: true,
});

obj.x; // 2
```

## 4.9 `isPrototypeOf()` 与原型判断

```js
Person.prototype.isPrototypeOf(person); // true
Object.prototype.isPrototypeOf(person); // true
```

它判断某对象是否出现在另一个对象的原型链上。与 `instanceof` 相比，它直接从原型对象出发，不要求左侧是构造函数。

## 4.10 原型污染

原型污染是指不可信输入修改了共享原型，导致许多对象意外继承恶意属性。

```js
// 危险思想示例：把外部路径无校验地写入对象
// payload: { "__proto__": { "isAdmin": true } }
```

防护思路：

- 不盲目深度合并不可信对象。
- 拒绝 `__proto__`、`prototype`、`constructor` 等危险路径段。
- 字典使用 `Object.create(null)` 或 `Map`。
- 使用维护良好的合并库并及时升级。
- 权限判断只读明确的自身字段，不依赖继承属性。

## 4.11 本章易错点

1. `prototype` 是构造函数上的属性，实例继承关系使用的是内部 `[[Prototype]]`。
2. `obj.__proto__` 通常只是继承自 `Object.prototype` 的访问器，不等同于内部槽本身。
3. 函数自身的原型与 `函数.prototype` 是两条不同关系。
4. 读取原型用 `Object.getPrototypeOf`，不要依赖 `__proto__`。
5. 动态 `setPrototypeOf` 可能导致明显性能退化，应尽量在创建时确定原型。
6. 属性遮蔽不等于修改了原型属性。

## 4.12 面试回答模板

> 每个普通对象内部都有 `[[Prototype]]`，它指向另一个对象或 null。读取属性时先查自身，找不到就沿这条链向上查，普通对象最终到达 `Object.prototype`，再到 null。构造函数的 `prototype` 是普通属性，使用 new 时，新实例的 `[[Prototype]]` 会指向这个对象。`__proto__` 只是历史访问器，实际代码应使用 `Object.getPrototypeOf`、`Object.setPrototypeOf` 或创建时使用 `Object.create`。

# 五、继承

## 5.1 继承的本质

JavaScript 的对象继承建立在原型委托上：对象找不到自身属性时，会把查找委托给其原型。传统“六种继承方式”主要是在解决两个问题：

1. 如何继承父构造函数初始化的实例属性。
2. 如何共享父类型原型上的方法。

## 5.2 原型链继承

让子构造函数的原型成为父类型实例：

```js
function Parent() {
  this.colors = ['red'];
}

Parent.prototype.sayHi = function () {
  return 'hi';
};

function Child() {}

Child.prototype = new Parent();
Child.prototype.constructor = Child;

const child1 = new Child();
const child2 = new Child();

child1.colors.push('blue');
child2.colors; // ["red", "blue"]
```

优点：父原型方法可以复用，原型链关系清楚。
缺点：父构造函数中的引用类型属性被放在 `Child.prototype` 上，所有子实例共享；创建子实例时也无法方便地给父构造函数传参。

## 5.3 构造函数继承（借用构造函数）

在子构造函数中用 `call` 调用父构造函数：

```js
function Parent(name) {
  this.name = name;
  this.colors = ['red'];
}

function Child(name, age) {
  Parent.call(this, name);
  this.age = age;
}

const child1 = new Child('Alice', 10);
const child2 = new Child('Bob', 12);

child1.colors.push('blue');
child2.colors; // ["red"]
```

优点：实例属性互相独立，并且可以向父构造函数传参。
缺点：没有继承父原型上的方法；如果方法写在父构造函数内部，每个实例又会重复创建。

## 5.4 组合继承

组合原型链继承与借用构造函数：

```js
function Parent(name) {
  this.name = name;
  this.colors = ['red'];
}

Parent.prototype.sayHi = function () {
  return `Hi, ${this.name}`;
};

function Child(name, age) {
  Parent.call(this, name); // 第二次调用 Parent
  this.age = age;
}

Child.prototype = new Parent(); // 第一次调用 Parent
Child.prototype.constructor = Child;

const child = new Child('Alice', 10);
child.sayHi();
```

优点：实例属性独立、原型方法复用、可以传参。
缺点：父构造函数被调用两次，并在子原型上留下多余实例属性。

## 5.5 原型式继承

直接以已有对象作为新对象的原型，核心就是 `Object.create()`。

```js
const person = {
  name: 'default',
  friends: ['Alice'],
};

const p1 = Object.create(person);
const p2 = Object.create(person);

p1.name = 'Bob';
p1.friends.push('Carol');

p2.friends; // ["Alice", "Carol"]，原型引用属性仍共享
```

适合基于某个对象做轻量委托，不适合需要独立初始化复杂实例状态的场景。

## 5.6 寄生继承

基于某个对象创建新对象，再给新对象增强能力并返回：

```js
function createAnother(original) {
  const clone = Object.create(original);

  clone.sayHi = function () {
    return 'hi';
  };

  return clone;
}
```

“寄生”表示创建逻辑包裹在函数中，并额外增强对象。缺点是增强方法通常无法跨实例共享。

## 5.7 寄生组合式继承

传统构造函数模式下最成熟的方案：借用构造函数继承实例属性，用 `Object.create` 继承原型方法，避免执行两次父构造函数。

```js
function Parent(name) {
  this.name = name;
  this.colors = ['red'];
}

Parent.prototype.sayHi = function () {
  return `Hi, ${this.name}`;
};

function Child(name, age) {
  Parent.call(this, name);
  this.age = age;
}

Child.prototype = Object.create(Parent.prototype, {
  constructor: {
    value: Child,
    writable: true,
    configurable: true,
  },
});

Child.prototype.sayAge = function () {
  return this.age;
};

const child = new Child('Alice', 10);

child instanceof Child;  // true
child instanceof Parent; // true
child.sayHi();            // "Hi, Alice"
```

也可以抽成辅助函数：

```js
function inheritPrototype(Child, Parent) {
  Child.prototype = Object.create(Parent.prototype, {
    constructor: {
      value: Child,
      writable: true,
      configurable: true,
    },
  });
}
```

## 5.8 为什么要修复 `constructor`

覆盖 `Child.prototype` 后，新对象默认不再拥有指向 `Child` 的 `constructor`：

```js
Child.prototype = Object.create(Parent.prototype);
Child.prototype.constructor === Parent; // 可能为 true（继承查找到）
```

修复它主要是保持原型结构与反射结果合理。`constructor` 不是实例创建机制本身，`new Child()` 不依赖 `Child.prototype.constructor` 来创建实例。

直接赋值修复会创建可枚举属性：

```js
Child.prototype.constructor = Child;
```

更严谨的方式是用 `defineProperty`，让它像原生构造函数原型的 `constructor` 一样不可枚举。

## 5.9 ES6 `class + extends`

```js
class Parent {
  constructor(name) {
    this.name = name;
  }

  sayHi() {
    return `Hi, ${this.name}`;
  }

  static category() {
    return 'person';
  }
}

class Child extends Parent {
  constructor(name, age) {
    super(name);
    this.age = age;
  }

  sayHi() {
    return `${super.sayHi()}, age ${this.age}`;
  }
}

const child = new Child('Alice', 10);
```

它建立两条继承链：

```js
Object.getPrototypeOf(Child.prototype) === Parent.prototype; // true
Object.getPrototypeOf(Child) === Parent;                     // true
```

第一条让实例继承父类实例方法；第二条让子类继承父类静态方法。

`class` 相比手写原型继承还有这些语义：

- 类必须通过 `new` 调用。
- 类声明存在暂时性死区，不像函数声明那样可在声明前调用。
- 类体默认严格模式。
- 原型方法默认不可枚举。
- 派生类构造函数必须先调用 `super()`，才能使用 `this`。

## 5.10 `super` 的机制

### 构造函数中的 `super()`

派生类中，`super(...args)` 调用父类构造逻辑，并初始化 `this`。在调用之前访问 `this` 会抛错。

```js
class Child extends Parent {
  constructor(name) {
    // console.log(this); // ReferenceError
    super(name);
    console.log(this); // 可用
  }
}
```

更精确地说，派生构造函数不会像基类构造函数那样一开始就拥有已初始化的 `this`；父构造过程通过类似 `Reflect.construct` 的机制创建实例，实例实际使用派生类的原型。

### 方法中的 `super.property`

`super` 不是一个可自由保存的普通变量。它依赖方法定义时的 `[[HomeObject]]`：

```js
const parent = {
  greet() {
    return 'parent';
  },
};

const child = {
  __proto__: parent,
  greet() {
    return `${super.greet()} child`;
  },
};
```

`super.greet()` 查找的是 `child` 的原型上的 `greet`，但调用时的 `this` 仍是当前接收者。

### 静态方法中的 `super`

静态方法里的 `super` 从子类构造函数的原型，也就是父类构造函数上查找：

```js
class Parent {
  static label() {
    return 'parent';
  }
}

class Child extends Parent {
  static label() {
    return `${super.label()} child`;
  }
}
```

## 5.11 `extends` 内置对象

现代 JavaScript 可以继承 `Array`、`Error` 等内置类型：

```js
class Stack extends Array {
  top() {
    return this.at(-1);
  }
}

const stack = new Stack(1, 2, 3);
stack.top();          // 3
stack instanceof Array; // true
```

继承 `Error` 时通常要设置名称，并注意运行环境中的错误堆栈行为：

```js
class ValidationError extends Error {
  constructor(message, field) {
    super(message);
    this.name = 'ValidationError';
    this.field = field;
  }
}
```

## 5.12 组合优于继承

继承适合稳定的“is-a”关系，但层级过深会提高耦合。实际项目也常通过对象组合复用能力：

```js
const canEat = {
  eat() {
    return 'eating';
  },
};

const canWalk = {
  walk() {
    return 'walking';
  },
};

const person = Object.assign({}, canEat, canWalk);
```

面试中应掌握各种继承模式；工程设计中则要根据关系选择继承、组合或委托。

## 5.13 本章易错点

1. 原型链继承会共享父构造函数产生的引用类型属性。
2. 借用构造函数没有继承父原型方法。
3. 组合继承会调用两次父构造函数。
4. 寄生组合式继承避免重复调用，是传统方案中的最佳实践。
5. `class` 不是脱离原型的新继承系统。
6. `extends` 同时建立实例方法链和静态方法链。
7. 修复 `constructor` 是维护反射结构，不是 `new` 能运行的必要条件。

## 5.14 面试回答模板

> 传统继承方案里，原型链继承能共享方法但会共享引用属性；借用构造函数能让实例属性独立但无法继承原型方法；组合继承解决了两者问题，却调用两次父构造函数；寄生组合式继承通过 `Parent.call(this)` 初始化实例属性，再用 `Object.create(Parent.prototype)` 建立原型链，是传统模式下较完整的方案。ES6 的 `class extends` 本质仍基于原型链，但语义更严格，并且同时继承实例方法和静态方法。

# 六、对象的拷贝

## 6.1 赋值、浅拷贝与深拷贝

```js
const source = { nested: { count: 1 } };
const alias = source;
```

这只是复制引用，`alias === source`，不是拷贝。

- 浅拷贝：创建新容器，只复制第一层属性值；嵌套对象仍共享引用。
- 深拷贝：递归创建嵌套结构，使目标对象与源对象尽可能互不影响。

```js
const shallow = { ...source };

shallow !== source;                 // true
shallow.nested === source.nested;   // true
```

“深拷贝”必须先定义语义：是否保留原型、描述符、函数、不可枚举属性、WeakMap、DOM 节点等，没有一个通用实现可以完美克隆所有 JavaScript 值。

## 6.2 `Object.assign()`

把一个或多个源对象的可枚举自身属性复制到目标对象：

```js
const source = { a: 1, nested: { b: 2 } };
const copy = Object.assign({}, source);
```

特点：

- 是浅拷贝。
- 包含可枚举字符串属性与 Symbol 属性。
- 会使用 `[[Get]]` 读取源属性，可能触发 getter。
- 会使用 `[[Set]]` 写目标属性，可能触发目标 setter。
- 后面的同名属性覆盖前面的。
- 返回目标对象，并会直接修改目标对象。

```js
const merged = Object.assign({}, { a: 1 }, { a: 2, b: 3 });
// { a: 2, b: 3 }
```

## 6.3 对象展开 `{ ...obj }`

```js
const copy = { ...source };
const merged = { ...defaults, ...options };
```

它同样复制可枚举自身字符串键与 Symbol 键，也是浅拷贝。与 `Object.assign` 的重要细节差异是：对象展开把属性创建到新对象上，不会触发目标对象原型上的 setter；`Object.assign` 使用普通设置语义。

```js
const targetProto = {
  set x(value) {
    console.log('setter', value);
  },
};

const target = Object.create(targetProto);
Object.assign(target, { x: 1 }); // 触发 setter

const spread = { ...target, x: 1 }; // 创建自身数据属性
```

两者都会读取源值，所以源 getter 仍可能执行，并且最终复制的是 getter 返回值，而不是 getter 描述符。

## 6.4 数组浅拷贝

```js
const arr = [{ x: 1 }, 2, 3];

const a = [...arr];
const b = Array.from(arr);
const c = arr.slice();

a[0] === arr[0]; // true
```

`Array.from()` 接收可迭代对象或类数组对象，还支持映射函数：

```js
Array.from({ length: 3 }, (_, index) => index);
// [0, 1, 2]
```

它不是普通对象的通用拷贝方法，也不是深拷贝。

## 6.5 JSON 深拷贝

```js
const copy = JSON.parse(JSON.stringify(source));
```

它只适合纯 JSON 数据。主要局限：

| 值/结构 | 结果 |
|---------|------|
| 循环引用 | `stringify` 抛 `TypeError` |
| `undefined`/函数/Symbol（对象属性） | 被忽略 |
| `undefined`/函数/Symbol（数组元素） | 转成 `null` |
| `NaN`、`Infinity`、`-Infinity` | 转成 `null` |
| `Date` | 通过 `toJSON` 变成 ISO 字符串 |
| `RegExp` | 通常变成 `{}` |
| `Map`、`Set` | 默认变成 `{}` |
| `BigInt` | 默认抛 `TypeError` |
| `-0` | 变成 `0` |
| 原型、描述符、不可枚举、Symbol 键 | 丢失 |

```js
const source = {
  date: new Date(),
  regexp: /js/gi,
  value: undefined,
  number: NaN,
};

const copy = JSON.parse(JSON.stringify(source));
// date 是字符串，regexp 是 {}，value 消失，number 是 null
```

## 6.6 `structuredClone()`

浏览器和现代 Node.js 提供的标准深拷贝 API：

```js
const source = {
  date: new Date(),
  regexp: /js/gi,
  map: new Map([[{ id: 1 }, { score: 100 }]]),
  set: new Set([1, 2]),
};

source.self = source;

const copy = structuredClone(source);

copy !== source;           // true
copy.self === copy;        // true
copy.date instanceof Date; // true
copy.map instanceof Map;   // true
```

优势：

- 支持循环引用和共享引用结构。
- 支持 Date、RegExp、Map、Set、ArrayBuffer、TypedArray、Error 等多种可结构化克隆类型。
- 比 JSON 方案保真度更好，语义标准化。
- 支持转移 transferable 对象的所有权。

```js
const buffer = new ArrayBuffer(8);
const copy = structuredClone(buffer, { transfer: [buffer] });

buffer.byteLength; // 0，原 buffer 已分离
copy.byteLength;   // 8
```

主要限制：

- 函数、WeakMap、WeakSet、WeakRef 等不能克隆，通常抛 `DataCloneError`。
- DOM 节点通常不能直接克隆，应使用其专用 `cloneNode`。
- Symbol 值和 Symbol 键不属于结构化克隆支持范围。
- 属性描述符、getter/setter、不可枚举属性和自定义原型通常不会按原样保留；普通对象通常克隆为普通对象。
- 转移会让原对象失去底层资源，必须明确这是所有权转移，不只是复制。

## 6.7 手写深拷贝：面试实用版

下面实现处理：

- 循环引用与共享引用：`WeakMap`。
- Symbol 键和不可枚举属性：`Reflect.ownKeys`。
- 原型与属性描述符。
- Date、RegExp、Map、Set、ArrayBuffer、DataView、TypedArray。

```js
function deepClone(value, cache = new WeakMap()) {
  if (value === null || typeof value !== 'object') {
    return value; // 函数按引用返回
  }

  if (cache.has(value)) {
    return cache.get(value);
  }

  if (value instanceof Date) {
    const clone = new Date(value.getTime());
    cache.set(value, clone);
    return clone;
  }

  if (value instanceof RegExp) {
    const clone = new RegExp(value.source, value.flags);
    clone.lastIndex = value.lastIndex;
    cache.set(value, clone);
    return clone;
  }

  if (value instanceof Map) {
    const clone = new Map();
    cache.set(value, clone);

    for (const [key, item] of value) {
      clone.set(deepClone(key, cache), deepClone(item, cache));
    }

    return clone;
  }

  if (value instanceof Set) {
    const clone = new Set();
    cache.set(value, clone);

    for (const item of value) {
      clone.add(deepClone(item, cache));
    }

    return clone;
  }

  if (value instanceof ArrayBuffer) {
    const clone = value.slice(0);
    cache.set(value, clone);
    return clone;
  }

  if (ArrayBuffer.isView(value)) {
    let clone;

    if (value instanceof DataView) {
      const buffer = deepClone(value.buffer, cache);
      clone = new DataView(buffer, value.byteOffset, value.byteLength);
    } else {
      const buffer = deepClone(value.buffer, cache);
      clone = new value.constructor(buffer, value.byteOffset, value.length);
    }

    cache.set(value, clone);
    return clone;
  }

  const clone = Array.isArray(value)
    ? []
    : Object.create(Object.getPrototypeOf(value));

  cache.set(value, clone);

  for (const key of Reflect.ownKeys(value)) {
    const descriptor = Object.getOwnPropertyDescriptor(value, key);

    if ('value' in descriptor) {
      descriptor.value = deepClone(descriptor.value, cache);
    }

    Object.defineProperty(clone, key, descriptor);
  }

  return clone;
}
```

测试：

```js
const symbol = Symbol('id');
const source = {
  date: new Date(),
  map: new Map(),
  nested: { count: 1 },
  [symbol]: 'symbol value',
};

source.self = source;
source.shared1 = source.nested;
source.shared2 = source.nested;

const copy = deepClone(source);

copy !== source;                       // true
copy.nested !== source.nested;         // true
copy.self === copy;                    // true
copy.shared1 === copy.shared2;         // true
copy[symbol] === 'symbol value';       // true
```

### 这份实现仍非“万能”

- 函数按引用返回，无法可靠克隆闭包环境。
- Promise、WeakMap、WeakSet、WeakRef、DOM、Proxy、宿主对象需要专门语义。
- 私有字段是内部槽，不能靠遍历复制。
- 某些内置对象依赖不可见内部槽，仅复制原型会产生“外形相似但不可用”的伪实例。
- 跨 realm 时，`instanceof` 检测可能失效。
- 代理对象在读取描述符、原型和键时会触发 trap。

面试时主动说明边界，通常比声称“支持所有类型”更加分。

## 6.8 为什么用 `WeakMap` 处理循环引用

错误的简单递归遇到循环会无限执行：

```js
const obj = {};
obj.self = obj;
```

缓存的映射关系是“源对象 → 已创建的克隆对象”。必须在递归复制子属性之前写入缓存：

```js
const clone = {};
cache.set(source, clone); // 先登记
// 再递归子属性
```

使用 `WeakMap` 的好处是键必须为对象，并且不会仅因缓存存在就阻止源对象被垃圾回收。

## 6.9 浅拷贝中的 getter 与描述符问题

```js
let count = 0;
const source = {
  get value() {
    count += 1;
    return count;
  },
};

const copy = { ...source };

count; // 1
Object.getOwnPropertyDescriptor(copy, 'value');
// 普通数据属性，不再是 getter
```

若目的是复制描述符而不是读取值：

```js
const copy = Object.create(
  Object.getPrototypeOf(source),
  Object.getOwnPropertyDescriptors(source),
);
```

这仍只是描述符级浅拷贝，数据描述符中嵌套对象的引用仍共享。

## 6.10 如何选择

| 场景 | 推荐方式 |
|------|----------|
| 合并配置、更新一层状态 | 展开语法 |
| 把属性写入既有目标 | `Object.assign()` |
| 浅拷贝数组 | `[...arr]` / `slice()` / `Array.from()` |
| 纯 JSON 数据且已接受丢失规则 | JSON 序列化方案 |
| 标准可克隆复杂数据、循环引用 | `structuredClone()` |
| 特殊业务类型与自定义语义 | 专用 clone 或经测试的库 |
| 保留原型和描述符 | 定制实现，明确边界 |

## 6.11 本章易错点

1. `const copy = source` 不是拷贝，只是复制引用。
2. 展开、`Object.assign`、`Array.from` 都是浅拷贝。
3. JSON 方案会静默丢失或改变大量非 JSON 值。
4. `structuredClone` 支持循环引用，但不能克隆函数、WeakMap 等。
5. `Object.assign` 与对象展开对目标 setter 的行为不同。
6. 深拷贝必须先定义类型范围和需要保留的语义，不存在无条件万能实现。

## 6.12 面试回答模板

> 浅拷贝只创建第一层新容器，嵌套对象仍共享引用，常见方式有对象展开、Object.assign、数组展开、slice 和 Array.from。JSON 序列化只适合纯 JSON 数据，会丢失 undefined、函数、Symbol，并改变 Date、Map、Set、NaN 等，也不支持循环引用。现代环境优先考虑 structuredClone，它支持循环引用和许多内置类型，但不能克隆函数、WeakMap，也不会完整保留自定义原型和属性描述符。手写深拷贝通常用 WeakMap 解决循环和共享引用，用 Reflect.ownKeys 处理 Symbol，并针对特殊类型分别构造。

# 七、对象的不可变性

## 7.1 三个层级总览

| 方法 | 可添加 | 可删除 | 可改值 | `configurable` | `writable` |
|------|--------|--------|--------|----------------|------------|
| `Object.preventExtensions()` | 否 | 是 | 是 | 不主动改变 | 不主动改变 |
| `Object.seal()` | 否 | 否 | 原可写属性可以 | 全部变 `false` | 不主动变 `false` |
| `Object.freeze()` | 否 | 否 | 数据属性不可以 | 全部变 `false` | 数据属性变 `false` |

层级关系可以记为：

```text
preventExtensions ⊂ seal ⊂ freeze
```

这里表示约束逐步增强；冻结对象一定是密封且不可扩展的，密封对象一定不可扩展。

## 7.2 `Object.preventExtensions()`

阻止对象新增自身属性，但已有属性仍可修改、删除或重新配置（前提是原描述符允许）。

```js
const user = { name: 'Alice' };
Object.preventExtensions(user);

user.age = 20;       // 失败
user.name = 'Bob';   // 成功
delete user.name;    // 成功
```

严格模式下，失败的新增操作会抛 `TypeError`；非严格模式通常静默失败。

不可扩展对象也不能把原型改成另一个对象。

## 7.3 `Object.seal()`

密封对象等价于：阻止扩展，并把所有现有自身属性的 `configurable` 设为 `false`。

```js
const user = { name: 'Alice' };
Object.seal(user);

user.age = 20;     // 失败，不能新增
delete user.name;  // 失败，不能删除
user.name = 'Bob'; // 成功，因为 writable 仍为 true
```

密封不会自动把数据属性设为只读。

## 7.4 `Object.freeze()`

冻结对象等价于：密封对象，并把所有自身数据属性的 `writable` 设为 `false`。

```js
const user = { name: 'Alice' };
Object.freeze(user);

user.name = 'Bob'; // 失败
user.age = 20;     // 失败
delete user.name;  // 失败
```

对于访问器属性，冻结不会移除 getter/setter。setter 仍可能修改外部状态或其他对象：

```js
let hidden = 0;
const obj = {
  get value() {
    return hidden;
  },
  set value(next) {
    hidden = next;
  },
};

Object.freeze(obj);
obj.value = 10;
hidden; // 10
```

因此“冻结”约束的是对象自身属性结构与数据属性写入，不代表所有可观察状态都绝对不变。

## 7.5 判断方法

```js
Object.isExtensible(obj);
Object.isSealed(obj);
Object.isFrozen(obj);
```

关系示例：

```js
const frozen = Object.freeze({ x: 1 });

Object.isExtensible(frozen); // false
Object.isSealed(frozen);     // true
Object.isFrozen(frozen);     // true
```

空的不可扩展对象没有属性可删除或修改，因此可能同时被认为密封和冻结：

```js
const empty = Object.preventExtensions({});

Object.isSealed(empty); // true
Object.isFrozen(empty); // true
```

## 7.6 冻结是浅层的

```js
const config = {
  api: {
    timeout: 1000,
  },
};

Object.freeze(config);
config.api.timeout = 2000; // 可以修改嵌套对象
```

因为 `freeze` 只冻结 `config` 自身；`config.api` 保存的引用不能被替换，但引用指向的对象没有自动冻结。

## 7.7 深冻结实现

需要处理循环引用，并遍历所有自身字符串和 Symbol 属性：

```js
function deepFreeze(value, visited = new WeakSet()) {
  if (
    value === null ||
    (typeof value !== 'object' && typeof value !== 'function') ||
    visited.has(value)
  ) {
    return value;
  }

  visited.add(value);

  for (const key of Reflect.ownKeys(value)) {
    const descriptor = Object.getOwnPropertyDescriptor(value, key);

    if (descriptor && 'value' in descriptor) {
      deepFreeze(descriptor.value, visited);
    }

    if (descriptor?.get) deepFreeze(descriptor.get, visited);
    if (descriptor?.set) deepFreeze(descriptor.set, visited);
  }

  return Object.freeze(value);
}
```

使用：

```js
const config = {
  api: { timeout: 1000 },
};
config.self = config;

deepFreeze(config);

Object.isFrozen(config);     // true
Object.isFrozen(config.api); // true
```

### 深冻结的边界

- 冻结 `Map` 或 `Set` 对象，并不会阻止调用 `set/add/delete/clear` 修改其内部数据，因为这些数据保存在内部槽中，不是普通自身属性。
- 私有字段、闭包状态和宿主对象内部状态也不受普通属性冻结完全控制。
- TypedArray 含元素时，某些环境对冻结会直接抛错。
- Proxy 可以介入相关内部操作，但必须遵守代理不变量。
- 冻结大型图结构有遍历成本，也可能影响第三方库的正常工作。

```js
const map = Object.freeze(new Map());
map.set('x', 1); // 仍能修改 Map 内部条目
```

若需要真正只读的集合，应隐藏原集合，只暴露受控查询接口，或使用专门的不可变数据结构。

## 7.8 `const` 与 `Object.freeze()`

`const` 约束变量绑定，`freeze` 约束对象自身属性：

```js
const user = { name: 'Alice' };

user.name = 'Bob'; // 可以，绑定没变
// user = {};      // TypeError，不能重新绑定
```

```js
let user = Object.freeze({ name: 'Alice' });

// user.name = 'Bob'; // 失败，对象被冻结
user = { name: 'Carol' }; // 可以，let 可以重新绑定
```

两者经常组合使用，但解决的问题不同。

## 7.9 严格模式的影响

对冻结或不可扩展对象执行非法写入：

- 非严格模式下通常静默失败。
- 严格模式下通常抛 `TypeError`。

```js
'use strict';

const obj = Object.freeze({ x: 1 });
obj.x = 2; // TypeError
```

模块和 `class` 代码天然处于严格模式，更容易及时暴露错误。

## 7.10 不可变更新

前端状态管理中常说的“不可变”，更多指不原地修改旧状态，而是创建共享未修改部分的新状态：

```js
const state = {
  user: { name: 'Alice', age: 20 },
  theme: 'dark',
};

const nextState = {
  ...state,
  user: {
    ...state.user,
    age: 21,
  },
};

nextState !== state;           // true
nextState.user !== state.user; // true
nextState.theme === state.theme; // true
```

这叫结构共享，与把整个对象图都 `freeze` 不是同一个概念。

## 7.11 本章易错点

1. `preventExtensions` 仍允许删除已有可配置属性。
2. `seal` 仍允许修改已有可写数据属性。
3. `freeze` 是浅冻结，不会递归冻结嵌套对象。
4. 冻结访问器属性不会消除 setter 的副作用。
5. 冻结 Map/Set 对象不能阻止修改其内部条目。
6. `const` 限制重新赋值，`freeze` 限制对象属性，二者作用层级不同。

## 7.12 面试回答模板

> `preventExtensions` 只禁止添加新属性；`seal` 在此基础上把所有自身属性设为不可配置，所以不能新增、删除或改变属性类型，但可写属性的值仍能修改；`freeze` 又把数据属性设为不可写，是三者中最严格的。它们都只作用于对象自身，freeze 默认是浅冻结。实现 deepFreeze 要递归 Reflect.ownKeys，并用 WeakSet 处理循环引用，但 Map、Set 等内部槽状态仍需额外设计。

# 八、对象的类型判断

## 8.1 `typeof`

`typeof` 适合区分基本类型和函数，但不适合细分普通对象：

```js
typeof undefined; // "undefined"
typeof true;      // "boolean"
typeof 1;         // "number"
typeof 1n;        // "bigint"
typeof 'x';       // "string"
typeof Symbol();  // "symbol"
typeof function () {}; // "function"

typeof {};        // "object"
typeof [];        // "object"
typeof new Date(); // "object"
typeof null;      // "object"
```

### 为什么 `typeof null === "object"`

这是 JavaScript 早期实现遗留的历史问题。早期值使用类型标签表示，对象标签接近全零，而空指针 `null` 也表示为零，导致被判断为对象。为兼容既有网页，这个行为一直保留。

判断非空对象常写：

```js
function isObjectLike(value) {
  return value !== null && typeof value === 'object';
}
```

如果希望包含函数：

```js
function isObject(value) {
  return value !== null &&
    (typeof value === 'object' || typeof value === 'function');
}
```

## 8.2 `instanceof`

通常判断右侧构造函数的 `prototype` 是否出现在左侧对象的原型链上。

```js
const arr = [];

arr instanceof Array;  // true
arr instanceof Object; // true
```

概念版实现：

```js
function myInstanceof(value, Constructor) {
  if (
    value === null ||
    (typeof value !== 'object' && typeof value !== 'function')
  ) {
    return false;
  }

  let proto = Object.getPrototypeOf(value);
  const target = Constructor.prototype;

  while (proto !== null) {
    if (proto === target) return true;
    proto = Object.getPrototypeOf(proto);
  }

  return false;
}
```

真实 `instanceof` 还会处理右侧的 `Symbol.hasInstance`、可调用性与错误情况，上述代码仅用于解释默认原型链机制。

### 局限

- 基本类型通常返回 `false`。
- 原型可以被动态修改，结果会变化。
- 多个 realm（iframe、Worker 等）各有自己的内置构造函数，跨 realm 判断可能失败。
- 可以通过 `Symbol.hasInstance` 自定义。

```js
const iframeArray = /* 来自另一个 iframe 的数组 */ null;
// iframeArray instanceof window.Array 可能是 false
// Array.isArray(iframeArray) 仍可正确判断
```

## 8.3 `Object.prototype.toString.call()`

常用于取得内建类型标签：

```js
const type = (value) =>
  Object.prototype.toString.call(value).slice(8, -1);

type(null);          // "Null"
type(undefined);     // "Undefined"
type([]);            // "Array"
type(new Date());    // "Date"
type(/x/);           // "RegExp"
type(new Map());     // "Map"
type(new Set());     // "Set"
```

为什么要用 `.call`：对象可能没有自己的 `toString`，也可能覆盖它；借用 `Object.prototype.toString` 更稳定。

但“最精确”也不是绝对的，因为 `Symbol.toStringTag` 可以改变标签：

```js
const obj = {
  [Symbol.toStringTag]: 'Magic',
};

Object.prototype.toString.call(obj); // "[object Magic]"
```

安全敏感场景不能仅凭可自定义标签确认对象具有某个内置类型的真实内部槽。

## 8.4 `Array.isArray()`

判断数组的标准方法：

```js
Array.isArray([]);              // true
Array.isArray(new Array());     // true
Array.isArray({ length: 0 });   // false
```

它比 `instanceof Array` 更适合跨 realm，并且不会把仅仅继承 `Array.prototype` 的伪数组当作真正数组。

```js
Array.isArray(Object.create(Array.prototype)); // false
```

## 8.5 构造函数属性判断

```js
value.constructor === Date;
```

这种方式不够可靠：

- `constructor` 可被修改或遮蔽。
- 纯净对象没有继承的 `constructor`。
- 跨 realm 构造函数身份不同。
- 原型被替换后可能指向错误构造函数。

因此只适合约束明确的内部代码，不应作为通用类型判断方案。

## 8.6 鸭子类型（Duck Typing）

关注对象是否具备所需能力，而不是它由哪个构造函数创建：

```js
function printSize(collection) {
  if (collection && typeof collection.size === 'number') {
    console.log(collection.size);
  }
}
```

更典型的协议判断：

```js
function isIterable(value) {
  return value != null &&
    typeof value[Symbol.iterator] === 'function';
}
```

优点：降低对具体类的耦合，适合接口式编程。
风险：仅凭几个同名属性可能误判；调用能力前仍应做好错误处理和输入校验。

## 8.7 `Symbol.hasInstance`

自定义 `instanceof` 行为：

```js
class EvenNumber {
  static [Symbol.hasInstance](value) {
    return typeof value === 'number' && value % 2 === 0;
  }
}

2 instanceof EvenNumber; // true
3 instanceof EvenNumber; // false
```

这也说明 `instanceof` 不总是单纯的原型链判断。默认函数使用继承自 `Function.prototype` 的 `@@hasInstance` 算法。

## 8.8 `Symbol.toStringTag`

自定义 `Object.prototype.toString` 的展示标签：

```js
class UserCollection {
  get [Symbol.toStringTag]() {
    return 'UserCollection';
  }
}

Object.prototype.toString.call(new UserCollection());
// "[object UserCollection]"
```

许多内置对象也通过类似机制暴露标签。它主要用于诊断与标识，不是安全的品牌校验。

## 8.9 常见需求的推荐判断

| 需求 | 推荐方式 |
|------|----------|
| 判断 `null` | `value === null` |
| 判断数组 | `Array.isArray(value)` |
| 判断函数 | `typeof value === 'function'` |
| 判断非空对象（不含函数） | `value !== null && typeof value === 'object'` |
| 判断是否可迭代 | 检查 `value?.[Symbol.iterator]` |
| 判断某原型是否在链上 | `proto.isPrototypeOf(value)` |
| 同一 realm 的类实例 | `value instanceof Class` |
| 获取诊断性内建标签 | `Object.prototype.toString.call(value)` |
| 判断某项能力 | 鸭子类型/协议检查 |

## 8.10 本章易错点

1. `typeof null` 是 `"object"`，判断对象要排除 `null`。
2. `typeof` 无法区分数组、Date、Map 等对象。
3. `instanceof` 存在跨 realm 和自定义 `Symbol.hasInstance` 问题。
4. 数组应优先用 `Array.isArray()`。
5. `Object.prototype.toString` 的标签可被 `Symbol.toStringTag` 改写。
6. `constructor` 属性可变，不适合作为通用可靠判断。

## 8.11 面试回答模板

> `typeof` 适合判断基本类型和函数，但 null 会返回 object，而且无法细分对象。`instanceof` 默认检查构造函数的 prototype 是否在对象原型链上，适合判断类实例，但存在跨 realm 和 Symbol.hasInstance 自定义问题。数组应使用 Array.isArray。需要诊断具体内建类型时常用 Object.prototype.toString.call，不过其标签也可能被 Symbol.toStringTag 修改。工程中还应根据实际需求使用协议检测或鸭子类型，而不是一味追求构造函数身份。

# 九、对象的比较与相等性

## 9.1 对象比较的是身份

对两个对象使用 `==` 或 `===` 时，判断它们是否指向同一个对象；不会逐项比较内容。

```js
{} === {}; // false
[] === []; // false

const a = { x: 1 };
const b = a;

a === b; // true
a == b;  // true
```

当两侧都是对象时，`==` 不会因为“宽松相等”而深度比较，结果与 `===` 的对象身份判断一致。

但对象与基本类型进行 `==` 时，对象可能先发生 `ToPrimitive` 转换：

```js
[1] == 1; // true，因为数组会转换为 "1"，再继续比较
```

## 9.2 `Object.is()`

`Object.is` 使用 SameValue 语义。大多数情况与 `===` 相同，两个特殊点是 `NaN` 和正负零：

```js
NaN === NaN;            // false
Object.is(NaN, NaN);    // true

0 === -0;               // true
Object.is(0, -0);       // false

Object.is({}, {});      // false
```

`Object.is()` 仍然不做对象深度比较。

## 9.3 四种常见相等算法

| 算法 | API/场景 | `NaN` 与自身 | `+0` 与 `-0` | 类型转换 |
|------|----------|--------------|---------------|----------|
| IsLooselyEqual | `==` | 不等 | 相等 | 会 |
| IsStrictlyEqual | `===` | 不等 | 相等 | 不会 |
| SameValue | `Object.is()` | 相等 | 不等 | 不会 |
| SameValueZero | `includes`、Map/Set 键 | 相等 | 相等 | 不会 |

```js
[NaN].includes(NaN); // true，SameValueZero
[NaN].indexOf(NaN);  // -1，历史上使用严格相等语义

new Set([NaN, NaN]).size; // 1
new Set([0, -0]).size;    // 1
```

Map 和 Set 对对象键仍按身份判断：

```js
const map = new Map();
map.set({ id: 1 }, 'value');

map.get({ id: 1 }); // undefined，两个对象不是同一引用
```

## 9.4 深度比较需要先定义规则

所谓 deep equal 没有唯一标准，需要明确：

- 是否比较原型。
- 是否比较不可枚举属性、Symbol 属性、属性描述符。
- 是否把 `+0` 与 `-0` 视为相等。
- 是否支持循环引用。
- Date、RegExp、Map、Set 如何比较。
- Map 的对象键按身份比较还是结构比较。
- 函数按引用还是源码比较。
- getter 是执行后比较结果，还是比较描述符本身。

## 9.5 手写深度比较：常见面试版

下面实现采用这些规则：

- 基本值使用 `Object.is`。
- 比较原型。
- 支持循环对象的成对映射。
- 支持 Date、RegExp、Array、普通对象、Map、Set。
- 普通对象比较全部自身键，但不比较完整描述符。
- Map 的键按 Map 自身键语义查找；Set 的值按 Set 自身值语义查找。
- 函数只在引用相同时相等。

```js
function deepEqual(a, b, seen = new WeakMap()) {
  if (Object.is(a, b)) return true;

  if (
    a === null ||
    b === null ||
    typeof a !== 'object' ||
    typeof b !== 'object'
  ) {
    return false;
  }

  if (Object.getPrototypeOf(a) !== Object.getPrototypeOf(b)) {
    return false;
  }

  if (seen.has(a)) {
    return seen.get(a) === b;
  }
  seen.set(a, b);

  if (a instanceof Date) {
    return Object.is(a.getTime(), b.getTime());
  }

  if (a instanceof RegExp) {
    return a.source === b.source &&
      a.flags === b.flags &&
      a.lastIndex === b.lastIndex;
  }

  if (a instanceof Map) {
    if (a.size !== b.size) return false;

    for (const [key, value] of a) {
      if (!b.has(key) || !deepEqual(value, b.get(key), seen)) {
        return false;
      }
    }

    return true;
  }

  if (a instanceof Set) {
    if (a.size !== b.size) return false;

    for (const value of a) {
      if (!b.has(value)) return false;
    }

    return true;
  }

  const keysA = Reflect.ownKeys(a);
  const keysB = Reflect.ownKeys(b);

  if (keysA.length !== keysB.length) return false;

  for (const key of keysA) {
    if (!Object.hasOwn(b, key)) return false;
    if (!deepEqual(a[key], b[key], seen)) return false;
  }

  return true;
}
```

示例：

```js
const a = { x: 1, nested: { y: 2 } };
const b = { x: 1, nested: { y: 2 } };
a.self = a;
b.self = b;

deepEqual(a, b); // true
```

### 上述实现的明确局限

- 读取 `a[key]` 可能触发 getter。
- Map/Set 中结构相同但引用不同的对象键/值会被视为不同。
- 没有处理 TypedArray、ArrayBuffer、Error 等全部内置对象。
- 成对缓存策略对某些极复杂的非同构循环图需要更严格的双向映射。
- Proxy 可以产生副作用或不稳定结果。
- 函数源码相同也不意味着闭包语义相同，因此只按引用判断。

实际项目优先使用成熟、规则明确并覆盖测试的库实现。

## 9.6 为什么不能直接 `JSON.stringify(a) === JSON.stringify(b)`

```js
JSON.stringify({ a: 1, b: 2 }) ===
JSON.stringify({ b: 2, a: 1 }); // false，顺序不同
```

此外它还会：

- 无法处理循环引用。
- 忽略 Symbol、函数、`undefined` 等。
- 改变 Date、NaN、Infinity、Map、Set 等值。
- 受 `toJSON` 影响。
- 无法表达共享引用拓扑。

因此只适合在输入已经被严格限定、键顺序已规范化的特定场景，不能当通用深比较。

## 9.7 React/状态管理中的浅比较

不可变更新让浅比较能够快速发现变化：

```js
const previous = {
  user: { name: 'Alice' },
  theme: 'dark',
};

const next = {
  ...previous,
  user: { ...previous.user, name: 'Bob' },
};

previous !== next;               // 顶层变化
previous.user !== next.user;     // user 分支变化
previous.theme === next.theme;   // theme 分支复用
```

这也是为什么状态管理通常要求不要原地修改旧对象：引用身份可作为廉价的变化信号。

## 9.8 本章易错点

1. 两个内容相同的对象使用 `==` 或 `===` 仍然不相等。
2. `Object.is` 不会深比较，只特殊处理 `NaN` 和正负零。
3. Set、Map 和 `includes` 使用 SameValueZero，`NaN` 等于自身，正负零相等。
4. `JSON.stringify` 比较不是通用 deep equal。
5. 深比较之前必须定义类型范围、原型、描述符、循环引用等规则。

## 9.9 面试回答模板

> 对象使用 `==`、`===` 或 `Object.is`，核心都是比较对象身份，不会自动比较内容。`Object.is` 与严格相等的区别是它认为 NaN 等于自身，并区分 +0 和 -0。Map、Set、includes 使用 SameValueZero，它认为 NaN 相等但不区分正负零。实现 deepEqual 要先定义语义，再递归比较键和值，用 WeakMap 处理循环引用，并为 Date、RegExp、Map、Set 等特殊类型分别处理。

# 十、对象的类型转换（ToPrimitive）

## 10.1 为什么对象要转成基本类型

当对象参与某些运算或比较时，JavaScript 需要先把它转换为基本类型。例如：

```js
const obj = { valueOf: () => 10 };
obj + 1; // 11
```

抽象操作 `ToPrimitive(input, preferredType)` 负责得到非对象值。若无法得到基本类型，就抛 `TypeError`。

## 10.2 转换优先级

如果对象定义了 `Symbol.toPrimitive`，优先调用它：

```js
const obj = {
  [Symbol.toPrimitive](hint) {
    if (hint === 'number') return 10;
    if (hint === 'string') return 'ten';
    return 'default';
  },
};

Number(obj); // 10
String(obj); // "ten"
obj + '';    // "default"
```

没有 `Symbol.toPrimitive` 时，使用普通转换流程：

- hint 为 `"number"`：通常先 `valueOf()`，再 `toString()`。
- hint 为 `"string"`：通常先 `toString()`，再 `valueOf()`。
- hint 为 `"default"`：大多数普通对象按 `"number"` 流程处理。
- `Date` 对象对 `"default"` 有特殊处理，倾向字符串流程。

注意：只有某一步返回基本类型才成功；返回对象会继续尝试下一方法。

```js
const obj = {
  valueOf() {
    return {}; // 仍是对象，继续
  },
  toString() {
    return '42';
  },
};

Number(obj); // 42
```

两种方法都返回对象则报错：

```js
const bad = {
  valueOf: () => ({}),
  toString: () => ({}),
};

// Number(bad); // TypeError: Cannot convert object to primitive value
```

## 10.3 hint 的三种值

| hint | 常见触发场景 | 无 `@@toPrimitive` 时的典型顺序 |
|------|--------------|---------------------------------|
| `"number"` | `Number(obj)`、一元 `+`、数值运算 | `valueOf → toString` |
| `"string"` | `String(obj)`、模板中的显式字符串转换、属性键转换 | `toString → valueOf` |
| `"default"` | `obj + value`、宽松相等的部分场景 | 多数对象类似 number；Date 特殊 |

不同语法的转换链可能还包含后续 `ToNumber` 或 `ToString`，不能只背第一步。

## 10.4 `+` 运算符为什么特殊

二元 `+` 会先把两侧转换为基本类型：

- 若任一结果是字符串，则做字符串拼接。
- 否则做数值加法（还要处理 Number/BigInt 规则）。

```js
1 + 2;      // 3
'1' + 2;    // "12"
[1] + 2;    // "12"，数组转成 "1"
[] + [];    // ""，两边数组都转成空字符串
```

其他算术运算符通常直接偏向数值转换：

```js
'5' - 2; // 3
[5] - 2; // 3
```

## 10.5 常见对象的默认转换

```js
String([]);       // ""
String([1, 2]);   // "1,2"
String({});       // "[object Object]"

Number([]);       // 0：[] → "" → 0
Number([1]);      // 1： [1] → "1" → 1
Number([1, 2]);   // NaN："1,2" 无法转成数字
Number({});       // NaN
```

数组通常继承的 `valueOf()` 返回数组本身，所以会继续调用数组的 `toString()`；数组 `toString()` 通常类似 `join(',')`。

## 10.6 经典题：`[] + {}`

作为正常表达式解析时：

```js
[] + {}; // "[object Object]"
```

过程：

1. `[]` 转基本类型为 `""`。
2. `{}` 转基本类型为 `"[object Object]"`。
3. 出现字符串，执行拼接。

结果为 `"[object Object]"`。

## 10.7 经典题：`{} + []`

这个问题的答案依赖解析上下文。

作为明确的表达式：

```js
({} + []); // "[object Object]"
```

但在某些旧式控制台或脚本语句开头：

```js
{} + []
```

开头的 `{}` 可能被解析为空代码块，剩余 `+[]` 是一元正号，结果为 `0`。现代控制台的解析与展示行为可能不同，所以面试时必须说明上下文，不能机械回答一个固定值。

## 10.8 经典题：`[] == ![]`

```js
[] == ![]; // true
```

过程：

1. `[]` 是对象，转布尔值永远为 `true`。
2. `![]` 得到 `false`。
3. 比较变成 `[] == false`。
4. `false` 转数字为 `0`。
5. `[]` 转基本类型为 `""`，再转数字为 `0`。
6. 最终比较 `0 == 0`，结果为 `true`。

牢记：所有对象都是真值，包括 `[]` 和 `{}`。

## 10.9 如何让 `a == 1 && a == 2 && a == 3`

利用每次宽松比较都会触发对象转基本类型：

```js
const a = {
  value: 0,
  [Symbol.toPrimitive]() {
    this.value += 1;
    return this.value;
  },
};

a == 1 && a == 2 && a == 3; // true
```

也可以改写 `valueOf()`：

```js
const a = {
  value: 0,
  valueOf() {
    return ++this.value;
  },
};
```

这是一道机制题，不应在业务代码中制造这种带副作用的隐式转换。

若题目使用严格相等：

```js
a === 1 && a === 2 && a === 3
```

单靠普通对象的类型转换无法实现，因为 `===` 不调用 `ToPrimitive`。通过全局 getter 等方式可以构造其他谜题，但那已经不是对象转换本身。

## 10.10 `Date` 的特殊行为

```js
const date = new Date(0);

date + 1;         // 通常是日期字符串后拼接 "1"
date - 1;         // -1，减法要求数值转换
Number(date);     // 0
```

`Date` 对 default hint 倾向字符串，而数值运算仍会使用 number hint。因此日期加法与减法可能表现不同。

## 10.11 属性键转换

普通对象使用非 Symbol 值作为属性键时，会执行 `ToPropertyKey`，其中会以 string hint 转为基本类型，再转字符串：

```js
const key = {
  toString() {
    return 'customKey';
  },
};

const obj = {};
obj[key] = 1;

obj.customKey; // 1
```

如果转换得到 Symbol，则直接作为 Symbol 属性键。

## 10.12 宽松相等的实用建议

业务代码通常优先使用 `===`，避免复杂转换。一个偶尔有意使用的写法是同时判断 `null` 和 `undefined`：

```js
if (value == null) {
  // value 是 null 或 undefined
}
```

若团队规范不接受宽松相等，则写成：

```js
if (value === null || value === undefined) {}
```

## 10.13 本章易错点

1. `Symbol.toPrimitive` 优先于 `valueOf` 和 `toString`。
2. string hint 通常先 `toString`，number hint 通常先 `valueOf`。
3. default hint 对多数对象类似 number，但 Date 是重要例外。
4. 二元 `+` 可能做拼接，减乘除通常偏数值转换。
5. `{}` 在语句开头可能被解析成代码块，经典题必须说明上下文。
6. 所有对象都是真值，空数组和空对象也不例外。
7. 严格相等不会触发对象的 `ToPrimitive`。

## 10.14 面试回答模板

> 对象需要转基本类型时，先检查 Symbol.toPrimitive，并传入 number、string 或 default hint；没有该方法时，number 通常按 valueOf、toString 顺序，string 则相反，default 对大多数对象类似 number，但 Date 倾向 string。二元加法会先转基本类型，只要一侧是字符串就拼接，否则数值相加。经典题 `{ } + []` 还受语法解析上下文影响，表达式中的对象与数组相加结果是字符串，而语句开头的空花括号可能被解析为代码块。

# 十一、ES6+ 对象新特性

## 11.1 对象解构基础

按属性名从对象中取值：

```js
const user = { name: 'Alice', age: 20 };
const { name, age } = user;
```

解构查找遵循普通属性访问，因此可以读取继承的属性；但对象剩余属性只收集自身可枚举属性。

## 11.2 重命名与默认值

```js
const user = { name: 'Alice' };

const {
  name: userName,
  age = 18,
} = user;

userName; // "Alice"
age;      // 18
```

默认值只在属性值严格等于 `undefined` 时生效，`null` 不会触发：

```js
const { x = 1 } = { x: null };
x; // null
```

重命名语法中，`name` 是属性名，`userName` 才是新变量名。

## 11.3 嵌套解构

```js
const response = {
  data: {
    user: {
      profile: { city: 'Shanghai' },
    },
  },
};

const {
  data: {
    user: {
      profile: { city },
    },
  },
} = response;
```

如果中间值可能为 `undefined`，直接深层解构会抛错。可以给中间层默认空对象：

```js
const { data: { user = {} } = {} } = response ?? {};
```

但嵌套过深时可读性差，实际代码常用可选链逐层访问。

## 11.4 对象剩余属性

```js
const user = { id: 1, name: 'Alice', password: 'secret' };
const { password, ...safeUser } = user;

safeUser; // { id: 1, name: "Alice" }
```

剩余对象是浅拷贝，收集尚未解构的可枚举自身属性，包括 Symbol 键；嵌套对象仍共享引用。

## 11.5 解构已有变量的语法陷阱

```js
let name;

({ name } = { name: 'Alice' });
```

外层括号不可省略，否则开头 `{}` 可能被解析为代码块。

## 11.6 对象展开

### 浅拷贝

```js
const copy = { ...source };
```

### 合并与覆盖

```js
const options = {
  ...defaults,
  ...userOptions,
  timeout: 5000,
};
```

后出现的同名属性覆盖前面的值；覆盖一般不会改变该键原有的顺序位置。

### 条件属性

```js
const result = {
  id: 1,
  ...(isAdmin && { role: 'admin' }),
};
```

对象展开会忽略 `null` 和 `undefined`；展开字符串会产生索引属性：

```js
({ ...null });   // {}
({ ...undefined }); // {}
({ ...'hi' });   // { 0: "h", 1: "i" }
```

## 11.7 可选链 `?.`

当链左侧为 `null` 或 `undefined` 时短路并返回 `undefined`：

```js
user.profile?.address?.city;
```

三种常用形式：

```js
obj?.property;       // 属性访问
obj?.[expression];   // 动态属性访问
fn?.(args);          // 可选调用
```

它只对 nullish 值短路，不会把 `0`、`false`、`''` 当成缺失。

```js
const value = { count: 0 };
value?.count; // 0
```

### 短路只在连续链中生效

```js
user?.profile?.name;   // 安全
(user?.profile).name;  // 分组中断链，profile 为 undefined 时会报错
```

### 方法调用与 `this`

```js
user.sayHi?.();
```

这种属性引用上的可选调用会保留 `user` 作为 `this`。但若属性存在却不是函数，仍会抛 `TypeError`。

### 不能用于赋值左侧

```js
// user?.name = 'Alice'; // SyntaxError
```

## 11.8 空值合并 `??`

左侧仅在 `null` 或 `undefined` 时使用右侧默认值：

```js
const count = inputCount ?? 0;
```

与 `||` 的区别：

```js
0 || 10;  // 10
0 ?? 10;  // 0

'' || 'default'; // "default"
'' ?? 'default'; // ""
```

配置默认值时，`??` 往往更符合“仅缺失才回退”的语义。

`??` 不能不加括号地直接与 `&&` 或 `||` 混用：

```js
// a ?? b || c; // SyntaxError
(a ?? b) || c;
```

对应的逻辑赋值运算符是 `??=`：

```js
options.timeout ??= 3000;
```

## 11.9 `Object.fromEntries()`

把键值对可迭代对象转换为普通对象，是 `Object.entries()` 的近似逆操作：

```js
const entries = [['name', 'Alice'], ['age', 20]];
Object.fromEntries(entries);
// { name: "Alice", age: 20 }
```

支持 Map 和 Symbol 键：

```js
const map = new Map([
  ['x', 1],
  [Symbol.for('id'), 2],
]);

const obj = Object.fromEntries(map);
```

重复键以后面的值为准。非 Symbol 键会被转换为字符串，所以把 Map 转成对象可能丢失键类型和对象键身份。

常见用法：

```js
const filtered = Object.fromEntries(
  Object.entries(user).filter(([, value]) => value !== undefined),
);
```

## 11.10 `Object.groupBy()`（ES2024）

按回调返回的属性键对可迭代数据分组：

```js
const products = [
  { name: 'apple', category: 'fruit' },
  { name: 'carrot', category: 'vegetable' },
  { name: 'banana', category: 'fruit' },
];

const grouped = Object.groupBy(
  products,
  (product) => product.category,
);

// {
//   fruit: [apple, banana],
//   vegetable: [carrot]
// }
```

重要特点：

- 输入是可迭代对象，不限于数组。
- 回调返回值会转换为属性键，即字符串或 Symbol。
- 返回一个 `null` 原型对象，不应直接调用 `grouped.hasOwnProperty(...)`。
- 分组中的元素仍是原元素引用，不会深拷贝。
- 若环境较旧，需要确认兼容性或提供 polyfill。

```js
Object.getPrototypeOf(grouped) === null; // true
```

如果希望任意类型作为分组键，使用 `Map.groupBy()`：

```js
const restock = { restock: true };
const enough = { restock: false };

const grouped = Map.groupBy(
  products,
  (product) => product.stock < 5 ? restock : enough,
);
```

`Map.groupBy` 保留键的身份，不会强制转成字符串。

## 11.11 本章易错点

1. 解构默认值只在值为 `undefined` 时生效，`null` 不生效。
2. 对象剩余属性和展开都是浅拷贝。
3. 可选链只对 `null`/`undefined` 短路，不对其他假值短路。
4. 给可选链结果加括号后再继续访问，可能打断短路链。
5. `??` 保留 `0`、`false` 和空字符串，`||` 不保留。
6. `Object.fromEntries` 会把非 Symbol 键转成字符串。
7. `Object.groupBy` 返回 null 原型对象，分组元素仍是原引用。

## 11.12 面试回答模板

> ES6+ 对象常用增强包括解构、剩余与展开、可选链、空值合并和 fromEntries。解构默认值只在 undefined 时生效；对象展开是浅拷贝，并遵循后值覆盖前值；可选链只在 null 或 undefined 时短路；空值合并比 `||` 更适合保留 0、false、空字符串等有效配置。ES2024 的 Object.groupBy 按属性键分组并返回 null 原型对象，若需要任意类型键则用 Map.groupBy。

# 十二、Map / WeakMap / Set / WeakSet

## 12.1 `Map` 基础

`Map` 是键值集合，键可以是任意 JavaScript 值。

```js
const objectKey = { id: 1 };
const map = new Map();

map.set('name', 'Alice');
map.set(objectKey, 'object value');
map.set(NaN, 'not a number');

map.get(objectKey); // "object value"
map.has('name');    // true
map.size;           // 3
map.delete('name');
map.clear();
```

`set` 返回 Map 本身，因此可以链式调用：

```js
const map = new Map()
  .set('a', 1)
  .set('b', 2);
```

## 12.2 Map 与普通对象

| 维度 | `Map` | 普通对象 |
|------|-------|----------|
| 键类型 | 任意值 | 字符串或 Symbol |
| 原型键冲突 | 无 | 普通对象可能有继承属性 |
| 数量 | `size` | 通常 `Object.keys(obj).length` |
| 迭代 | 原生可迭代 | 需先取 keys/entries |
| 顺序 | 插入顺序 | 索引键等有专门顺序规则 |
| 增删 API | `set/get/has/delete/clear` | 属性语法、`delete` |
| JSON | 默认不直接支持 | 天然适合字符串键 JSON 结构 |
| 频繁动态增删 | 通常更适合 | 依场景和引擎而定 |

不要绝对声称 Map 在所有场景性能都更好。性能受数据量、访问模式、引擎和对象形状影响，应以基准测试为准。静态记录、领域模型和 JSON 数据通常仍适合普通对象；动态键值表、任意类型键和频繁增删更适合 Map。

## 12.3 Map 的遍历与转换

Map 按插入顺序迭代：

```js
for (const [key, value] of map) {}

map.keys();
map.values();
map.entries();
map.forEach((value, key) => {});
```

注意 Map `forEach` 参数顺序是 `(value, key, map)`，与数组 `(value, index, array)` 形态一致。

```js
const object = Object.fromEntries(map);
const mapAgain = new Map(Object.entries(object));
```

转成对象时，非 Symbol 键会字符串化，对象键可能冲突，因此转换可能有损。

## 12.4 Map 键的相等性

Map 使用 SameValueZero：

```js
const map = new Map();

map.set(NaN, 'value');
map.get(NaN); // "value"

map.set(0, 'zero');
map.get(-0); // "zero"
```

对象键按身份：

```js
map.set({ id: 1 }, 'A');
map.get({ id: 1 }); // undefined
```

## 12.5 `WeakMap`

WeakMap 的键是弱持有的：若某对象除作为 WeakMap 键之外不再被其他地方强引用，它可以被垃圾回收，WeakMap 不会单独阻止回收。

```js
const metadata = new WeakMap();
let user = { name: 'Alice' };

metadata.set(user, { lastLogin: Date.now() });
metadata.get(user);

user = null;
// 原对象未来可能被回收，对应 WeakMap 条目也会消失
```

现代规范允许 WeakMap 的键为对象或未注册的 Symbol；为了面试和兼容性，最稳妥的核心回答仍是“主要以对象作为弱键”，并知道已注册的 `Symbol.for()` 不能作为弱键。具体运行环境支持度需确认。

WeakMap 的特点：

- 键被弱持有。
- 不可遍历，没有 `keys/values/entries/size/clear`。
- 不能观察垃圾回收时机。
- 常用 API 是 `set/get/has/delete`。
- 值被正常强引用，但只有在键仍可达或条目存在的语义下访问。

不可遍历是必要设计：垃圾回收发生时间不确定，如果能枚举，程序结果会随 GC 时机变化。

## 12.6 WeakMap 应用场景

### 关联私有数据

```js
const privateData = new WeakMap();

class Counter {
  constructor() {
    privateData.set(this, { count: 0 });
  }

  increment() {
    privateData.get(this).count += 1;
  }

  get value() {
    return privateData.get(this).count;
  }
}
```

现代 class 私有字段 `#count` 通常更直接，但 WeakMap 仍适合跨模块关联和兼容方案。

### DOM 关联数据

```js
const elementState = new WeakMap();

elementState.set(button, { clickCount: 0 });
```

当 DOM 节点不再被其他地方引用时，关联数据不会仅因映射而强行保留节点。

### 对象结果缓存

```js
const cache = new WeakMap();

function compute(obj) {
  if (cache.has(obj)) return cache.get(obj);

  const result = expensiveOperation(obj);
  cache.set(obj, result);
  return result;
}
```

### 循环引用处理

深拷贝、序列化、深比较中，用 WeakMap/WeakSet 记录访问过的对象。

## 12.7 `Set`

Set 保存不重复的值：

```js
const set = new Set([1, 2, 2, NaN, NaN]);

set.size;    // 3
set.add(3);  // 返回 set，可链式调用
set.has(2);  // true
set.delete(2);
set.clear();
```

常见数组去重：

```js
const unique = [...new Set([1, 1, 2, 3])];
```

对象按身份去重，内容相同的不同对象不会合并：

```js
new Set([{ id: 1 }, { id: 1 }]).size; // 2
```

按字段去重可借助 Map：

```js
const uniqueById = [
  ...new Map(users.map((user) => [user.id, user])).values(),
];
```

后出现的同 id 用户覆盖值，但键的最初插入位置通常不变。

## 12.8 Set 的 SameValueZero

```js
const set = new Set();

set.add(NaN);
set.add(NaN);
set.size; // 1

set.add(0);
set.add(-0);
// 正负零只保留一个
```

## 12.9 Set 集合运算

传统通用写法：

```js
const union = (a, b) => new Set([...a, ...b]);

const intersection = (a, b) =>
  new Set([...a].filter((value) => b.has(value)));

const difference = (a, b) =>
  new Set([...a].filter((value) => !b.has(value)));

const isSubset = (a, b) =>
  [...a].every((value) => b.has(value));
```

新版本 ECMAScript 已提供 `union`、`intersection`、`difference`、`symmetricDifference`、`isSubsetOf`、`isSupersetOf`、`isDisjointFrom` 等 Set 方法，但使用前要检查目标运行环境兼容性。

## 12.10 `WeakSet`

WeakSet 是弱集合，核心用途是记录对象是否出现过：

```js
const visited = new WeakSet();

function walk(obj) {
  if (obj === null || typeof obj !== 'object') return;
  if (visited.has(obj)) return;

  visited.add(obj);

  for (const key of Reflect.ownKeys(obj)) {
    walk(obj[key]);
  }
}
```

特点与 WeakMap 类似：弱持有、不可遍历、没有 `size` 和 `clear`，主要 API 是 `add/has/delete`。同样，现代规范对未注册 Symbol 弱值有所扩展，但对象是最典型和兼容的用法。

## 12.11 `WeakRef`

`WeakRef` 允许创建对对象的弱引用：

```js
let target = { large: 'data' };
const ref = new WeakRef(target);

ref.deref(); // 当前可能返回对象
target = null;

// 未来某次 ref.deref() 可能返回 undefined
```

`deref()` 的结果不稳定，对象可能已被回收。不要用 WeakRef 管理必须可靠存在的业务状态。

适用场景很有限，例如非关键缓存、规范允许随时重建的辅助对象。大部分代码无需直接使用它。

## 12.12 `FinalizationRegistry`

可在目标被垃圾回收后的某个不确定时机，安排清理回调：

```js
const registry = new FinalizationRegistry((heldValue) => {
  console.log('target collected:', heldValue);
});

let target = {};
registry.register(target, 'target metadata');
target = null;
```

重要限制：

- 回调何时执行不确定，甚至进程退出前可能不执行。
- 不能用于关键资源释放、业务正确性或精确统计。
- held value 不能强引用目标，否则会妨碍回收设计。
- 文件句柄、连接等资源应显式释放，不能依赖终结回调。

## 12.13 本章易错点

1. Map 的键可以是任意值，普通对象键只能是字符串或 Symbol。
2. Map 并非在所有场景都比对象快，应根据数据模型和基准选择。
3. WeakMap 的弱引用针对键，不代表所有相关值都神奇地变成弱引用。
4. WeakMap/WeakSet 不可遍历，也没有 `size`，因为 GC 时机不确定。
5. Set 对对象按引用身份去重，不做深度去重。
6. WeakRef 和 FinalizationRegistry 不能承担关键业务正确性。

## 12.14 面试回答模板

> Map 与普通对象相比，键可为任意值，原生提供 size 和稳定插入序迭代，适合动态键值表；对象更适合静态记录、领域模型和 JSON。Map 和 Set 使用 SameValueZero，所以 NaN 等于自身、正负零相同，但对象仍按引用身份判断。WeakMap 的键被弱持有且不可遍历，适合对象私有数据、DOM 关联、缓存和循环引用记录。WeakRef 与 FinalizationRegistry 的时机不确定，只适合非关键辅助场景，不能依赖它们释放关键资源。

# 十三、Symbol 与对象

## 13.1 Symbol 基础

`Symbol` 是基本类型，每次调用通常产生唯一值：

```js
const a = Symbol('id');
const b = Symbol('id');

a === b; // false
typeof a; // "symbol"
```

描述只是调试标签，不参与唯一性。`Symbol` 不能用 `new` 调用：

```js
// new Symbol('id'); // TypeError
```

## 13.2 Symbol 作为属性键

```js
const id = Symbol('id');
const user = {
  name: 'Alice',
  [id]: 1001,
};

user[id]; // 1001
```

意义：

- 避免与普通字符串属性意外冲突。
- 为对象附加协议或元数据。
- 实现框架与用户属性之间的命名隔离。

Symbol 属性不是“真正私有”。只要拿到 Symbol 或通过反射获取所有键，就能访问：

```js
Reflect.ownKeys(user);              // ["name", Symbol(id)]
Object.getOwnPropertySymbols(user); // [Symbol(id)]
```

真正的类私有字段使用 `#field`，或借助闭包/WeakMap。

## 13.3 Symbol 属性的遍历行为

Symbol 键不会出现在：

- `for...in`
- `Object.keys/values/entries`
- `Object.getOwnPropertyNames`
- JSON 对象输出

会出现在：

- `Object.getOwnPropertySymbols`
- `Reflect.ownKeys`
- `Object.getOwnPropertyDescriptors`
- 对象展开和 `Object.assign`（前提是可枚举）

```js
const key = Symbol('key');
const source = { [key]: 1 };

({ ...source })[key];             // 1
Object.assign({}, source)[key];   // 1
JSON.stringify(source);           // "{}"
```

## 13.4 `Symbol.for()` 与全局注册表

`Symbol.for(key)` 会在全局 Symbol 注册表中查找或创建，因此相同键返回相同 Symbol：

```js
const a = Symbol.for('app.id');
const b = Symbol.for('app.id');

a === b; // true
```

使用 `Symbol.keyFor()` 反查注册键：

```js
Symbol.keyFor(a);             // "app.id"
Symbol.keyFor(Symbol('id'));  // undefined
```

对比：

| 创建方式 | 唯一性 | 是否进入全局注册表 | 可否 `keyFor` |
|----------|--------|--------------------|----------------|
| `Symbol('x')` | 每次不同 | 否 | 否 |
| `Symbol.for('x')` | 同键复用 | 是 | 是 |

“全局”是相对于相关 agent/realm 的共享注册机制而言，不代表跨所有进程、机器或序列化边界共享。

## 13.5 常见内置 Symbol

内置 Symbol 定义语言级协议，通常称为 well-known symbols。

| Symbol | 作用 |
|--------|------|
| `Symbol.iterator` | 定义同步迭代协议 |
| `Symbol.asyncIterator` | 定义异步迭代协议 |
| `Symbol.toPrimitive` | 自定义对象转基本类型 |
| `Symbol.hasInstance` | 自定义 `instanceof` |
| `Symbol.toStringTag` | 自定义对象类型标签 |
| `Symbol.species` | 指定派生对象的构造函数 |
| `Symbol.match` | 自定义 `String.prototype.match` 行为 |
| `Symbol.matchAll` | 自定义 `matchAll` 行为 |
| `Symbol.replace` | 自定义 `replace` 行为 |
| `Symbol.search` | 自定义 `search` 行为 |
| `Symbol.split` | 自定义 `split` 行为 |
| `Symbol.isConcatSpreadable` | 控制 `concat` 是否展开 |
| `Symbol.unscopables` | 控制 `with` 中排除的属性 |

## 13.6 `Symbol.iterator`

让对象支持 `for...of`、展开、解构等迭代消费方式：

```js
const range = {
  from: 1,
  to: 3,

  *[Symbol.iterator]() {
    for (let value = this.from; value <= this.to; value += 1) {
      yield value;
    }
  },
};

[...range]; // [1, 2, 3]

for (const value of range) {
  console.log(value);
}
```

可迭代对象的 `Symbol.iterator` 必须返回迭代器；迭代器的 `next()` 返回 `{ value, done }`。

## 13.7 `Symbol.asyncIterator`

定义异步迭代，可被 `for await...of` 消费：

```js
const source = {
  async *[Symbol.asyncIterator]() {
    yield await Promise.resolve(1);
    yield await Promise.resolve(2);
  },
};

for await (const value of source) {
  console.log(value);
}
```

## 13.8 `Symbol.species`

某些内置派生操作用它决定返回对象的构造函数：

```js
class MyArray extends Array {
  static get [Symbol.species]() {
    return Array;
  }
}

const source = new MyArray(1, 2, 3);
const mapped = source.map((x) => x * 2);

mapped instanceof Array;   // true
mapped instanceof MyArray; // false
```

这是较底层的库设计能力，业务代码很少需要修改。

## 13.9 `Symbol.isConcatSpreadable`

控制对象被 `Array.prototype.concat` 处理时是否展开：

```js
const arrayLike = {
  0: 'a',
  1: 'b',
  length: 2,
  [Symbol.isConcatSpreadable]: true,
};

[].concat(arrayLike); // ["a", "b"]
```

也可以让数组不展开：

```js
const arr = [1, 2];
arr[Symbol.isConcatSpreadable] = false;

[].concat(arr); // [[1, 2]]
```

## 13.10 Symbol 不能被隐式转为字符串

```js
const id = Symbol('id');

String(id);       // "Symbol(id)"
id.toString();    // "Symbol(id)"
// '' + id;       // TypeError
```

设计上禁止某些隐式字符串转换，有助于避免 Symbol 键无意变成普通字符串键。

## 13.11 本章易错点

1. `Symbol('x')` 的描述相同也不相等。
2. `Symbol.for('x')` 会复用全局注册表中的 Symbol。
3. Symbol 属性不参与常规字符串键遍历，但并非私有。
4. 可枚举 Symbol 属性会被对象展开和 `Object.assign` 复制。
5. JSON 会忽略 Symbol 键；Symbol 值在对象和数组中的规则也不同。
6. 内置 Symbol 本质上是 JavaScript 对象参与语言协议的扩展点。

## 13.12 面试回答模板

> Symbol 是一种基本类型，每次 `Symbol(description)` 通常创建唯一值，适合作为不会意外冲突的属性键。Symbol 属性不会出现在 for...in、Object.keys 和 JSON 中，但能通过 getOwnPropertySymbols 或 Reflect.ownKeys 获取，所以不是真正私有。`Symbol.for` 使用全局注册表，同一个键会复用。内置 Symbol 则定义语言协议，例如 iterator、toPrimitive、hasInstance 和 toStringTag，让对象可以定制迭代、转换、instanceof 等行为。

# 十四、Proxy 与 Reflect

## 14.1 Proxy 基础

`Proxy` 为目标对象的内部操作提供拦截层：

```js
const target = { count: 0 };

const proxy = new Proxy(target, {
  get(target, key, receiver) {
    console.log('get:', key);
    return Reflect.get(target, key, receiver);
  },

  set(target, key, value, receiver) {
    console.log('set:', key, value);
    return Reflect.set(target, key, value, receiver);
  },
});

proxy.count;     // 触发 get
proxy.count = 1; // 触发 set
```

Proxy 代理的是对象操作，不是简单给某个属性装 getter/setter。新增属性、删除、`in`、枚举、函数调用、构造等都可在相应 trap 中拦截。

## 14.2 Proxy 的 13 种 trap

| trap | 拦截的典型操作 | 对应 Reflect |
|------|----------------|--------------|
| `get` | `proxy.key` | `Reflect.get` |
| `set` | `proxy.key = value` | `Reflect.set` |
| `has` | `key in proxy` | `Reflect.has` |
| `deleteProperty` | `delete proxy.key` | `Reflect.deleteProperty` |
| `ownKeys` | `Reflect.ownKeys`、枚举取键 | `Reflect.ownKeys` |
| `getOwnPropertyDescriptor` | 查询自身描述符 | `Reflect.getOwnPropertyDescriptor` |
| `defineProperty` | `Object.defineProperty` | `Reflect.defineProperty` |
| `getPrototypeOf` | 查询原型 | `Reflect.getPrototypeOf` |
| `setPrototypeOf` | 设置原型 | `Reflect.setPrototypeOf` |
| `isExtensible` | 查询是否可扩展 | `Reflect.isExtensible` |
| `preventExtensions` | 阻止扩展 | `Reflect.preventExtensions` |
| `apply` | 函数调用、`call/apply` | `Reflect.apply` |
| `construct` | `new proxy()` | `Reflect.construct` |

只有目标可调用时 `apply` 才有意义，只有目标可构造时 `construct` 才有意义。

## 14.3 常用 trap 示例

### `get`

```js
const proxy = new Proxy(target, {
  get(target, key, receiver) {
    if (!(key in target)) {
      throw new ReferenceError(`Unknown property: ${String(key)}`);
    }

    return Reflect.get(target, key, receiver);
  },
});
```

### `set`

```js
const user = new Proxy({}, {
  set(target, key, value, receiver) {
    if (key === 'age' && (!Number.isInteger(value) || value < 0)) {
      throw new TypeError('age must be a non-negative integer');
    }

    return Reflect.set(target, key, value, receiver);
  },
});
```

`set` trap 应返回布尔值表示是否成功。严格模式下返回假值会引发 `TypeError`。

### `has` 与 `deleteProperty`

```js
const proxy = new Proxy(target, {
  has(target, key) {
    if (String(key).startsWith('_')) return false;
    return Reflect.has(target, key);
  },

  deleteProperty(target, key) {
    if (key === 'id') return false;
    return Reflect.deleteProperty(target, key);
  },
});
```

“隐藏”属性仍受代理不变量限制，且拿到原始 target 就可绕过，不是真正安全隔离。

### `ownKeys`

```js
const proxy = new Proxy(target, {
  ownKeys(target) {
    return Reflect.ownKeys(target).filter(
      (key) => !String(key).startsWith('_'),
    );
  },
});
```

### `apply`

```js
function sum(a, b) {
  return a + b;
}

const loggedSum = new Proxy(sum, {
  apply(target, thisArg, args) {
    console.log('args:', args);
    return Reflect.apply(target, thisArg, args);
  },
});

loggedSum(1, 2); // 3
```

### `construct`

```js
class User {
  constructor(name) {
    this.name = name;
  }
}

const UserProxy = new Proxy(User, {
  construct(target, args, newTarget) {
    console.log('new User:', args);
    return Reflect.construct(target, args, newTarget);
  },
});
```

`construct` 必须返回对象。

## 14.4 为什么 trap 内推荐使用 Reflect

Reflect 把许多对象内部操作以函数形式暴露，并与 Proxy trap 一一对应。优势：

- 命名和语义统一。
- 容易透传默认行为。
- 多数修改操作返回布尔值，便于代理 trap 返回。
- `Reflect.get/set` 支持显式 `receiver`，对 getter/setter 与继承很重要。
- `Reflect.construct` 可以指定 `newTarget`。

```js
Reflect.get(target, key, receiver);
Reflect.set(target, key, value, receiver);
```

## 14.5 `receiver` 为什么重要

```js
const target = {
  _name: 'Alice',
  get name() {
    return this._name;
  },
};

const proxy = new Proxy(target, {
  get(target, key, receiver) {
    return Reflect.get(target, key, receiver);
  },
});
```

`receiver` 表示最初发生属性访问的对象，通常是 proxy 或继承 proxy 的对象。使用 `Reflect.get(target, key, receiver)` 能让 getter 中的 `this` 保持正确接收者，而直接 `target[key]` 会把内部访问绑定到 target 的语义上。

继承场景更明显：

```js
const child = Object.create(proxy);
child._name = 'Bob';
child.name; // 应读取 child._name，得到 "Bob"
```

## 14.6 Reflect 常用 API

Reflect 不是构造函数，不能 `new Reflect()`。它的方法包括：

```js
Reflect.get(target, key, receiver);
Reflect.set(target, key, value, receiver);
Reflect.has(target, key);
Reflect.deleteProperty(target, key);
Reflect.ownKeys(target);
Reflect.getOwnPropertyDescriptor(target, key);
Reflect.defineProperty(target, key, descriptor);
Reflect.getPrototypeOf(target);
Reflect.setPrototypeOf(target, proto);
Reflect.isExtensible(target);
Reflect.preventExtensions(target);
Reflect.apply(fn, thisArg, args);
Reflect.construct(Constructor, args, NewTarget);
```

与部分 `Object` 方法的风格差异：

```js
Object.defineProperty(obj, 'x', descriptor); // 失败通常抛错
Reflect.defineProperty(obj, 'x', descriptor); // 返回 false
```

## 14.7 Proxy 不变量（invariants）

Proxy 不能随意伪造违反目标对象底层约束的结果。常见规则：

- 不可配置的自身属性不能从 `ownKeys` 结果中消失。
- 目标不可扩展时，`ownKeys` 必须准确反映目标自身键，不能增减。
- 不可配置且不可写的数据属性，`get` trap 不能报告不同值。
- 不可配置且 getter 为 `undefined` 的访问器属性，`get` 必须返回 `undefined`。
- `getOwnPropertyDescriptor` 不能把不可配置属性伪装成可配置。
- `isExtensible` 和 `preventExtensions` 的结果必须与目标实际状态一致。
- `construct` 必须返回对象。

违反不变量时，即使 trap 返回了自认为合理的值，引擎也会抛 `TypeError`。

```js
const target = {};
Object.defineProperty(target, 'fixed', {
  value: 1,
  configurable: false,
});

const proxy = new Proxy(target, {
  ownKeys() {
    return []; // 隐藏了不可配置属性
  },
});

// Reflect.ownKeys(proxy); // TypeError
```

## 14.8 Proxy 的身份与内部槽问题

代理与目标不是同一个对象：

```js
proxy === target; // false
```

Map/Set 键会把二者视为不同身份。某些带内部槽的原生对象方法也不能直接在普通代理上工作：

```js
const map = new Map();
const proxy = new Proxy(map, {});

// proxy.set('x', 1); // 某些调用会因 this 缺少 Map 内部槽而报错
```

可以在 `get` trap 中为方法绑定原目标，但这也会改变方法身份等行为：

```js
const proxy = new Proxy(map, {
  get(target, key, receiver) {
    const value = Reflect.get(target, key, target);
    return typeof value === 'function' ? value.bind(target) : value;
  },
});
```

私有字段也依赖真实实例品牌，透明代理并不自动拥有目标的私有槽。

## 14.9 `Proxy.revocable()`

创建可撤销代理：

```js
const target = { secret: 42 };
const { proxy, revoke } = Proxy.revocable(target, {});

proxy.secret; // 42
revoke();

// proxy.secret; // TypeError
```

撤销后，绝大多数代理操作都会抛 `TypeError`，且不可恢复。适合临时授权、插件接口、生命周期受控的访问能力。

## 14.10 Proxy 与 `Object.defineProperty` 对比

| 维度 | Proxy | `Object.defineProperty` |
|------|-------|-------------------------|
| 拦截范围 | 对象级多种操作 | 已定义属性的读写 |
| 新增属性 | 可通过 `set/defineProperty` 自动拦截 | 通常需再次处理新属性 |
| 删除属性 | 可拦截 | 无法仅靠 getter/setter 拦截 |
| 数组索引/长度 | 可统一代理 | 需要特殊处理 |
| 返回值 | 新代理对象 | 修改原对象 |
| 兼容性 | ES2015+，无法完整 polyfill | ES5+ |
| 深层对象 | 都需按需递归处理 | 都需递归处理 |
| 身份 | proxy 与 target 不同 | 原对象身份不变 |

Vue 2 主要使用 `Object.defineProperty` 劫持已有属性；Vue 3 使用 Proxy，对新增、删除、数组、Map/Set 等支持更自然。

## 14.11 Vue 3 响应式原理（简化）

核心流程：

1. `reactive` 返回原对象的 Proxy。
2. effect 执行时读取属性，`get` trap 调用 `track(target, key)` 收集依赖。
3. 修改属性时，`set/deleteProperty` 调用 `trigger(target, key)` 通知依赖。
4. 嵌套对象通常在读取时按需包装成响应式代理。
5. 用 WeakMap 缓存“原对象 → 代理”，避免重复代理和额外内存保留。

概念版：

```js
let activeEffect;
const targetMap = new WeakMap();

function track(target, key) {
  if (!activeEffect) return;

  let depsMap = targetMap.get(target);
  if (!depsMap) {
    depsMap = new Map();
    targetMap.set(target, depsMap);
  }

  let effects = depsMap.get(key);
  if (!effects) {
    effects = new Set();
    depsMap.set(key, effects);
  }

  effects.add(activeEffect);
}

function trigger(target, key) {
  targetMap.get(target)?.get(key)?.forEach((effect) => effect());
}

function reactive(target) {
  return new Proxy(target, {
    get(target, key, receiver) {
      track(target, key);
      const value = Reflect.get(target, key, receiver);
      return value !== null && typeof value === 'object'
        ? reactive(value)
        : value;
    },

    set(target, key, value, receiver) {
      const oldValue = Reflect.get(target, key, receiver);
      const success = Reflect.set(target, key, value, receiver);

      if (success && !Object.is(oldValue, value)) {
        trigger(target, key);
      }

      return success;
    },
  });
}

function effect(fn) {
  activeEffect = fn;
  fn();
  activeEffect = undefined;
}
```

这只是教学版。真实 Vue 还要处理代理缓存、effect 栈、分支依赖清理、调度器、数组、集合类型、迭代依赖、readonly、ref、computed 等大量细节。

## 14.12 本章易错点

1. Proxy 有 13 个 trap，并不只拦截 get/set。
2. trap 不能违反目标对象的不变量，否则抛 `TypeError`。
3. `set`、`deleteProperty` 等 trap 应返回表示成功与否的布尔值。
4. `Reflect.get/set` 的 receiver 对 getter、setter 和继承语义很重要。
5. proxy 与 target 身份不同，拿到 target 可绕过代理。
6. 内置对象内部槽与类私有字段可能导致“透明代理”失效。
7. Vue 3 深层响应式仍需要按需递归代理，并非一个浅 Proxy 自动处理全部层级。

## 14.13 面试回答模板

> Proxy 是对象操作级拦截器，共有 get、set、has、deleteProperty、ownKeys、描述符、原型、扩展性、apply 和 construct 等 13 个 trap。Reflect 提供与这些内部操作对应的标准函数，适合在 trap 中透传默认行为，尤其 receiver 能保证 getter/setter 的 this 语义。Proxy 必须遵守目标对象不变量。Vue 3 使用 Proxy 在读取时 track 依赖、修改时 trigger 更新，并用 WeakMap 组织依赖和缓存代理，相比 defineProperty 能更自然地处理新增、删除、数组和集合操作。

# 十五、对象序列化

## 15.1 JSON 的数据范围

JSON 能表达：

- 对象：键必须是字符串。
- 数组。
- 字符串。
- 有限数字。
- 布尔值。
- `null`。

JSON 不是 JavaScript 对象字面量的完整子集，不能原生表达 `undefined`、函数、Symbol、BigInt、Date、RegExp、Map、Set、循环引用、原型或属性描述符。

## 15.2 `JSON.stringify()` 基础

```js
const json = JSON.stringify({ name: 'Alice', age: 20 });
// '{"name":"Alice","age":20}'
```

完整签名：

```js
JSON.stringify(value, replacer, space);
```

- `value`：待序列化值。
- `replacer`：函数或属性白名单数组。
- `space`：缩进字符串或数字，美化输出。

## 15.3 对象属性中的特殊值

对象属性值为 `undefined`、函数或 Symbol 时，该属性被忽略：

```js
JSON.stringify({
  a: undefined,
  b: function () {},
  c: Symbol('c'),
  d: 1,
});
// '{"d":1}'
```

Symbol 键始终不会出现在普通 JSON 结果中，即使传给 replacer 白名单也不行。

## 15.4 数组元素中的特殊值

数组中的 `undefined`、函数和 Symbol 会变成 `null`，以保留数组位置：

```js
JSON.stringify([undefined, function () {}, Symbol('x'), 1]);
// '[null,null,null,1]'
```

数组只序列化从 `0` 到 `length - 1` 的元素，不会像普通对象那样序列化额外字符串属性。

## 15.5 顶层特殊值

```js
JSON.stringify(undefined);     // undefined（不是字符串）
JSON.stringify(function () {}); // undefined
JSON.stringify(Symbol('x'));   // undefined
```

## 15.6 数字规则

```js
JSON.stringify({
  nan: NaN,
  infinity: Infinity,
  negativeInfinity: -Infinity,
  negativeZero: -0,
});
// '{"nan":null,"infinity":null,"negativeInfinity":null,"negativeZero":0}'
```

非有限数字变为 `null`，`-0` 变为 `0`。

## 15.7 只处理可枚举自身字符串属性

```js
const symbol = Symbol('id');
const obj = { visible: 1, [symbol]: 2 };

Object.defineProperty(obj, 'hidden', {
  value: 3,
  enumerable: false,
});

JSON.stringify(obj); // '{"visible":1}'
```

继承属性、不可枚举属性和 Symbol 键都不参与。属性访问过程可能触发 getter 或 Proxy trap。

## 15.8 `toJSON()`

如果值拥有 `toJSON` 方法，`JSON.stringify` 会先调用它，并序列化其返回值：

```js
const user = {
  name: 'Alice',
  password: 'secret',

  toJSON(key) {
    return { name: this.name };
  },
};

JSON.stringify(user); // '{"name":"Alice"}'
```

`toJSON` 接收当前属性键；顶层调用时键是空字符串 `""`。

Date 默认实现了 `toJSON()`，通常返回 ISO 字符串：

```js
JSON.stringify({ date: new Date('2020-01-01T00:00:00Z') });
// '{"date":"2020-01-01T00:00:00.000Z"}'
```

所以 JSON 往返后得到字符串，不会自动恢复 Date。

## 15.9 replacer 函数

replacer 函数可过滤或转换值：

```js
const json = JSON.stringify(
  { name: 'Alice', password: 'secret', age: 20 },
  (key, value) => {
    if (key === 'password') return undefined;
    if (typeof value === 'number') return value * 2;
    return value;
  },
);
```

调用特点：

- 首次会用包装对象调用，key 为 `""`，value 为顶层值。
- 按层级递归调用。
- 返回 `undefined` 通常会让对象属性被忽略；数组位置则变成 `null`。
- 使用普通函数时，`this` 是持有当前属性的对象；箭头函数不会获得该动态 `this`。

## 15.10 replacer 数组

作为对象属性白名单：

```js
JSON.stringify(
  { name: 'Alice', age: 20, password: 'secret' },
  ['name', 'age'],
);
// '{"name":"Alice","age":20}'
```

主要使用字符串和数字元素，数字会转成字符串键。它针对对象属性名，不是按数组索引过滤数组元素。

## 15.11 `space` 参数

```js
JSON.stringify({ a: 1, b: 2 }, null, 2);
```

数字缩进最多按 10 个空格处理；字符串缩进也最多使用前 10 个字符。美化 JSON 增加体积，通常用于日志、配置和调试，不用于追求最小网络体积的场景。

## 15.12 `JSON.parse()` 与 reviver

```js
const value = JSON.parse('{"name":"Alice","age":20}');
```

reviver 在解析后自底向上处理属性，可以转换或删除值：

```js
const value = JSON.parse(
  '{"createdAt":"2020-01-01T00:00:00.000Z"}',
  (key, value) => {
    if (key === 'createdAt') return new Date(value);
    return value;
  },
);

value.createdAt instanceof Date; // true
```

返回 `undefined` 会删除对应属性：

```js
JSON.parse('{"a":1,"b":2}', (key, value) =>
  key === 'b' ? undefined : value,
);
// { a: 1 }
```

reviver 同样会对顶层使用空字符串键，因此不应不加区分地删除 `key === ""` 的值。

## 15.13 循环引用处理

默认行为：

```js
const obj = {};
obj.self = obj;

// JSON.stringify(obj); // TypeError: Converting circular structure to JSON
```

简单做法是使用 WeakSet replacer 丢弃重复对象：

```js
function createCircularReplacer() {
  const seen = new WeakSet();

  return (key, value) => {
    if (value !== null && typeof value === 'object') {
      if (seen.has(value)) return '[Circular]';
      seen.add(value);
    }

    return value;
  };
}

JSON.stringify(obj, createCircularReplacer(), 2);
```

但这会把“循环引用”和“同一对象在两个位置被共享引用”都当成重复，并且不能还原原图结构。真正可逆的图序列化需要给对象分配 id，再用引用标记表示边，或使用成熟的专用格式/库。

## 15.14 BigInt 序列化

默认会抛错：

```js
// JSON.stringify({ id: 1n }); // TypeError
```

可以用 replacer 转字符串，并使用显式协议标记：

```js
const json = JSON.stringify(
  { id: 123n },
  (key, value) =>
    typeof value === 'bigint'
      ? { $type: 'BigInt', value: value.toString() }
      : value,
);

const result = JSON.parse(json, (key, value) =>
  value?.$type === 'BigInt'
    ? BigInt(value.value)
    : value,
);
```

不要仅凭字符串以 `n` 结尾就恢复 BigInt，否则普通业务字符串可能被误判。

也可以给 `BigInt.prototype` 添加 `toJSON`，但修改全局内置原型会影响整个运行环境，一般不推荐在库代码中这样做。

## 15.15 Map、Set 的序列化

默认：

```js
JSON.stringify(new Map([['a', 1]])); // '{}'
JSON.stringify(new Set([1, 2]));     // '{}'
```

可以显式转换并添加类型标记：

```js
function replacer(key, value) {
  if (value instanceof Map) {
    return { $type: 'Map', entries: [...value] };
  }

  if (value instanceof Set) {
    return { $type: 'Set', values: [...value] };
  }

  return value;
}

function reviver(key, value) {
  if (value?.$type === 'Map') return new Map(value.entries);
  if (value?.$type === 'Set') return new Set(value.values);
  return value;
}
```

真实协议还要防止 `$type` 与用户数据冲突，并做输入验证。

## 15.16 JSON 与安全

- `JSON.parse` 不会像 `eval` 那样执行任意 JavaScript，解析 JSON 应优先使用它。
- 解析成功不代表数据可信，仍要校验字段、类型、范围和权限。
- 把解析结果深度合并到普通对象时仍要防范 `__proto__` 等原型污染路径。
- reviver 会运行自己的代码，不应把不可信输入拼接成函数。
- 大体积或深嵌套 JSON 可能造成内存和 CPU 压力，需要限制输入规模。

## 15.17 本章易错点

1. 对象属性中的 `undefined`/函数/Symbol 被忽略，数组中则变成 `null`。
2. `NaN` 和无穷值变为 `null`，`-0` 变为 `0`。
3. Date 因 `toJSON` 变成字符串，不会自动恢复。
4. JSON 只处理可枚举自身字符串属性，不包含 Symbol 键。
5. replacer 首次和 reviver 最后都会处理空字符串顶层键。
6. 循环替换为 `[Circular]` 不等于可逆序列化。
7. BigInt 默认无法序列化，转换时应使用无歧义类型协议。

## 15.18 面试回答模板

> JSON.stringify 只序列化可枚举自身字符串属性。对象属性中的 undefined、函数和 Symbol 会被忽略，数组中的这些值变成 null；NaN 和 Infinity 也变成 null；Date 通过 toJSON 变成 ISO 字符串；Map、Set 默认是空对象；BigInt 和循环引用默认抛错。toJSON 可定制单个对象输出，replacer 可过滤或转换，JSON.parse 的 reviver 可自底向上恢复类型。复杂类型应设计显式类型标记，循环图若要可逆则需要 id 与引用协议。

# 十六、对象的内存模型

## 16.1 “栈与堆”是教学模型，不是语言保证

常见入门说法：

- 基本类型值存储在栈中。
- 对象存储在堆中，变量在栈中保存对象地址。

这能帮助理解复制与共享，但并非 ECMAScript 规范规定的真实布局。规范描述的是值、引用关系和执行语义，不要求引擎必须把某类值固定放在栈或堆。现代引擎会使用：

- 调用栈和执行帧。
- 托管堆。
- 寄存器。
- 指针压缩与值标记。
- 逃逸分析、标量替换等优化。
- 不同代的垃圾回收区域。

因此面试中可用栈/堆作概念模型，但最好补一句“实际存储由引擎实现和优化决定”。

## 16.2 基本值与对象值的复制

基本值赋值后，两个变量的值相互独立：

```js
let a = 1;
let b = a;
b = 2;

a; // 1
```

对象赋值复制的是同一个对象身份的引用值：

```js
const a = { count: 1 };
const b = a;

b.count = 2;
a.count; // 2
```

但变量 `a` 与 `b` 本身仍是两个独立绑定；让 `b` 指向新对象不会改变 `a`：

```js
let a = { count: 1 };
let b = a;

b = { count: 2 };
a.count; // 1
```

## 16.3 JavaScript 参数始终按值传递

更严谨的说法是：JavaScript 始终按值传参。传入对象时，被复制的值是一个指向同一对象的引用值，所以函数内可以修改共享对象，却不能通过重绑定形参来替换外部变量。

```js
function update(user) {
  user.name = 'Bob';       // 修改共享对象，外部可见
  user = { name: 'Carol' }; // 只重绑定局部形参，外部不可见
}

const user = { name: 'Alice' };
update(user);

user.name; // "Bob"
```

有些资料称之为“按共享传递”（call by sharing），是为了强调多个引用共享同一对象；它不是传统意义上的“按引用传递”，因为函数不能直接改变调用者变量的绑定。

## 16.4 可达性与垃圾回收

JavaScript 使用自动垃圾回收。核心概念是可达性：从根对象出发仍能沿引用访问到的对象，通常被认为仍然存活。

常见根包括：

- 当前执行上下文中的局部变量。
- 全局对象及其属性。
- 活跃闭包捕获的变量。
- 正在处理的任务、事件回调等宿主引用。

```js
let user = { name: 'Alice' };
user = null;
```

如果原对象没有其他强引用，它就变成不可达，并可能在未来某次 GC 中回收。“可能”很重要：回收时间由引擎决定，无法精确预测。

## 16.5 标记清除与分代回收

概念上的标记清除：

1. 从根开始标记可达对象。
2. 遍历它们引用的其他对象。
3. 未被标记的对象视为不可达。
4. 回收其内存。

现代引擎还常采用：

- 分代回收：新对象通常进入新生代，多次存活后晋升老生代。
- 增量标记：把长时间工作拆成小片，减少停顿。
- 并发/并行回收：部分 GC 工作与主线程并发或由多个线程处理。
- 内存压缩：移动存活对象以减少碎片。

这些属于引擎实现知识，不要把某个版本 V8 的具体参数当作 JavaScript 语言保证。

## 16.6 循环引用并不必然泄漏

```js
function createCycle() {
  const a = {};
  const b = {};

  a.b = b;
  b.a = a;
}

createCycle();
```

函数结束后，如果外部无法再访问 `a` 和 `b`，现代可达性 GC 可以整体回收这个循环。循环引用本身不是泄漏；真正问题是对象仍被某个根或长生命周期对象意外引用。

## 16.7 常见内存泄漏场景

### 意外全局变量

```js
// 非严格模式中的错误赋值可能创建全局属性
// leakedData = new Array(1_000_000);
```

使用模块、严格模式、lint 规则，并明确声明变量。

### 未清理的定时器

```js
const largeData = new Array(1_000_000);

const timer = setInterval(() => {
  console.log(largeData.length);
}, 1000);

// 不再需要时
clearInterval(timer);
```

回调闭包引用 `largeData`，定时器存活期间数据可能一直可达。

### 未移除的事件监听器

```js
function mount(button) {
  const state = { /* 大量数据 */ };

  const handleClick = () => {
    console.log(state);
  };

  button.addEventListener('click', handleClick);

  return () => {
    button.removeEventListener('click', handleClick);
  };
}
```

组件卸载时应执行清理。也可在支持的 API 中使用 `AbortController` 管理生命周期：

```js
const controller = new AbortController();

button.addEventListener('click', handleClick, {
  signal: controller.signal,
});

controller.abort();
```

### 脱离 DOM 的节点

```js
let detached = document.querySelector('#panel');
detached.remove();

// 若不再使用，应清除额外引用
detached = null;
```

从 DOM 树移除不等于立刻可回收；JavaScript 变量、监听器或缓存仍可能引用它。

### 无界缓存

```js
const cache = new Map();

function remember(key, value) {
  cache.set(key, value); // 如果永不淘汰，可能持续增长
}
```

解决方案包括容量上限、LRU、TTL、显式删除；若键是对象且数据应随键生命周期消失，可评估 WeakMap。

### 闭包保留大对象

```js
function createHandler() {
  const largeData = loadLargeData();

  return () => largeData.summary;
}
```

闭包不是泄漏，只有当其生命周期超出预期、且捕获了不再需要的数据时才构成问题。可只捕获真正需要的小值：

```js
function createHandler() {
  const { summary } = loadLargeData();
  return () => summary;
}
```

### 未终止的订阅和观察器

WebSocket、EventSource、RxJS subscription、MutationObserver、ResizeObserver、IntersectionObserver 等都可能维持回调和状态引用，应在生命周期结束时 `close`、`unsubscribe` 或 `disconnect`。

### Promise 与异步任务

长时间 pending 的 Promise 及其回调可能保留闭包数据。普通已完成 Promise 通常不会永久泄漏，但无限等待、不断积累的任务队列和未取消请求可能造成内存持续增长。

## 16.8 WeakMap 不等于自动解决所有泄漏

```js
const cache = new WeakMap();
cache.set(objectKey, largeValue);
```

只有当 `objectKey` 在别处不可达时，条目才有机会被回收。如果键本身仍被全局数组或其他 Map 强引用，WeakMap 不会解决问题。并且若 value 通过其他路径被强引用，它仍然存活。

## 16.9 内存泄漏排查思路

1. 稳定复现操作，例如反复进入/退出页面或挂载/卸载组件。
2. 观察内存是否在 GC 后仍持续增长，不只看瞬时峰值。
3. 获取多个 Heap Snapshot，对比新增与保留对象。
4. 从异常对象查看 retaining path，找到是谁让它仍可从根访问。
5. 检查监听器、定时器、订阅、缓存、DOM 引用和闭包。
6. 修复后重复同样操作验证对象数量能回落。

常见工具：Chrome DevTools Memory 面板、Performance 面板、Node.js heap snapshot、分配采样器和运行时内存指标。

## 16.10 对象形状与隐藏类

许多现代引擎会根据对象属性结构建立内部“形状”或隐藏类，并用内联缓存优化属性访问。以一致顺序初始化相同结构的对象通常更利于优化：

```js
function Point(x, y) {
  this.x = x;
  this.y = y;
}
```

大量随机增删属性、让同一调用点接收过多结构完全不同的对象，可能使优化困难。但这是引擎层性能知识：

- 不同引擎策略不同。
- 优化细节会随版本变化。
- 不应为了猜测隐藏类而牺牲代码正确性和可读性。
- 遇到真实性能问题应先 profile，再定向优化。

## 16.11 大对象释放的正确理解

```js
largeObject = null;
```

这只移除一个引用，不会强制立即 GC。若还有其他引用，对象仍然可达；即使已经不可达，回收时机也由引擎决定。通常无需也无法在浏览器业务代码中主动强制垃圾回收。

## 16.12 本章易错点

1. “基本类型一定在栈、对象一定在堆”只是简化模型，不是规范保证。
2. JavaScript 始终按值传参；对象参数复制的是共享对象的引用值。
3. 循环引用不等于泄漏，不可达的环可以被现代 GC 回收。
4. 真正的泄漏是已经无用的数据仍从根可达。
5. 设为 `null` 只断开一个引用，不会强制立即回收。
6. WeakMap 只有在键不再被其他地方强引用时才发挥弱键价值。

## 16.13 面试回答模板

> 栈和堆是理解 JavaScript 内存的常用简化模型，但规范不规定具体布局，实际由引擎优化。JavaScript 参数始终按值传递，对象传参复制的是指向同一对象的引用值，所以函数能修改共享对象，却不能通过重绑形参替换调用方变量。现代 GC 以可达性为核心，循环引用只要整体不可达也能回收。常见泄漏来自未清理监听器、定时器和订阅、无界缓存、脱离 DOM 节点及长生命周期闭包；排查时应对比堆快照并查看 retaining path。
