# JavaScript 函数专题 — 完整笔记

> 分类：js-basics

## 一句话总结

JavaScript 中函数是一等公民：它既可以被调用，也可以像普通值一样被赋值、传参、返回和挂载属性。函数专题的核心，不只是会写函数，而是理解函数在作用域、闭包、this、原型、异步和函数式编程中的行为边界。

---

## 1. 函数基础

### 1.1 什么是函数

函数是一段可以被重复执行的代码块。它可以接收输入参数，执行内部逻辑，并通过 `return` 返回结果。

```js
function add(a, b) {
  return a + b;
}

add(1, 2); // 3
```

### 1.2 函数的作用

- 复用代码，避免重复逻辑。
- 封装细节，对外暴露稳定接口。
- 抽象行为，把“怎么做”隐藏在函数内部。
- 拆分复杂问题，让程序结构更清晰。
- 支持回调、高阶函数、闭包、异步编程等能力。

### 1.3 函数的组成

```js
function fn(a, b) {
  const result = a + b;
  return result;
}
```

| 组成 | 说明 |
|------|------|
| 函数名 | 用于标识函数，方便调用和调试 |
| 参数 | 函数接收外部输入的入口 |
| 函数体 | 函数真正执行的代码 |
| 返回值 | 函数执行完成后输出的结果 |

### 1.4 函数调用流程

调用函数时，引擎大致会做这些事：

1. 创建新的函数执行上下文。
2. 初始化参数、局部变量、作用域链和 `this`。
3. 执行函数体代码。
4. 遇到 `return` 时返回结果。
5. 函数执行结束后，普通局部变量通常被回收；如果被闭包引用，则不会立即回收。

```js
function test(x) {
  const y = 2;
  return x + y;
}

test(1);
```

### 1.5 函数也是对象

在 JavaScript 中，函数本质上是可调用对象。

```js
function fn() {}

fn.name; // "fn"
fn.length; // 0，形参数量
fn.custom = 'hello';

console.log(fn.custom); // "hello"
```

函数对象有两个重要内部能力：

- `[[Call]]`：支持普通调用，例如 `fn()`。
- `[[Construct]]`：支持构造调用，例如 `new Fn()`。

不是所有函数都有 `[[Construct]]`。箭头函数没有这个内部方法，所以不能被 `new` 调用。

### 1.6 面试回答模板

如果被问“JavaScript 中函数有什么特点”，可以这样答：

> JavaScript 中函数是一等公民，本质是可调用对象。它可以像普通值一样赋值给变量、作为参数传入、作为返回值返回，也可以拥有属性。函数调用时会创建执行上下文，涉及参数初始化、作用域链、this 绑定和返回值处理。函数还是闭包、回调、高阶函数、异步编程和函数式编程的基础。

## 2. 函数的定义方式

### 2.1 函数声明

```js
function fn() {
  console.log('fn');
}
```

特点：

- 会被整体提升。
- 可以先调用，后声明。
- 有自己的 `this`。
- 有 `arguments`。
- 可以作为构造函数使用。

```js
sayHi();

function sayHi() {
  console.log('hi');
}
```

### 2.2 函数表达式

```js
const fn = function () {
  console.log('fn');
};
```

特点：

- 函数本身不会像函数声明一样整体提升。
- 是否能提前访问，取决于变量声明方式。
- 常用于把函数当作值保存、传参或返回。

```js
console.log(fn); // ReferenceError，const 有暂时性死区

const fn = function () {};
```

如果使用 `var`：

```js
console.log(fn); // undefined
fn(); // TypeError: fn is not a function

var fn = function () {};
```

### 2.3 具名函数表达式

```js
const fn = function inner() {
  console.log(inner.name);
};

fn(); // "inner"
```

`inner` 只在函数内部可见，外部不能直接访问。

```js
const fn = function inner() {};

console.log(inner); // ReferenceError
```

具名函数表达式的优点：

- 调试堆栈更清晰。
- 递归调用时可以在函数内部引用自身。

### 2.4 箭头函数

```js
const fn = () => {
  console.log('arrow');
};
```

特点：

- 没有自己的 `this`。
- 没有自己的 `arguments`。
- 不能作为构造函数。
- 没有 `prototype`。
- 更适合短回调和需要继承外层 `this` 的场景。

```js
const obj = {
  name: 'Alice',
  sayLater() {
    setTimeout(() => {
      console.log(this.name);
    }, 100);
  }
};

obj.sayLater(); // "Alice"
```

### 2.5 Function 构造函数

```js
const add = new Function('a', 'b', 'return a + b');

add(1, 2); // 3
```

特点：

- 参数和函数体都是字符串。
- 函数体在全局作用域中执行。
- 可读性差，性能差，有安全风险。
- 实际开发中很少使用。

```js
const x = 1;

function outer() {
  const x = 2;
  const fn = new Function('return x');
  return fn();
}

outer(); // 1，访问的是全局 x，不是 outer 内部的 x
```

### 2.6 IIFE 立即执行函数

```js
(function () {
  const privateValue = 1;
})();
```

作用：

- 创建独立作用域。
- 避免变量污染全局。
- 在早期没有块级作用域时很常用。

为什么要用括号包裹：

```js
function () {}(); // SyntaxError
```

函数声明必须有名字，且声明不能直接调用。括号把 `function` 转成函数表达式。

### 2.7 不同定义方式对比

| 方式 | 是否提升 | 有自己的 this | 有 arguments | 能否 new | 是否有 prototype |
|------|----------|---------------|---------------|----------|------------------|
| 函数声明 | 是，整体提升 | 是 | 是 | 是 | 是 |
| 函数表达式 | 变量按声明规则提升 | 是 | 是 | 是 | 是 |
| 箭头函数 | 变量按声明规则提升 | 否 | 否 | 否 | 否 |
| Function 构造函数 | 变量按声明规则提升 | 是 | 是 | 是 | 是 |

### 2.8 易错点

- 函数声明可以先调用，函数表达式不一定可以。
- `var fn = function () {}` 提前调用是 `TypeError`，不是 `ReferenceError`。
- 箭头函数不是普通函数的简写，它的 `this`、`arguments`、构造能力都不同。
- `new Function` 创建的函数无法捕获当前局部作用域。

## 3. 函数参数

### 3.1 普通参数

```js
function add(a, b) {
  return a + b;
}
```

JavaScript 不要求实参和形参数量一致。

```js
function fn(a, b) {
  console.log(a, b);
}

fn(1); // 1 undefined
fn(1, 2, 3); // 1 2，多余参数可以通过 arguments 或 rest 获取
```

### 3.2 默认参数

```js
function createUser(name = 'anonymous') {
  return { name };
}

createUser(); // { name: 'anonymous' }
```

默认参数只在对应实参为 `undefined` 时生效。

```js
function fn(x = 1) {
  console.log(x);
}

fn(undefined); // 1
fn(null); // null
fn(0); // 0
fn(''); // ''
```

默认参数可以引用前面的参数：

```js
function add(a, b = a) {
  return a + b;
}

add(2); // 4
```

不能引用后面的参数：

```js
function fn(a = b, b = 1) {
  return a + b;
}

fn(); // ReferenceError
```

### 3.3 剩余参数 `...rest`

```js
function sum(...nums) {
  return nums.reduce((total, num) => total + num, 0);
}

sum(1, 2, 3); // 6
```

特点：

- 收集剩余实参。
- 得到的是一个真正的数组。
- 必须放在参数列表最后。

```js
function fn(a, ...rest) {
  console.log(a);
  console.log(rest);
}

fn(1, 2, 3); // 1 [2, 3]
```

### 3.4 参数解构

对象参数解构：

```js
function createUser({ name, age }) {
  return `${name}-${age}`;
}

createUser({ name: 'Alice', age: 18 });
```

数组参数解构：

```js
function getPoint([x, y]) {
  return { x, y };
}

getPoint([10, 20]); // { x: 10, y: 20 }
```

配合默认值：

```js
function request({ url, method = 'GET', headers = {} } = {}) {
  return { url, method, headers };
}

request(); // { url: undefined, method: 'GET', headers: {} }
```

### 3.5 `arguments`

`arguments` 是普通函数内部自动存在的类数组对象，保存所有实参。

```js
function fn() {
  console.log(arguments);
  console.log(arguments.length);
}

fn(1, 2, 3);
```

特点：

- 只有普通函数有，箭头函数没有自己的 `arguments`。
- 是类数组，有索引和 `length`，但没有数组方法。
- 可以用 `Array.from(arguments)` 转成数组。

```js
function sum() {
  return Array.from(arguments).reduce((total, num) => total + num, 0);
}
```

现代写法优先使用剩余参数：

```js
function sum(...nums) {
  return nums.reduce((total, num) => total + num, 0);
}
```

### 3.6 参数传递机制

JavaScript 中参数传递可以理解为：值传递。

基本类型传的是值的副本：

```js
let x = 1;

function change(num) {
  num = 2;
}

change(x);
console.log(x); // 1
```

引用类型传的是引用地址的副本：

```js
const obj = { count: 1 };

function change(target) {
  target.count = 2;
}

change(obj);
console.log(obj.count); // 2
```

但重新赋值形参不会影响外部变量：

```js
const obj = { count: 1 };

function change(target) {
  target = { count: 2 };
}

change(obj);
console.log(obj.count); // 1
```

面试中可以说得更准确一点：对象传参是“共享传递”或“引用地址的值传递”，不是直接把变量本身传进去。

### 3.7 形参和实参的关系

非严格模式下，简单参数列表中的形参和 `arguments` 会存在映射关系：

```js
function fn(a) {
  arguments[0] = 2;
  console.log(a);
}

fn(1); // 非严格模式下输出 2
```

严格模式下没有这种映射：

```js
function fn(a) {
  'use strict';
  arguments[0] = 2;
  console.log(a);
}

fn(1); // 1
```

实际开发不要依赖这种行为。

### 3.8 易错点

- 默认参数只对 `undefined` 生效，不对 `null`、`0`、空字符串生效。
- `...rest` 必须是最后一个参数。
- `arguments` 不是数组。
- 箭头函数没有自己的 `arguments`。
- 对象作为参数时，修改对象属性会影响外部；重新给形参赋值不会影响外部。

## 4. 返回值

### 4.1 `return` 的作用

`return` 有两个作用：

- 返回函数执行结果。
- 立即结束函数执行。

```js
function fn() {
  return 1;
  console.log('不会执行');
}
```

### 4.2 没有 `return` 时返回什么

普通函数没有显式 `return`，默认返回 `undefined`。

```js
function fn() {}

console.log(fn()); // undefined
```

只有 `return;` 也返回 `undefined`。

```js
function fn() {
  return;
}

console.log(fn()); // undefined
```

### 4.3 返回基本类型

```js
function getName() {
  return 'Alice';
}

function isAdult(age) {
  return age >= 18;
}
```

### 4.4 返回对象

```js
function createUser(name) {
  return {
    name,
    role: 'user'
  };
}
```

注意自动分号插入：

```js
function createUser() {
  return
  {
    name: 'Alice'
  };
}

createUser(); // undefined
```

正确写法：

```js
function createUser() {
  return {
    name: 'Alice'
  };
}
```

### 4.5 返回函数

返回函数是闭包和高阶函数的基础。

```js
function createAdder(base) {
  return function (num) {
    return base + num;
  };
}

const add10 = createAdder(10);
add10(5); // 15
```

### 4.6 提前结束函数

```js
function submit(form) {
  if (!form.username) {
    return;
  }

  // 后续逻辑
}
```

这种写法叫提前返回，可以减少嵌套，让代码更清晰。

### 4.7 构造函数中的返回值

构造函数被 `new` 调用时，返回值规则比较特殊。

返回基本类型会被忽略：

```js
function Person(name) {
  this.name = name;
  return 1;
}

const p = new Person('Alice');
console.log(p.name); // "Alice"
```

返回对象会覆盖默认返回的实例：

```js
function Person(name) {
  this.name = name;
  return { name: 'Bob' };
}

const p = new Person('Alice');
console.log(p.name); // "Bob"
```

### 4.8 易错点

- `return` 后面换行可能触发自动分号插入。
- 普通函数没有返回值时默认返回 `undefined`。
- 构造函数返回对象会覆盖实例，返回基本类型不会。
- 箭头函数简写对象返回值时，需要用括号包裹对象。

```js
const createUser = () => ({ name: 'Alice' });
```

## 5. 作用域与作用域链

### 5.1 全局作用域

全局作用域中的变量在整个程序中都可以访问。

```js
const globalName = 'global';

function fn() {
  console.log(globalName);
}
```

在浏览器中，使用 `var` 声明的全局变量会成为 `window` 的属性；`let` 和 `const` 不会。

```js
var a = 1;
let b = 2;

window.a; // 1
window.b; // undefined
```

### 5.2 函数作用域

函数内部声明的变量，只能在函数内部访问。

```js
function fn() {
  var x = 1;
}

console.log(x); // ReferenceError
```

### 5.3 块级作用域

`let`、`const`、`class` 存在块级作用域。

```js
if (true) {
  let x = 1;
  const y = 2;
}

console.log(x); // ReferenceError
```

`var` 没有块级作用域：

```js
if (true) {
  var x = 1;
}

console.log(x); // 1
```

### 5.4 词法作用域

JavaScript 使用词法作用域，也叫静态作用域。变量查找规则在函数定义时由代码位置决定，而不是调用位置决定。

```js
const name = 'global';

function foo() {
  console.log(name);
}

function bar() {
  const name = 'bar';
  foo();
}

bar(); // "global"
```

`foo` 定义在全局，所以它查找的是全局的 `name`。

### 5.5 作用域链

当函数访问变量时，会从当前作用域开始查找：

```text
当前作用域 -> 外层作用域 -> 再外层作用域 -> 全局作用域 -> 报错
```

```js
const a = 1;

function outer() {
  const b = 2;

  function inner() {
    const c = 3;
    console.log(a, b, c);
  }

  inner();
}
```

`inner` 的作用域链：

```text
inner 作用域 -> outer 作用域 -> 全局作用域
```

### 5.6 变量查找规则

```js
const x = 1;

function outer() {
  const x = 2;

  function inner() {
    const x = 3;
    console.log(x);
  }

  inner();
}

outer(); // 3
```

查找变量时，先找最近的作用域，找到后停止，不会继续向外找。

### 5.7 执行上下文

函数执行时会创建执行上下文。

```text
执行上下文 = {
  词法环境,
  变量环境,
  this 绑定
}
```

创建阶段会处理声明：

| 声明 | 创建阶段行为 | 访问表现 |
|------|--------------|----------|
| `var` | 提升并初始化为 `undefined` | 声明前访问是 `undefined` |
| `let` / `const` | 提升但不初始化 | 声明前访问报错 |
| `function` | 整体提升并初始化为函数 | 声明前可调用 |

### 5.8 暂时性死区 TDZ

`let` 和 `const` 从作用域开始到声明语句执行前，这段区域叫暂时性死区。

```js
console.log(x); // ReferenceError
let x = 1;
```

注意：不是没有提升，而是提升了但不能访问。

### 5.9 易错点

- 作用域链由函数定义位置决定，不由调用位置决定。
- `var` 是函数作用域，`let` / `const` 是块级作用域。
- `let` / `const` 也会提升，只是在初始化前不能访问。
- 内层作用域变量会遮蔽外层同名变量。

## 6. 闭包

### 6.1 什么是闭包

闭包是指：函数能够记住并访问它定义时所在的词法作用域，即使这个函数在原作用域之外执行。

```js
function outer() {
  const count = 1;

  return function inner() {
    console.log(count);
  };
}

const fn = outer();
fn(); // 1
```

`outer` 已经执行完了，但 `inner` 依然能访问 `count`，这就是闭包。

### 6.2 闭包产生的原因

闭包产生依赖两个条件：

- 函数嵌套。
- 内层函数引用外层函数的变量，并被外部持有。

```js
function outer() {
  const value = 'hello';

  function inner() {
    return value;
  }

  return inner;
}
```

### 6.3 为什么变量不会被回收

正常情况下，函数执行结束后，局部变量会被垃圾回收。

但如果内部函数引用了这些变量，并且内部函数还在外部被使用，引擎会判断这些变量仍然可达，因此不会回收。

### 6.4 闭包的典型场景

#### 数据私有化

```js
function createCounter() {
  let count = 0;

  return {
    increment() {
      count++;
    },
    getCount() {
      return count;
    }
  };
}

const counter = createCounter();
counter.increment();
counter.getCount(); // 1
```

外部不能直接访问 `count`，只能通过暴露的方法操作。

#### 函数工厂

```js
function createFormatter(prefix) {
  return function (value) {
    return `${prefix}: ${value}`;
  };
}

const error = createFormatter('Error');
error('Not found'); // "Error: Not found"
```

#### 回调函数

```js
function delayLog(message) {
  setTimeout(function () {
    console.log(message);
  }, 1000);
}

delayLog('hello');
```

`setTimeout` 的回调在未来执行，但仍然能访问 `message`。

#### 防抖节流

防抖和节流都需要用闭包保存跨多次调用共享的状态，例如 `timer` 和 `lastTime`。

### 6.5 闭包的优点

- 可以保存函数执行后的变量。
- 可以实现数据私有化。
- 可以复用参数和状态。
- 是高阶函数、函数式编程和异步回调的重要基础。

### 6.6 闭包的缺点

- 被闭包引用的变量不会被立即回收，可能增加内存占用。
- 滥用闭包会让变量生命周期变长，排查问题更困难。

解决思路：

```js
let fn = createLargeClosure();

// 使用完后解除引用
fn = null;
```

### 6.7 常见闭包面试题

#### 循环中的 `var`

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => {
    console.log(i);
  }, 100);
}

// 3 3 3
```

原因：

- `var` 没有块级作用域。
- 三个回调共享同一个 `i`。
- 定时器执行时，循环已经结束，`i` 变成了 3。

解决方式一：使用 `let`

```js
for (let i = 0; i < 3; i++) {
  setTimeout(() => {
    console.log(i);
  }, 100);
}

// 0 1 2
```

解决方式二：IIFE

```js
for (var i = 0; i < 3; i++) {
  (function (j) {
    setTimeout(() => {
      console.log(j);
    }, 100);
  })(i);
}
```

解决方式三：`setTimeout` 第三个参数

```js
for (var i = 0; i < 3; i++) {
  setTimeout((j) => {
    console.log(j);
  }, 100, i);
}
```

### 6.8 面试回答模板

> 闭包是函数和它定义时词法作用域的组合。即使外层函数执行结束，只要内部函数还被外部引用，它仍然可以访问外层函数中的变量。闭包常用于数据私有化、函数工厂、回调、防抖节流等场景。缺点是会延长变量生命周期，滥用可能导致内存占用增加。

## 7. `this`

### 7.1 `this` 是什么

`this` 是函数执行时自动生成的一个绑定，通常指向当前调用这个函数的对象。

核心原则：

> 普通函数的 `this` 取决于调用方式，不取决于定义位置。箭头函数没有自己的 `this`，它的 `this` 来自定义时外层作用域。

### 7.2 默认绑定

独立调用函数时使用默认绑定。

```js
function fn() {
  console.log(this);
}

fn();
```

结果：

- 非严格模式：浏览器中指向 `window`。
- 严格模式：指向 `undefined`。

```js
function fn() {
  'use strict';
  console.log(this);
}

fn(); // undefined
```

### 7.3 隐式绑定

作为对象方法调用时，`this` 指向调用它的对象。

```js
const obj = {
  name: 'Alice',
  say() {
    console.log(this.name);
  }
};

obj.say(); // "Alice"
```

只看函数调用时点号前最近的对象。

```js
const a = {
  name: 'a',
  b: {
    name: 'b',
    say() {
      console.log(this.name);
    }
  }
};

a.b.say(); // "b"
```

### 7.4 隐式绑定丢失

赋值给变量后丢失：

```js
const obj = {
  name: 'Alice',
  say() {
    console.log(this.name);
  }
};

const fn = obj.say;
fn(); // this 不再是 obj
```

作为回调传入后丢失：

```js
setTimeout(obj.say, 100);
```

原因：传进去的是函数引用，真正调用时不是 `obj.say()`。

修复方式：

```js
setTimeout(() => obj.say(), 100);
setTimeout(obj.say.bind(obj), 100);
```

### 7.5 显式绑定

使用 `call`、`apply`、`bind` 明确指定 `this`。

```js
function say(city) {
  console.log(this.name, city);
}

const user = { name: 'Alice' };

say.call(user, 'Beijing');
say.apply(user, ['Beijing']);

const boundSay = say.bind(user);
boundSay('Beijing');
```

### 7.6 `new` 绑定

构造函数通过 `new` 调用时，`this` 指向新创建的实例对象。

```js
function Person(name) {
  this.name = name;
}

const p = new Person('Alice');
console.log(p.name); // "Alice"
```

### 7.7 箭头函数绑定

箭头函数没有自己的 `this`，它会捕获定义时外层作用域的 `this`。

```js
const obj = {
  name: 'Alice',
  say() {
    const fn = () => {
      console.log(this.name);
    };

    fn();
  }
};

obj.say(); // "Alice"
```

`call`、`apply`、`bind` 不能改变箭头函数的 `this`。

```js
const obj = { name: 'Alice' };

const fn = () => {
  console.log(this);
};

fn.call(obj); // this 不会变成 obj
```

### 7.8 `this` 绑定优先级

```text
new 绑定 > 显式绑定 > 隐式绑定 > 默认绑定
```

箭头函数不参与这套规则。

```js
function Fn() {
  this.name = 'instance';
}

const obj = { name: 'obj' };
const BoundFn = Fn.bind(obj);

const instance = new BoundFn();
console.log(instance.name); // "instance"
```

### 7.9 严格模式下的 `this`

严格模式下，默认绑定的 `this` 是 `undefined`。

```js
function fn() {
  'use strict';
  console.log(this);
}

fn(); // undefined
```

这能避免默认绑定到全局对象导致的意外污染。

### 7.10 易错点

- `this` 看调用方式，不看定义位置。
- `obj.fn` 只是取函数引用，只有 `obj.fn()` 调用时才绑定到 `obj`。
- 多层对象调用时，`this` 是离函数最近的调用者。
- 箭头函数没有自己的 `this`，不适合作为对象方法。
- `bind` 返回新函数，不会立即执行。

## 8. 改变 `this` 指向

### 8.1 `call`

`call` 会立即调用函数，并逐个传入参数。

```js
function fn(a, b) {
  console.log(this.name, a, b);
}

fn.call({ name: 'Alice' }, 1, 2);
```

### 8.2 `apply`

`apply` 会立即调用函数，第二个参数是数组或类数组。

```js
function fn(a, b) {
  console.log(this.name, a, b);
}

fn.apply({ name: 'Alice' }, [1, 2]);
```

常见场景：

```js
const nums = [1, 2, 3];

Math.max.apply(null, nums); // 3
Math.max(...nums); // 现代写法
```

### 8.3 `bind`

`bind` 不会立即调用函数，而是返回一个绑定好 `this` 的新函数。

```js
function fn(a, b) {
  return this.value + a + b;
}

const bound = fn.bind({ value: 10 }, 1);

bound(2); // 13
```

`bind` 支持参数预设，这也是偏函数的一种形式。

### 8.4 三者区别

| 方法 | 是否立即执行 | 参数形式 | 返回值 |
|------|--------------|----------|--------|
| `call` | 是 | 逐个传参 | 原函数执行结果 |
| `apply` | 是 | 数组传参 | 原函数执行结果 |
| `bind` | 否 | 逐个传参，可预设 | 新函数 |

### 8.5 手写 `call`

下面是常见面试简化版，主要考察“临时挂载到对象上再调用”的思路。

```js
Function.prototype.myCall = function (context, ...args) {
  context = context == null ? globalThis : Object(context);

  const fnKey = Symbol('fn');
  context[fnKey] = this;

  const result = context[fnKey](...args);

  delete context[fnKey];
  return result;
};
```

关键点：

- `this` 是要被调用的原函数。
- 把函数临时挂到目标对象上，让它以 `obj.fn()` 形式调用。
- 使用 `Symbol` 避免属性名冲突。
- `null` / `undefined` 在这个简化版中默认绑定到 `globalThis`。
- 基本类型需要通过 `Object(context)` 包装。
- 严格模式下原生 `call` 对 `thisArg` 的处理更细，这里不展开到规范级完全模拟。

### 8.6 手写 `apply`

和 `call` 的区别主要是参数来源变成数组或类数组。

```js
Function.prototype.myApply = function (context, args) {
  context = context == null ? globalThis : Object(context);

  const fnKey = Symbol('fn');
  context[fnKey] = this;

  const result = args == null
    ? context[fnKey]()
    : context[fnKey](...args);

  delete context[fnKey];
  return result;
};
```

### 8.7 手写 `bind`

```js
Function.prototype.myBind = function (context, ...boundArgs) {
  const originalFn = this;

  function boundFn(...callArgs) {
    const isNewCall = this instanceof boundFn;
    const finalThis = isNewCall ? this : context;

    return originalFn.apply(finalThis, [...boundArgs, ...callArgs]);
  }

  if (originalFn.prototype) {
    boundFn.prototype = Object.create(originalFn.prototype);
  }

  return boundFn;
};
```

关键点：

- `bind` 返回新函数。
- 需要支持参数预设。
- 需要支持被 `new` 调用。
- 被 `new` 调用时，绑定的 `context` 应该失效，`this` 指向新实例。
- 需要维护原型链。

## 9. 箭头函数

### 9.1 箭头函数语法

```js
const add = (a, b) => {
  return a + b;
};
```

单表达式可以省略 `{}` 和 `return`：

```js
const add = (a, b) => a + b;
```

只有一个参数可以省略括号：

```js
const double = num => num * 2;
```

没有参数必须写括号：

```js
const getValue = () => 1;
```

### 9.2 返回对象的写法

箭头函数直接返回对象时，需要用括号包裹对象字面量。

```js
const createUser = () => ({ name: 'Alice' });
```

否则 `{}` 会被解析为函数体。

```js
const createUser = () => { name: 'Alice' };

createUser(); // undefined
```

### 9.3 箭头函数没有自己的 `this`

```js
const obj = {
  name: 'Alice',
  say: () => {
    console.log(this.name);
  }
};

obj.say(); // 通常不是 "Alice"
```

箭头函数定义时位于外层作用域，不会因为 `obj.say()` 调用而绑定到 `obj`。

正确写法：

```js
const obj = {
  name: 'Alice',
  say() {
    console.log(this.name);
  }
};
```

### 9.4 箭头函数没有 `arguments`

```js
const fn = () => {
  console.log(arguments); // ReferenceError 或访问外层 arguments
};
```

替代方案：

```js
const fn = (...args) => {
  console.log(args);
};
```

### 9.5 箭头函数不能作为构造函数

```js
const Person = (name) => {
  this.name = name;
};

new Person('Alice'); // TypeError: Person is not a constructor
```

原因：

- 箭头函数没有 `[[Construct]]`。
- 箭头函数没有 `prototype`。

### 9.6 箭头函数适合的场景

- 数组方法回调。
- Promise 回调。
- 定时器中需要继承外层 `this`。
- React 事件回调或类字段方法。
- 简短的纯计算函数。

```js
const nums = [1, 2, 3];
const doubled = nums.map(num => num * 2);
```

### 9.7 箭头函数不适合的场景

- 对象方法。
- 构造函数。
- 需要使用 `arguments` 的函数。
- 需要动态改变 `this` 的函数。
- 原型方法。

```js
function Person(name) {
  this.name = name;
}

Person.prototype.say = () => {
  console.log(this.name); // 错误示范
};
```

### 9.8 箭头函数口诀

> 箭头函数五无：无自己的 this、无 arguments、无 new、无 prototype、无 super。

更准确地说，箭头函数内部可以访问外层的 `this`、`arguments`、`super`、`new.target`，但它自身不创建这些绑定。

## 10. 高阶函数

### 10.1 什么是高阶函数

满足下面任意一个条件的函数，就是高阶函数：

- 接收函数作为参数。
- 返回一个函数。

```js
function operate(a, b, fn) {
  return fn(a, b);
}

operate(1, 2, (a, b) => a + b); // 3
```

### 10.2 函数作为参数

```js
function filter(list, predicate) {
  const result = [];

  for (const item of list) {
    if (predicate(item)) {
      result.push(item);
    }
  }

  return result;
}

filter([1, 2, 3], num => num > 1); // [2, 3]
```

### 10.3 函数作为返回值

```js
function withPrefix(prefix) {
  return function (text) {
    return `${prefix}${text}`;
  };
}

const addErrorPrefix = withPrefix('[Error] ');
addErrorPrefix('failed'); // "[Error] failed"
```

### 10.4 常见高阶函数

#### `map`

把数组每一项映射成新值，返回新数组。

```js
[1, 2, 3].map(num => num * 2); // [2, 4, 6]
```

#### `filter`

筛选符合条件的元素，返回新数组。

```js
[1, 2, 3].filter(num => num > 1); // [2, 3]
```

#### `reduce`

把数组归约成一个结果。

```js
[1, 2, 3].reduce((total, num) => total + num, 0); // 6
```

#### `forEach`

遍历数组，通常用于执行副作用，不返回新数组。

```js
[1, 2, 3].forEach(num => {
  console.log(num);
});
```

#### `some`

只要有一个元素满足条件，就返回 `true`。

```js
[1, 2, 3].some(num => num > 2); // true
```

#### `every`

所有元素都满足条件，才返回 `true`。

```js
[1, 2, 3].every(num => num > 0); // true
```

#### `sort`

接收比较函数，原地排序。

```js
[3, 1, 2].sort((a, b) => a - b); // [1, 2, 3]
```

### 10.5 高阶函数的应用场景

- 数组处理。
- 事件回调。
- 中间件。
- 权限包装。
- 日志埋点。
- 函数缓存。
- 防抖节流。
- 柯里化和函数组合。

### 10.6 示例：权限包装

```js
function withAuth(fn) {
  return function (...args) {
    if (!isLogin()) {
      throw new Error('请先登录');
    }

    return fn.apply(this, args);
  };
}

const submitWithAuth = withAuth(submit);
```

### 10.7 易错点

- `map` 应该返回新值，不适合只做副作用。
- `forEach` 没有返回新数组，也不能用 `break` 跳出。
- `sort` 会修改原数组。
- `reduce` 最好提供初始值，避免空数组报错和类型不稳定。

## 11. 回调函数

### 11.1 什么是回调函数

把一个函数作为参数传给另一个函数，在合适的时机被调用，这个函数就是回调函数。

```js
function request(callback) {
  const data = 'result';
  callback(data);
}

request((data) => {
  console.log(data);
});
```

### 11.2 同步回调

同步回调会在当前函数执行期间立即调用。

```js
[1, 2, 3].map(num => num * 2);
```

### 11.3 异步回调

异步回调会在未来某个时机执行。

```js
setTimeout(() => {
  console.log('later');
}, 1000);
```

常见异步回调：

- 定时器。
- DOM 事件。
- 网络请求。
- Node.js 文件读取。

### 11.4 回调函数的问题

#### 回调地狱

```js
login(function (user) {
  getProfile(user.id, function (profile) {
    getOrders(profile.id, function (orders) {
      console.log(orders);
    });
  });
});
```

问题：

- 嵌套层级深。
- 可读性差。
- 错误处理分散。
- 流程控制困难。

### 11.5 解决回调地狱

使用 Promise：

```js
login()
  .then(user => getProfile(user.id))
  .then(profile => getOrders(profile.id))
  .then(orders => {
    console.log(orders);
  })
  .catch(error => {
    console.error(error);
  });
```

使用 async/await：

```js
async function main() {
  try {
    const user = await login();
    const profile = await getProfile(user.id);
    const orders = await getOrders(profile.id);

    console.log(orders);
  } catch (error) {
    console.error(error);
  }
}
```

### 11.6 易错点

- 回调函数不一定是异步的，数组方法中的回调通常是同步的。
- `try/catch` 捕获不到未来异步回调里抛出的错误。
- 传回调时要注意 `this` 丢失。

```js
try {
  setTimeout(() => {
    throw new Error('error');
  }, 100);
} catch (error) {
  // 捕获不到
}
```

## 12. 递归函数

### 12.1 什么是递归

递归是函数直接或间接调用自身。

```js
function fn() {
  fn();
}
```

实际递归必须有终止条件，否则会无限调用，导致调用栈溢出。

### 12.2 递归的组成

递归通常包含两部分：

- 递归终止条件。
- 递归调用，问题规模不断缩小。

```js
function factorial(n) {
  if (n <= 1) {
    return 1;
  }

  return n * factorial(n - 1);
}

factorial(5); // 120
```

### 12.3 递归常见场景

#### 斐波那契

```js
function fib(n) {
  if (n <= 1) {
    return n;
  }

  return fib(n - 1) + fib(n - 2);
}
```

这个写法有大量重复计算，面试中最好能指出性能问题。

优化版本：

```js
function fib(n, memo = {}) {
  if (n <= 1) {
    return n;
  }

  if (memo[n] !== undefined) {
    return memo[n];
  }

  memo[n] = fib(n - 1, memo) + fib(n - 2, memo);
  return memo[n];
}
```

#### 树结构遍历

```js
function traverse(tree) {
  console.log(tree.name);

  if (!tree.children) {
    return;
  }

  for (const child of tree.children) {
    traverse(child);
  }
}
```

#### 深拷贝

```js
function deepClone(value, map = new WeakMap()) {
  if (value === null || typeof value !== 'object') {
    return value;
  }

  if (map.has(value)) {
    return map.get(value);
  }

  const result = Array.isArray(value) ? [] : {};
  map.set(value, result);

  Reflect.ownKeys(value).forEach((key) => {
    result[key] = deepClone(value[key], map);
  });

  return result;
}
```

### 12.4 递归的问题

- 调用栈可能溢出。
- 重复计算可能导致性能问题。
- 大数据量时可能不如迭代稳定。

```js
function count(n) {
  if (n === 0) {
    return;
  }

  count(n - 1);
}

count(100000); // 可能栈溢出
```

### 12.5 递归转迭代

```js
function factorial(n) {
  let result = 1;

  for (let i = 2; i <= n; i++) {
    result *= i;
  }

  return result;
}
```

### 12.6 易错点

- 递归必须有终止条件。
- 每次递归都应该让问题规模变小。
- 不要忽略返回值。
- 树和图结构递归时要注意循环引用。

## 13. 构造函数

### 13.1 什么是构造函数

构造函数是专门用来创建对象的函数，通常首字母大写，并通过 `new` 调用。

```js
function Person(name, age) {
  this.name = name;
  this.age = age;
}

const p = new Person('Alice', 18);
```

### 13.2 `new` 做了什么

执行 `new Fn()` 时，大致发生四步：

1. 创建一个空对象。
2. 把空对象的原型指向构造函数的 `prototype`。
3. 把构造函数内部的 `this` 绑定到这个新对象。
4. 执行构造函数，如果没有显式返回对象，则返回这个新对象。

```js
function Person(name) {
  this.name = name;
}

const p = new Person('Alice');
```

等价理解：

```js
const obj = {};
Object.setPrototypeOf(obj, Person.prototype);
Person.call(obj, 'Alice');
```

### 13.3 构造函数与普通函数的区别

构造函数本质上也是普通函数，区别主要在调用方式。

```js
function Person(name) {
  this.name = name;
}

Person('Alice'); // 普通调用
new Person('Alice'); // 构造调用
```

普通调用时：

- 非严格模式下 `this` 可能指向全局对象。
- 严格模式下 `this` 是 `undefined`。

构造调用时：

- `this` 指向新实例。
- 实例的原型指向 `Person.prototype`。

### 13.4 构造函数返回值规则

返回基本类型会被忽略：

```js
function Person() {
  this.name = 'Alice';
  return 1;
}

new Person().name; // "Alice"
```

返回对象会替代实例：

```js
function Person() {
  this.name = 'Alice';
  return { name: 'Bob' };
}

new Person().name; // "Bob"
```

### 13.5 手写 `new`

```js
function myNew(Constructor, ...args) {
  const obj = Object.create(Constructor.prototype);
  const result = Constructor.apply(obj, args);

  const isObject = result !== null && typeof result === 'object';
  const isFunction = typeof result === 'function';

  return isObject || isFunction ? result : obj;
}
```

使用：

```js
function Person(name) {
  this.name = name;
}

const p = myNew(Person, 'Alice');
console.log(p instanceof Person); // true
```

### 13.6 易错点

- 构造函数不加 `new`，`this` 可能出问题。
- 箭头函数不能作为构造函数。
- 构造函数中的方法如果写在 `this` 上，每个实例都会创建一份；写在原型上可以共享。

```js
function Person(name) {
  this.name = name;
}

Person.prototype.say = function () {
  console.log(this.name);
};
```

## 14. 函数与原型

### 14.1 函数的 `prototype`

每个可以作为构造函数的普通函数都有 `prototype` 属性。

```js
function Person() {}

console.log(Person.prototype);
```

`prototype` 指向一个对象，这个对象会成为实例的原型。

```js
function Person(name) {
  this.name = name;
}

Person.prototype.say = function () {
  console.log(this.name);
};

const p = new Person('Alice');
p.say(); // "Alice"
```

### 14.2 实例的 `__proto__`

实例内部有原型指针，通常通过 `__proto__` 访问。

```js
function Person() {}

const p = new Person();

p.__proto__ === Person.prototype; // true
```

更推荐的标准写法：

```js
Object.getPrototypeOf(p) === Person.prototype; // true
```

### 14.3 原型链

读取属性时，如果对象自身没有，就会沿着原型链向上查找。

```js
function Person(name) {
  this.name = name;
}

Person.prototype.say = function () {
  return this.name;
};

const p = new Person('Alice');

p.say(); // 自身没有 say，去 Person.prototype 找
```

查找路径：

```text
p -> Person.prototype -> Object.prototype -> null
```

### 14.4 构造函数、实例、原型之间的关系

```js
function Person() {}

const p = new Person();

p.__proto__ === Person.prototype; // true
Person.prototype.constructor === Person; // true
p.constructor === Person; // true，沿原型链找到的
```

三角关系：

```text
构造函数 Person --prototype--> 原型对象 Person.prototype
实例 p --__proto__--> 原型对象 Person.prototype
原型对象 Person.prototype --constructor--> 构造函数 Person
```

### 14.5 原型方法与实例方法的区别

实例方法：

```js
function Person(name) {
  this.name = name;
  this.say = function () {
    console.log(this.name);
  };
}
```

每个实例都会创建一份 `say`。

原型方法：

```js
function Person(name) {
  this.name = name;
}

Person.prototype.say = function () {
  console.log(this.name);
};
```

所有实例共享一份 `say`，更节省内存。

### 14.6 箭头函数和原型

箭头函数没有 `prototype`。

```js
const Fn = () => {};

console.log(Fn.prototype); // undefined
new Fn(); // TypeError
```

原型方法不应该写成箭头函数，因为箭头函数没有自己的 `this`。

```js
function Person(name) {
  this.name = name;
}

Person.prototype.say = () => {
  console.log(this.name); // this 不是实例
};
```

### 14.7 易错点

- 只有函数才有 `prototype`，普通对象没有。
- 实例没有 `prototype`，只有原型指针。
- `__proto__` 是历史访问器，推荐使用 `Object.getPrototypeOf`。
- 原型链查找只影响读取，不会影响普通赋值。

```js
const parent = { x: 1 };
const child = Object.create(parent);

child.x = 2;

console.log(child.x); // 2
console.log(parent.x); // 1
```

## 15. 异步函数

### 15.1 异步回调

早期异步主要通过回调实现。

```js
setTimeout(() => {
  console.log('later');
}, 1000);
```

问题：

- 多层嵌套可读性差。
- 错误处理复杂。
- 逻辑流程不直观。

### 15.2 Promise 中的函数

Promise 接收一个执行器函数，执行器会立即同步执行。

```js
const promise = new Promise((resolve, reject) => {
  resolve('success');
});
```

`then`、`catch`、`finally` 接收回调，这些回调会进入微任务队列。

```js
Promise.resolve()
  .then(() => {
    console.log('microtask');
  });

console.log('sync');

// sync
// microtask
```

### 15.3 `async` 函数

`async` 函数一定返回 Promise。

```js
async function fn() {
  return 1;
}

fn().then(value => {
  console.log(value); // 1
});
```

如果返回的不是 Promise，会被自动包装成 resolved Promise。

```js
async function fn() {
  return 1;
}

fn(); // Promise fulfilled with 1
```

如果抛出错误，会返回 rejected Promise。

```js
async function fn() {
  throw new Error('fail');
}

fn().catch(error => {
  console.log(error.message);
});
```

### 15.4 `await` 的执行机制

`await` 会等待 Promise 结果，并暂停当前 async 函数后续代码的执行。

```js
async function fn() {
  console.log(1);
  await Promise.resolve();
  console.log(2);
}

fn();
console.log(3);

// 1
// 3
// 2
```

理解：

- `await` 前面的代码同步执行。
- `await` 后面的代码会被放到微任务中继续执行。
- `await` 只能直接用在 `async` 函数中，或现代模块顶层。

### 15.5 异步函数的错误处理

使用 `try/catch`：

```js
async function loadData() {
  try {
    const data = await request();
    return data;
  } catch (error) {
    console.error(error);
    throw error;
  }
}
```

或者在调用处使用 `.catch`：

```js
loadData().catch(error => {
  console.error(error);
});
```

### 15.6 并发与串行

串行：

```js
const a = await requestA();
const b = await requestB();
```

`requestB` 要等 `requestA` 完成后才开始。

并发：

```js
const [a, b] = await Promise.all([
  requestA(),
  requestB()
]);
```

两个请求同时开始，总耗时更短。

### 15.7 async/await 面试题

```js
async function async1() {
  console.log('async1 start');
  await async2();
  console.log('async1 end');
}

async function async2() {
  console.log('async2');
}

console.log('script start');

setTimeout(() => {
  console.log('setTimeout');
}, 0);

async1();

new Promise((resolve) => {
  console.log('promise1');
  resolve();
}).then(() => {
  console.log('promise2');
});

console.log('script end');
```

输出：

```text
script start
async1 start
async2
promise1
script end
async1 end
promise2
setTimeout
```

核心：

- 同步代码先执行。
- Promise `then` 和 `await` 后续都是微任务。
- 微任务先于宏任务执行。

### 15.8 易错点

- `async` 函数返回的永远是 Promise。
- `await` 后面的代码不是立即同步继续执行。
- `Array.prototype.forEach` 不会等待异步回调。

错误示范：

```js
list.forEach(async (item) => {
  await request(item);
});
```

需要串行：

```js
for (const item of list) {
  await request(item);
}
```

需要并发：

```js
await Promise.all(list.map(item => request(item)));
```

## 16. 生成器函数

### 16.1 `function*`

生成器函数使用 `function*` 定义，调用后不会立即执行函数体，而是返回一个迭代器对象。

```js
function* gen() {
  yield 1;
  yield 2;
  return 3;
}

const iterator = gen();
```

### 16.2 `yield`

`yield` 用来暂停生成器函数，并向外返回一个值。

```js
function* gen() {
  yield 'a';
  yield 'b';
}

const iterator = gen();

iterator.next(); // { value: 'a', done: false }
iterator.next(); // { value: 'b', done: false }
iterator.next(); // { value: undefined, done: true }
```

### 16.3 `next`

每次调用 `next()`，生成器会从上次暂停的位置继续执行。

```js
function* gen() {
  const value = yield 1;
  console.log(value);
}

const iterator = gen();

iterator.next(); // 第一次 next 启动生成器，停在 yield 1
iterator.next('hello'); // "hello"，作为上一个 yield 的返回值
```

### 16.4 生成器函数的执行机制

```js
function* gen() {
  console.log(1);
  yield 'a';
  console.log(2);
  yield 'b';
  console.log(3);
}

const iterator = gen();

iterator.next(); // 打印 1，返回 { value: 'a', done: false }
iterator.next(); // 打印 2，返回 { value: 'b', done: false }
iterator.next(); // 打印 3，返回 { value: undefined, done: true }
```

生成器函数可以理解为“可暂停、可恢复”的函数。

### 16.5 使用场景

- 自定义迭代器。
- 惰性序列。
- 状态机。
- 早期异步流程控制。

自定义可迭代对象：

```js
const range = {
  start: 1,
  end: 3,
  *[Symbol.iterator]() {
    for (let i = this.start; i <= this.end; i++) {
      yield i;
    }
  }
};

[...range]; // [1, 2, 3]
```

### 16.6 易错点

- 调用生成器函数不会执行函数体，只会返回迭代器。
- 第一次 `next` 是启动生成器，传入的参数会被忽略。
- `return` 的值只会出现在最后一次 `next` 的 `value` 中，且 `done: true`。

## 17. 函数式编程基础

### 17.1 纯函数

纯函数满足两个条件：

- 相同输入永远得到相同输出。
- 不产生副作用。

```js
function add(a, b) {
  return a + b;
}
```

非纯函数：

```js
let count = 0;

function increment() {
  count++;
}
```

### 17.2 副作用

副作用是指函数除了返回值之外，还影响了外部世界。

常见副作用：

- 修改外部变量。
- 修改入参对象。
- DOM 操作。
- 网络请求。
- 读写本地存储。
- 打印日志。

```js
function updateUser(user) {
  user.name = 'Alice';
  return user;
}
```

### 17.3 不可变数据

不可变数据强调不直接修改原数据，而是返回新数据。

```js
const user = { name: 'Alice', age: 18 };

const nextUser = {
  ...user,
  age: 19
};
```

数组：

```js
const list = [1, 2, 3];

const nextList = [...list, 4];
```

好处：

- 状态变化更可追踪。
- 减少隐式副作用。
- 适合 React/Vue 状态更新。

### 17.4 柯里化

柯里化是把接收多个参数的函数，转换成一系列接收单个或部分参数的函数。

```js
function add(a, b, c) {
  return a + b + c;
}

function curryAdd(a) {
  return function (b) {
    return function (c) {
      return a + b + c;
    };
  };
}

curryAdd(1)(2)(3); // 6
```

通用 curry：

```js
function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) {
      return fn.apply(this, args);
    }

    return function (...nextArgs) {
      return curried.apply(this, [...args, ...nextArgs]);
    };
  };
}
```

使用：

```js
const add = (a, b, c) => a + b + c;
const curriedAdd = curry(add);

curriedAdd(1)(2)(3); // 6
curriedAdd(1, 2)(3); // 6
```

### 17.5 函数组合

函数组合是把多个函数组合成一个函数，前一个函数的输出作为后一个函数的输入。

```js
const double = x => x * 2;
const addOne = x => x + 1;

const compose = (f, g) => x => f(g(x));

const fn = compose(double, addOne);
fn(3); // 8，先 addOne 得 4，再 double 得 8
```

通用 compose：

```js
function compose(...fns) {
  return function (value) {
    return fns.reduceRight((result, fn) => fn(result), value);
  };
}
```

pipe 从左到右执行：

```js
function pipe(...fns) {
  return function (value) {
    return fns.reduce((result, fn) => fn(result), value);
  };
}
```

### 17.6 偏函数

偏函数是先固定一部分参数，返回一个接收剩余参数的新函数。

```js
function add(a, b, c) {
  return a + b + c;
}

const addOne = add.bind(null, 1);

addOne(2, 3); // 6
```

手写偏函数：

```js
function partial(fn, ...presetArgs) {
  return function (...laterArgs) {
    return fn.apply(this, [...presetArgs, ...laterArgs]);
  };
}
```

### 17.7 易错点

- 纯函数不是不能做任何事，而是不能产生外部可观察副作用。
- 函数式编程不是完全不用变量，而是减少状态变化和副作用。
- `compose` 通常从右到左执行，`pipe` 通常从左到右执行。
- 柯里化关注“分步传参”，偏函数关注“预设部分参数”。

## 18. 常见手写题

### 18.1 手写 `call`

面试简化版：

```js
Function.prototype.myCall = function (context, ...args) {
  context = context == null ? globalThis : Object(context);

  const fnKey = Symbol('fn');
  context[fnKey] = this;

  const result = context[fnKey](...args);

  delete context[fnKey];
  return result;
};
```

### 18.2 手写 `apply`

面试简化版：

```js
Function.prototype.myApply = function (context, args) {
  context = context == null ? globalThis : Object(context);

  const fnKey = Symbol('fn');
  context[fnKey] = this;

  const result = args == null
    ? context[fnKey]()
    : context[fnKey](...args);

  delete context[fnKey];
  return result;
};
```

### 18.3 手写 `bind`

```js
Function.prototype.myBind = function (context, ...boundArgs) {
  const originalFn = this;

  function boundFn(...callArgs) {
    const isNewCall = this instanceof boundFn;
    const finalThis = isNewCall ? this : context;

    return originalFn.apply(finalThis, [...boundArgs, ...callArgs]);
  }

  if (originalFn.prototype) {
    boundFn.prototype = Object.create(originalFn.prototype);
  }

  return boundFn;
};
```

### 18.4 手写 `new`

```js
function myNew(Constructor, ...args) {
  const obj = Object.create(Constructor.prototype);
  const result = Constructor.apply(obj, args);

  const isObject = result !== null && typeof result === 'object';
  const isFunction = typeof result === 'function';

  return isObject || isFunction ? result : obj;
}
```

### 18.5 手写防抖 debounce

防抖：事件频繁触发时，只在最后一次触发后等待一段时间再执行。

适用场景：

- 搜索框输入联想。
- 窗口大小变化。
- 表单校验。

```js
function debounce(fn, delay) {
  let timer = null;

  return function (...args) {
    clearTimeout(timer);

    timer = setTimeout(() => {
      fn.apply(this, args);
    }, delay);
  };
}
```

支持立即执行：

```js
function debounce(fn, delay, immediate = false) {
  let timer = null;

  return function (...args) {
    const shouldCallNow = immediate && !timer;

    clearTimeout(timer);

    timer = setTimeout(() => {
      timer = null;

      if (!immediate) {
        fn.apply(this, args);
      }
    }, delay);

    if (shouldCallNow) {
      fn.apply(this, args);
    }
  };
}
```

### 18.6 手写节流 throttle

节流：事件频繁触发时，固定时间间隔内最多执行一次。

适用场景：

- 滚动监听。
- 鼠标移动。
- 高频点击。

时间戳版本：

```js
function throttle(fn, delay) {
  let lastTime = 0;

  return function (...args) {
    const now = Date.now();

    if (now - lastTime >= delay) {
      lastTime = now;
      fn.apply(this, args);
    }
  };
}
```

定时器版本：

```js
function throttle(fn, delay) {
  let timer = null;

  return function (...args) {
    if (timer) {
      return;
    }

    timer = setTimeout(() => {
      timer = null;
      fn.apply(this, args);
    }, delay);
  };
}
```

### 18.7 手写柯里化 curry

```js
function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) {
      return fn.apply(this, args);
    }

    return function (...nextArgs) {
      return curried.apply(this, [...args, ...nextArgs]);
    };
  };
}
```

### 18.8 手写 compose

```js
function compose(...fns) {
  return function (initialValue) {
    return fns.reduceRight((value, fn) => fn(value), initialValue);
  };
}
```

使用：

```js
const addOne = x => x + 1;
const double = x => x * 2;

const fn = compose(double, addOne);

fn(3); // 8
```

### 18.9 手写 once

一个函数只执行一次。

```js
function once(fn) {
  let called = false;
  let result;

  return function (...args) {
    if (!called) {
      called = true;
      result = fn.apply(this, args);
    }

    return result;
  };
}
```

### 18.10 手写 memoize

缓存函数计算结果。

```js
function memoize(fn, resolver = (...args) => JSON.stringify(args)) {
  const cache = new Map();

  return function (...args) {
    const key = resolver(...args);

    if (cache.has(key)) {
      return cache.get(key);
    }

    const result = fn.apply(this, args);
    cache.set(key, result);
    return result;
  };
}
```

## 19. 常见易错点

### 19.1 函数提升

函数声明会整体提升：

```js
fn(); // 可以执行

function fn() {}
```

函数表达式不会整体提升：

```js
fn(); // TypeError 或 ReferenceError

var fn = function () {};
```

### 19.2 函数声明和函数表达式区别

| 对比 | 函数声明 | 函数表达式 |
|------|----------|------------|
| 提升 | 整体提升 | 变量按声明规则提升 |
| 名称 | 必须有函数名 | 可以匿名，也可以具名 |
| 使用场景 | 定义常规函数 | 作为值传递或赋值 |

### 19.3 `this` 丢失

```js
const obj = {
  name: 'Alice',
  say() {
    console.log(this.name);
  }
};

const fn = obj.say;
fn(); // this 丢失
```

修复：

```js
const fn = obj.say.bind(obj);
fn();
```

### 19.4 箭头函数误用

对象方法不要用箭头函数：

```js
const obj = {
  name: 'Alice',
  say: () => {
    console.log(this.name);
  }
};
```

原型方法不要用箭头函数：

```js
Person.prototype.say = () => {
  console.log(this.name);
};
```

### 19.5 闭包导致变量共享

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}

// 3 3 3
```

使用 `let` 可以创建每轮循环独立作用域。

### 19.6 `return` 换行问题

```js
function fn() {
  return
  {
    value: 1
  };
}

fn(); // undefined
```

### 19.7 参数默认值作用域

默认参数有自己的作用域，并且可以访问前面的参数。

```js
function fn(a, b = a) {
  return b;
}

fn(1); // 1
```

不能访问后面的参数：

```js
function fn(a = b, b = 1) {
  return a;
}

fn(); // ReferenceError
```

### 19.8 `forEach` 和 async

`forEach` 不会等待异步回调。

```js
async function run(list) {
  list.forEach(async (item) => {
    await request(item);
  });

  console.log('done'); // 不会等待 request 全部结束
}
```

串行用 `for...of`，并发用 `Promise.all`。

### 19.9 `bind` 和 `new`

`bind` 绑定的 `this` 会被 `new` 覆盖。

```js
function Person(name) {
  this.name = name;
}

const obj = {};
const BoundPerson = Person.bind(obj);

const p = new BoundPerson('Alice');

console.log(p.name); // "Alice"
console.log(obj.name); // undefined
```

### 19.10 函数 length

函数的 `length` 表示第一个有默认值参数之前的形参数量。

```js
function a(x, y) {}
function b(x, y = 1) {}
function c(x = 1, y) {}
function d(...args) {}

a.length; // 2
b.length; // 1
c.length; // 0
d.length; // 0
```

## 20. 面试题整理

### 20.1 基础概念题

#### JavaScript 中函数为什么是一等公民？

因为函数可以像普通值一样被使用：

- 可以赋值给变量。
- 可以作为参数传递。
- 可以作为返回值返回。
- 可以存储在对象或数组中。
- 可以动态创建和调用。

```js
const fn = function () {};

function wrapper(callback) {
  return callback;
}
```

#### 函数声明和函数表达式有什么区别？

函数声明会整体提升，可以在声明前调用；函数表达式本质是把函数值赋给变量，变量如何提升取决于 `var`、`let`、`const`。函数表达式更适合用在回调、条件赋值和模块内部封装场景。

#### 箭头函数和普通函数有什么区别？

核心区别：

- 箭头函数没有自己的 `this`。
- 箭头函数没有自己的 `arguments`。
- 箭头函数不能被 `new` 调用。
- 箭头函数没有 `prototype`。
- 箭头函数更适合短回调，不适合对象方法和构造函数。

#### 什么是闭包？

闭包是函数和它定义时词法作用域的组合。即使外层函数执行结束，内部函数仍然可以访问外层函数中的变量。常用于数据私有化、函数工厂、回调、防抖节流。

#### `this` 的绑定规则有哪些？

普通函数有四种绑定规则：

```text
new 绑定 > 显式绑定 > 隐式绑定 > 默认绑定
```

箭头函数没有自己的 `this`，不参与这套规则。

### 20.2 输出结果题

#### 题 1：函数提升

```js
foo();

var foo = function () {
  console.log(1);
};

function foo() {
  console.log(2);
}

foo();
```

输出：

```text
2
1
```

解释：

- 函数声明整体提升，`foo` 初始为打印 2 的函数。
- `var foo` 只提升声明，不覆盖函数。
- 执行到赋值语句后，`foo` 被改成打印 1 的函数。

#### 题 2：this 隐式丢失

```js
var name = 'global';

const obj = {
  name: 'obj',
  say() {
    console.log(this.name);
  }
};

const fn = obj.say;

obj.say();
fn();
```

浏览器非严格模式输出：

```text
obj
global
```

解释：

- `obj.say()` 是隐式绑定，`this` 是 `obj`。
- `fn()` 是独立调用，退回默认绑定。

#### 题 3：箭头函数 this

```js
const obj = {
  name: 'obj',
  say() {
    const fn = () => {
      console.log(this.name);
    };

    fn();
  }
};

obj.say();
```

输出：

```text
obj
```

解释：箭头函数没有自己的 `this`，捕获 `say` 执行时的 `this`。

#### 题 4：闭包循环

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
```

输出：

```text
3
3
3
```

解释：`var` 没有块级作用域，三个回调共享同一个 `i`。

#### 题 5：async/await

```js
async function fn() {
  console.log(1);
  await 2;
  console.log(3);
}

console.log(4);
fn();
console.log(5);
```

输出：

```text
4
1
5
3
```

解释：`await` 后面的代码进入微任务。

### 20.4 场景应用题

#### 场景 1：为什么 React 中状态更新要避免直接修改对象？

因为直接修改对象会产生副作用，引用地址不变时也不利于变更检测。更推荐用不可变更新返回新对象。

```js
setUser(prev => ({
  ...prev,
  age: prev.age + 1
}));
```

#### 场景 2：搜索框为什么用防抖？

输入过程中会频繁触发事件，如果每次都请求接口，会浪费资源并造成结果竞争。防抖可以等用户停止输入一段时间后再发送请求。

```js
const handleSearch = debounce((keyword) => {
  request(keyword);
}, 300);
```

#### 场景 3：滚动监听为什么用节流？

滚动事件触发频率很高，节流可以保证固定时间内最多执行一次，降低性能压力。

```js
window.addEventListener('scroll', throttle(() => {
  console.log(window.scrollY);
}, 200));
```

#### 场景 4：对象方法作为回调时 this 丢失怎么办？

可以使用 `bind`、箭头函数包裹，或者在调用时保持对象调用形式。

```js
button.addEventListener('click', obj.handleClick.bind(obj));

button.addEventListener('click', () => {
  obj.handleClick();
});
```
