## Part 1: 函数基础与声明方式

### 1.1 三种声明方式

| 方式 | 语法 | 提升行为 |
|------|------|----------|
| 函数声明 | `function fn() {}` | ✅ 整体提升，可先调用后声明 |
| 函数表达式 | `const fn = function() {}` | ❌ 仅变量名提升，值为 undefined |
| 箭头函数 | `const fn = () => {}` | ❌ 同函数表达式 |

> ⚠️ `var fn = function(){}` 时，调用在前会报 TypeError（undefined 不是函数），不是 ReferenceError。

### 1.2 IIFE（立即执行函数）

```js
(function() { /* 独立作用域 */ })();
```

- 作用：创建独立作用域，避免全局污染
- 用括号包裹的原因：让引擎把 function 解析为表达式而非声明

### 1.3 箭头函数 vs 普通函数

**口诀：箭头函数五无 — 无 this、无 arguments、无 new、无 prototype、无 super**

#### arguments 对象

- 普通函数内部**自动存在**的类数组对象，收集所有实参
- 不需要声明，引擎在每次函数调用时自动创建
- 类数组：有 length 和索引，但没有数组方法（需 `Array.from()` / `[...arguments]` 转换）
- 收集的是实际传入的参数，与声明的形参数量无关
- 现代替代：`...args` 剩余参数（直接是真数组）

#### [[Construct]] 内部方法

- 函数对象有两个内部调用通道：`[[Call]]`（普通调用）和 `[[Construct]]`（new 调用）
- `[[Construct]]` 不是每个函数各存一份逻辑，而是**指针/标记**，指向引擎的统一构造逻辑
- 箭头函数出厂时就没有 `[[Construct]]`，所以 new 时直接报错
- new 触发 `[[Construct]]` 做的事（普通函数）：
  1. 创建空对象 `{}`
  2. 空对象的 `__proto__` 指向构造函数的 prototype
  3. 绑定 this 为这个空对象
  4. 执行函数体
  5. 没有显式返回对象则返回 this

#### super 与 [[HomeObject]]

- super 不是基于 this 查找的，而是基于 **[[HomeObject]]**（方法定义所在的对象）
- 查找路径：`super.xxx` → `Object.getPrototypeOf([[HomeObject]]).xxx`
- 为什么不能用 this？
  - 原型链方法调用时，this 始终指向最初调用者
  - 多层继承时，如果从 this 出发找 super，中间层会死循环
- [[HomeObject]] 是固定的（定义时确定），保证每层 super 都能正确指向上一层
- 只有**方法简写语法**才有 [[HomeObject]]（普通函数属性 `bar: function(){}` 没有）

**this vs super 的区别：**
- `this.say()` → 从 this 开始沿原型链找第一个 say（一次查找，找到就停）
- `super.say()` → 从方法所在对象的 `__proto__` 开始找第一个 say（起点固定，不跟着 this 跑）

## Part 2: this 指向

### 核心原则

this 取决于「怎么调用」，而不是「在哪定义」（箭头函数例外）。

### 四大绑定规则（优先级从低到高）

#### 1. 默认绑定 — 独立调用

```js
fn(); // 非严格模式 → window | 严格模式 → undefined
```

#### 2. 隐式绑定 — 作为对象方法调用

```js
obj.say(); // this = obj（只看紧挨着函数的那个对象）
```

**⚠️ 隐式丢失（高频考点）：**
- 赋值给变量：`const fn = obj.say; fn();` → 退回默认绑定
- 回调传递：`setTimeout(obj.say, 1000)` → 退回默认绑定
- 多层对象：`a.b.say()` → this 是 b 不是 a

#### 3. 显式绑定 — call / apply / bind

```js
fn.call(obj, arg1, arg2);    // 立即调用，逐个传参
fn.apply(obj, [arg1, arg2]); // 立即调用，数组传参（Apply → Array）
const bound = fn.bind(obj);  // 返回永久绑定的新函数
```

- bind 返回的函数 this 无法再被隐式绑定覆盖

#### 4. new 绑定

```js
new Fn(); // this = 新创建的实例对象
```

### 优先级

```
new > 显式绑定(call/apply/bind) > 隐式绑定 > 默认绑定
```

- new 能覆盖 bind：`new (Fn.bind(obj))()` → this 是新实例，不是 obj

### 箭头函数（独立于四大规则之外）

- 没有自己的 this，继承**定义时**外层作用域的 this
- 一旦确定，永远无法修改（call/apply/bind 对它无效）

## Part 3: 闭包

### 定义

函数能够记住并访问它定义时所在的词法作用域，即使在该作用域外执行。

### 形成条件

1. 函数嵌套 — 内层函数引用了外层函数的变量
2. 内层函数被传到外部 — 通过 return、赋值、回调等方式

### 为什么变量不会被回收

正常函数执行完局部变量就销毁。但闭包引用着变量 → 引擎发现还有人用 → 不回收。

### 经典应用场景

| 场景 | 核心思路 |
|------|----------|
| 数据私有化（模块模式） | 外部无法直接访问内部变量，只能通过暴露的方法操作 |
| 柯里化 | 外层函数的参数被内层记住，实现参数复用 |
| 防抖/节流 | 闭包保存 timer 变量，跨多次调用共享状态 |

### 经典面试题：循环 + var + 闭包

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// 输出 3, 3, 3 — var 无块级作用域，所有回调共享同一个 i
```

**解决方案：**
1. `let` 替代 `var`（每轮循环独立的块级作用域）
2. IIFE 包裹（手动创建独立作用域捕获当前值）
3. setTimeout 第三个参数（直接传值给回调）

### 副作用：内存泄漏

闭包引用的变量不会被 GC 回收。解决：用完后 `fn = null` 解除引用。

## Part 4: 作用域与执行上下文

### 三个核心概念辨析

| 概念 | 是什么 | 何时确定 | 性质 |
|------|--------|----------|------|
| 词法作用域 | 规则 — 变量该去哪找 | 写代码时 | 静态 |
| 执行上下文 | 代码运行时的完整环境 | 函数调用时 | 动态 |
| 词法环境 | 执行上下文里存变量的组件 | 函数调用时 | 动态 |

**关系：** 词法作用域（规则）→ 决定词法环境的 outer 指针怎么连 → 词法环境是执行上下文的子组件

### 执行上下文的组成

```
执行上下文 = {
  词法环境(LexicalEnvironment): 存 let/const/class,
  变量环境(VariableEnvironment): 存 var/function,
  this 绑定
}
```

> 规范上分开描述，V8 实际实现中基本合并处理。分开是为了解释：var 能穿透块（VariableEnvironment 不随块更新），let 有块级作用域（LexicalEnvironment 每个块创建新的）。

### 词法环境的结构

```
词法环境 = {
  环境记录: { 变量名: 值, ... },
  outer: 指向外层词法环境  ← 这就是作用域链的实现
}
```

### 变量提升的底层原理

执行上下文的**创建阶段**（代码还没执行）就扫描声明：

| 声明方式 | 创建阶段做了什么 | 结果 |
|----------|----------------|------|
| `var` | 提升 + 初始化为 undefined | 访问得到 undefined |
| `let/const` | 提升但不初始化 | 访问报错（暂时性死区 TDZ）|
| `function` | 提升 + 初始化为函数体 | 可以正常调用 |

### 作用域链

变量查找路径：当前词法环境 → outer 指向的词法环境 → ... → 全局 → 没找到报错

在**定义时**就确定（词法作用域决定的），不是运行时。
